# Architecture and platform parity

## Scope, sources and honest status

**Current implementation: a bounded x86_64 bootstrap is in progress; no architecture is complete or physically/performance qualified.** Only the routed `ws-arch-x86-kernel` and `ws-arch-x86-mm` architecture prefixes are `in_progress`; unimplemented architecture work remains `not_started`. The baseline is Linux **6.18.57**, not the architecture list of an older kernel or the list of targets rustc happens to support. The [pinned architecture tree](https://github.com/gregkh/linux/tree/v6.18.57/arch), reconciled with [the complete inventory](../coverage.md), contains exactly **21 architecture directories**: `alpha`, `arc`, `arm`, `arm64`, `csky`, `hexagon`, `loongarch`, `m68k`, `microblaze`, `mips`, `nios2`, `openrisc`, `parisc`, `powerpc`, `riscv`, `s390`, `sh`, `sparc`, `um`, `x86`, `xtensa`. In particular, Nios II remains in this pinned tree; historical removals in another release do not change this program.

The profile rows cite each pinned `arch/<name>/Kconfig`; implementation must expand all sourced Kconfigs, CPU/board tables, defconfigs, UAPI and source paths rather than treating a row as an exhaustive hardware SKU list. Endian, MMU, word size and compat options are constrained combinations, not a Cartesian product to invent. Nonexistent Linux combinations need evidence-backed not-applicable dispositions; all existing baseline combinations remain in scope. A compiler or hardware gap is a blocker, never an exclusion.

The accepted design is a modular monolithic Rust kernel with fixed 6.18.57 feature scope and explicit reviewed security deltas. All in-baseline module functionality requires Rust replacement; arbitrary proprietary/out-of-tree module functionality is not silently added. Later feature-baseline changes require a separate decision.

The [Rust platform-support policy/table](https://doc.rust-lang.org/rustc/platform-support.html) is compiler research evidence, not proof of a kernel port. Tier 1 concerns ordinary target testing; tier 2 may only guarantee builds; tier 3 may lack automated builds/tests. A userspace Linux target is not a correct freestanding kernel target, and a supported target does not prove exception entry, memory ordering, privileged instructions, mitigations or all CPU generations. The actual `x86_64-unknown-none` build/ABI cell below is bound to its exact compiler; no other architecture build is inferred. Current online support documentation remains moving research. See [toolchain](../toolchain.md), [dependencies](../dependencies.md), [firmware](firmware.md), [drivers](drivers.md), [memory](memory.md), [process](process.md), [virtualization](virtualization.md), [performance](../performance.md) and [bare-metal](../bare-metal.md).

### Current routed bootstrap and evidence

- `ws-arch-x86-kernel` routes to [CPU entry/descriptors/traps](../../kernel/src/cpu.rs) and [ordered bootstrap](../../kernel/src/main.rs): x86_64 LE,4KiB pages, one executing BSP, native Limine base5/four-level request, external Limine12.9.3 and q35/TCG/OVMF. Actual GDT/TSS/IDT, guarded stacks and PIC/PIT exist. Non-error compiler entries remain; confirmed defective error-code lowering now has the [minimal local boundary and real before/after proof](../implementation.md#error-code-entry-defect-reproduction-and-repair). The earlier physical artifacts are withdrawn. These are not complete Linux entry/controller or SMP ports.
- `ws-arch-x86-mm` routes to [owned four-level tables](../../kernel/src/paging.rs), shared with the [memory owner](memory.md). Cell9 switches CR3 to owned mappings, checks W^X/four guards/no writable text alias, recovers exact CPU page faults with errors 0/3/17 and rolls back every one of the 20 actual table-allocation failure points.
- The maintained target uses the exact runtime rustc `1.101.0-nightly` commit `5c543b0b8c73c7b72bc8284ced4fb22ead15734d`/LLVM 23.1.1 and matching rebuilt Rust `core`/`compiler_builtins`; host MSRV 1.88 is a separate engineering metadata choice, not user approval or runtime qualification. Both final profiles have inspected scalar code, load permissions and no undefined symbols. The interrupt ABI is not qualified merely by a mutable nightly alias or kernel manifest 1.101.
- [Cell9 artifacts and eight bounded QEMU cases](../implementation.md#observed-execution-and-retained-failures) retain positive exit33 and seven intentional negative exits35, including unsupported PAT and actual unmasked-timer mutation. Breakpoint and IRQ checks preserve full 64-bit patterns in all 15 scalar GPRs. [Five host parser tests and strict owned Clippy](../implementation.md#final-owned-strict-lint-gate) are distinct evidence, not a physical or independent-review pass.

These are [engineering implementation choices](../decisions.md#initial-implementation-decisions-not-additional-user-approvals), not additional detailed user approvals. Linux boot protocol/PVH/native EFI/systemd-boot, BIOS/mixed mode, APIC/SMP/NUMA, context switches/userspace ABIs, broader page modes, mitigations and every other baseline architecture remain mandatory. The storage-free framebuffer diagnostic may proceed only through the user-operated isolated-media/recovery path in [packaging](../packaging.md); no physical operation is authorized or claimed, and M1 remains incomplete.


## Common ordered implementation contract

1. **M0 → M1: close the target feasibility gate before claiming a port.** Record target triple/specification, CPU features, endian/data layout, relocation/linking model, code model, panic strategy, stack alignment, red-zone status, register reservations, floating-point/vector restrictions, available atomics and compiler helper calls. Build `core`/required Rust compiler-builtins without target libc, libgcc, compiler-rt C objects, C startup or assembly source. External rustc/LLVM/linker binaries may themselves be non-Rust; kernel runtime may not. Audit link maps and disassembly. Extend a Rust compiler backend/target where absent, with compiler tests and reproducible provenance. A target JSON cannot create a missing code generator.
2. **M1: emulator and recoverable physical entry together.** Start x86_64 QEMU debugging, and user-operated current workstation boot when a genuine safe candidate exists. Preserve working Arch/CachyOS kernel, recovery entry and user control; [packaging](../packaging.md) distinguishes the isolated storage-free diagnostic trial from the later Linux-replacement Limine/systemd-boot package. Bring up serial/remote console or a proven bounded diagnostic alternative, boot-state validation, BSS/stack, memory map, reserved firmware regions, exception vectors and timer IRQ. Extend the same M1 contract to every architecture as it enters development; never postpone its physical bring-up until M7.
3. **M1–M2: memory, ordering and multiprocessor primitives.** Port page-table geometry/permissions, ASIDs, TLB invalidation/shootdown, cache alias rules, MMIO ordering, coherent/noncoherent DMA, atomic/lock implementation, per-CPU storage, secondary startup, IPIs, hotplug and topology/NUMA. noMMU is a separate MM/exec/ABI behavior, not MMU code with checks disabled. Unsupported hardware isolation must be stated, not falsely promised.
4. **M2–M3: process and ABI.** Port context switch, TLS, FP/vector/debug state, exception fixups, signal frames, ptrace/regsets, syscall number/argument/error/restart rules, vDSO, ELF notes/relocations/personality, seccomp/audit architecture IDs and user return. Cover compat ABIs independently. Reject invalid return PCs/flags/state before restoring privilege; preserve Linux-observable error behavior.
5. **M4–M6: platform integration.** Durable real I/O and real NICs, firmware/interrupt routing, suspend/wake, CPU frequency/idle, RAS, debugging and hardware virtualization where baseline supports them. Security mitigations and CPU errata are correctness requirements, not optional tuning. KVM backend scope includes x86, arm64, loongarch, mips, powerpc, riscv and s390; architecture support does not imply their virtualization paths are complete.
6. **M7–M8: every remaining CPU/board/ABI configuration cell, then non-inferiority release gate.** Obtain or name unavailable hardware, compiler/manual and firmware blockers. Prove Linux compatibility and at-least-baseline per-workload performance with unchanged security posture. One emulator machine, CPU model, endian mode or board cannot qualify an architecture.

The actual bounded [Rust bare-metal suite](../bare-metal-suite.md) runs via `cargo run -p baremetal -- run --output <new-directory> --label <label> --expect-release <exact-osrelease> --environment <reference|qemu|bare-metal>`. Select one environment label; the label is the operator's assertion, not physical detection. It is a non-destructive userspace functional smoke suite, not architecture/driver/performance qualification. The current bootstrap cannot run Linux userspace or this suite; its early QEMU self-tests are separate. A reference run validates the suite/current OS only. Broader tests below remain required.

## Inline assembly, unsafe boundaries and safe sharing

Rust `no_std` is the kernel implementation language. `repr(C)`/`extern` calling convention syntax is permitted for binary layouts and firmware ABI, not evidence of a C implementation. Prefer Rust code and supported intrinsics. Only operations that cannot be expressed correctly in Rust/intrinsics may use function-local `asm!` or `naked_asm!` in necessary naked Rust entry/return functions. This includes audited privilege transitions, barriers, TLB/cache/control-register and firmware/hypercall instructions when no suitable intrinsic exists. No `global_asm!`, standalone `.S`/`.s`, C shim, vendor startup object or imported binary runtime.

For each such operation record: upstream source/provenance; architectural manual/revision; why a Rust/intrinsic expression cannot suffice; input/output/clobbered registers including hidden special state; stack/alignment/red-zone rules; memory/flags effects; interrupt/preemption/privilege requirements; cache/TLB/compiler ordering; fault behavior and fixups; safe wrapper preconditions; reviewers; disassembly assertions and hardware tests. A compiler fence is not a CPU barrier; volatile accesses are not atomic synchronization; architectural atomics do not by themselves implement Linux RCU or LKMM. [Linux memory barriers](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/memory-barriers.txt) explicitly calls out Alpha dependent-read behavior and directs readers to [the Linux memory model](https://github.com/gregkh/linux/tree/v6.18.57/tools/memory-model). Rust memory-model assumptions must be reconciled with kernel shared-memory primitives, not copied as racy non-atomic Rust references.

Bundle common boot-information ownership, checked byte parsing, resources, IRQ domains, generic page-table policy, scheduler state and ABI dispatch. Keep small architecture implementations for encoding, cache/TLB, entry, firmware and barriers. Avoid runtime trait dispatch in proven hot paths when static specialization is sufficient; do not use a giant architecture enum in every memory access. Candidate register crates (x86_64, AArch64/Arm, RISC-V and platform PACs) require [dependency admission](../dependencies.md) and codegen audits; none replaces the table's Linux ABI/ordering/erratum work. For missing targets, the appropriate reuse is upstream compiler/backend work plus direct Linux source port, not hidden C compiler-builtins.

Safe simplifications include one internal boot-info format with lossless source records, shared topology/resource allocation and a small explicit entry-state machine. Unsafe simplifications include dropping endian/compat/noMMU variants, assuming every device DMA address equals a CPU physical address, sharing all page-table encodings, treating UP as no barriers, replacing PAL/SBI/PROM/PSW semantics with an x86-shaped interface, or emulating an unsupported security feature while advertising hardware isolation.

## Exhaustive architecture definition of done

Apply [global completion rules](../definition-of-done.md) **for every architecture row and every existing constrained configuration cell**. No row is done until all of these obligations have evidence:

- **Configuration register:** all pinned CPUs, boards/platforms, endian/width/ABI combinations, page sizes/MMU/noMMU, FP/vector extensions, topology/NUMA and security configuration branches enumerated from source with source-file ownership and applicability decisions. Every active file and source-enabled facility maps to an implementation and tests; documentation/build/test/metadata paths are not silently ignored.
- **Toolchain register:** complete Rust codegen/core/builtins/link closure, correct instruction minimums/layouts/atomics/relocations, CPU errata and disabled unwanted SIMD/red-zone; entry and inline-assembly review/disassembly checks. Unsupported rustc targets remain open toolchain blockers until implemented and tested, not marked complete because documentation exists.
- **Boot and processor state:** all advertised handoffs and firmware versions, legal/illegal entry state, early exceptions, timers/interrupt priorities/nesting/NMI-like events, context switches, FP/vector/TLS/debug state, faults/fixups, CPU startup/hotplug/suspend/reboot and failure recovery tested. M1 genuine physical boot remains prerequisite for each architecture's development lane.
- **Memory and I/O:** page faults/permissions, ASID rollover/shootdown, page sizes/address-width limits, cache alias/DMA coherency, IOMMU translation/faults, MMIO ordering and noMMU-specific exec/protection behavior; SMP/NUMA/weak-order litmus and stress under preemption. Emulator success cannot close electrical cache/DMA/timing behavior.
- **Linux binary behavior:** syscall numbers/argument/error/restart and compat rules; ELF/vDSO, signals/alternate stack, ptrace/core dumps, seccomp/audit, TLS, endian/unaligned access, invalid user return state and context leakage. Differential userspace regression and adversarial tests against pinned Linux for native and every compat ABI.
- **Security/errata:** every source-enabled mitigation and advertised isolation boundary carried across; privileged instructions, speculative execution, invalid return/flags, firmware trust and platform error paths independently reviewed/tested. No disabled mitigation to obtain a performance win.
- **Hardware proof:** per machine/CPU/firmware/device and configuration cell, genuine serial/console logs, external timing where required, real storage/network/DMA, power/hotplug/error injection, and recovery. `um` evidence is qualified hosted execution; s390/pSeries/sun4v/PS3 or guest evidence states mediation honestly. One physical workstation does not qualify other architectures or vendors. Additional hardware, manuals, legal firmware and instruments are explicit blockers today.
- **Performance and operations:** same configuration, compiler, firmware, security, power profile and topology as reference; repeated per-workload throughput/tails/CPU/memory/startup/power and confidence intervals under [performance rules](../performance.md). Include real server/container workloads and eventually desktop, audio/graphics, embedded/RT and legacy paths. No missing/inconclusive result counts as non-inferiority. Reproducible builds, safe selectable packages where applicable, recovery instructions and maintained regressions complete the gate.

Physical qualification starts at M1 for the first lane and continues at every phase, not after all code is written. The only presently available machine is the user's workstation; no remote consoles, other CPUs, boards or instrumented lab inventory have been observed. This documentation makes their absence visible and preserves their scope. It does not authorize host installation, reboot, firmware flashing, unsafe electrical tests or destructive disk testing. See [bare-metal execution](../bare-metal.md), [bounded suite limitations](../bare-metal-suite.md), and [packaging/recovery](../packaging.md).
