# Memory management: ownership, virtual memory, pressure, and devices

## Scope, ordering, and completion contract

**Current routes:** `ws-mm` owns early physical/block lifetime, `ws-mm-page-alloc-c` now owns selected indexed buddy splitting/coalescing, and `ws-arch-x86-mm` owns shared tables. The [publication checkpoint](../implementation.md#publication-checkpoint) is bounded; other child facilities remain `not_started`. Full Linux6.18.57 MM, all configurations and M1–M8 obligations remain open; latest authority is wrap-up/publication, not new feature expansion.

The approved architecture is modular monolithic Rust. The feature baseline stays fixed at 6.18.57 with explicit reviewed security deltas, not silent additions/removals. Only unavoidable local `asm!`/`naked_asm!` may implement target MMU/cache/barrier operations with reviewed register/memory/clobber/privilege contracts and disassembly evidence; no `global_asm!` or standalone assembly backend. All in-baseline module functionality remains required; arbitrary external/proprietary module functionality requires separate enumeration and approval.

Linux facts below come from pinned source/documentation. Interface/type names suggested here are proposals. Preserve direct-port provenance and notices under [licensing](../licensing.md). The pinned [MM documentation index](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/mm/index.rst) is a useful mechanism list; some upstream pages such as `oom.rst` and `page_reclaim.rst` are heading-only, so their existence is not algorithm evidence. Use actual pinned implementation and complete tests for closure. Structural [coverage](../coverage.md) cannot prove every allocation flag, VMA flag, ioctl, sysctl, architecture special PTE and fault outcome works.

Every mechanism below requires: fallible Rust-only implementation; exact externally visible error/partial-success/signal behavior; race and failure-injection evidence; integrated consumers; and performance/physical evidence under [verification](../verification.md), [definition of done](../definition-of-done.md), [performance](../performance.md) and [bare-metal rules](../bare-metal.md). Compare per-workload throughput, latency/tails, CPU, resident/peak memory, startup and energy to matched pinned Linux, with repetitions, confidence intervals, topology, firmware and mitigations recorded. At-least-baseline is a release requirement, not a present claim or permission to trade away security. Unknown results are blockers. Only the current workstation is available now; NUMA, weak-memory and other device/platform cells require additional hardware and remain unqualified.

### Current routed bootstrap and evidence

The first-userspace slice adds user mappings to the same owned tables (`map_user`: U/S on every level, NX unless executable; since the [kernel services foundation](../implementation.md#kernel-services-foundation) also after CR3 publication, with `invlpg` and atomic PTE updates) and the single user-copy mechanism [`usercopy`](../../kernel/src/usercopy.rs) (`access_ok` plus a software walk and direct-map alias, no user-address dereference); its TOCTOU argument holds only for one task on one CPU and must be replaced before `munmap`/`mprotect` or a second CPU. See [the slice record](../implementation.md#first-userspace-slice-kernel-side).

`ws-mm` routes to [early frame ownership](../../kernel/src/memory.rs): checked usable ranges and reservations, actual variable-sized bitmap metadata, non-copyable frame owners and raw initialization before typed references. The [four-level backend](../../kernel/src/paging.rs) is routed to `ws-arch-x86-mm` with the architecture owner; it consumes the same frame allocator rather than a second allocation convention. This BSP-only cell has a fallible-only kernel heap ([`heap.rs`](../../kernel/src/heap.rs), [`kalloc.rs`](../../kernel/src/kalloc.rs): vendored `buddy_system_allocator` over buddy frames, task context only, chunks never returned, no slab/GFP/reclaim) and init's user mappings (editable after CR3 publication, see [implementation](../implementation.md#kernel-services-foundation)), but no reclaim, demand paging, DMA, TLB shootdown or AP concurrency.

The immutable [cell9 evidence](../implementation.md#observed-execution-and-retained-failures) exercises real distinct frame contents, zero/reuse/alignment/accounting, complete exhaustion and restoration of the dynamically available 18,147 frames in that run, and rollback at every one of 20 actual page-table allocation points. Those observed counts are artifact/configuration-specific, not hard-coded Linux limits. Owned CR3 mappings enforce W^X, no writable text direct-map alias and four guards; actual CPU page faults with error codes 0/3/17 exercise nonpresent/readonly/NX behavior. The bad-map negative uses the production overflow validator, not a fabricated failure result.

[Five host production-parser tests and strict owned Clippy](../implementation.md#final-owned-strict-lint-gate) supplement, not replace, privileged QEMU observations. Full Linux memblock/buddy/SLAB, zones/NUMA, reclaim/swap/OOM/accounting, VMA/process mappings, SMP TLB lifetime, device memory and all other architecture/configuration obligations below remain open. No physical or performance qualification, independent soundness approval or M1 completion follows from this cell.

The subsequent [consumed native-word bitmap revision](../implementation.md#consumed-native-word-bitmap-revision) replaces this allocator's bytewise search, not its frame-ownership contract. Metadata rounds up to complete native words, is raw-initialized before references and reserves whole backing pages; cyclic selection scans two bounded ranges and filters physical alignment. Fresh integrated-005 actually exhausted/recovered116,653 frames, forced upper-then-lower two-hole reuse, checked zeroing,8KiB alignment and alignment-filtered failure, and passed all eight QEMU cases. Its own independent visual/source reviews and fresh both-profile artifact inspection are recorded separately; cell9/integrated-004 and diagnostic-001 remain immutable. This non-atomic exclusive view does not authorize IRQ/AP allocator access or discharge any SMP/TLB/NUMA obligation.

**Current cutover:** [buddy.rs](../../kernel/src/buddy.rs) is the single allocator algorithm for every order0–10; [memory.rs](../../kernel/src/memory.rs) preserves order0 callers while exposing whole-block ownership, byte alignment and explicit-order reclaim. Free-word hierarchy indexing avoids rescanning full RAM prefixes; alignment search skips ineligible head intervals. Metadata excludes its own backing pages, allocation zeroes the full extent before references, and no CPU/DMA/IRQ consumer shares this BSP allocator. The actual current consumer exercises every order, a retained isolated16-page pool, fragmented order1 failure, full64KiB zero/coalescence, exhaustion/recovery and table rollback. The old cyclic-hint/address-order test above is historical, not a second retained backend. Object allocation research stopped before code/workspaces/tests; no SLUB/heap, live SMP ownership, reclaim or performance qualification is claimed.


## 1. Physical memory model, boot reservation, and page allocation — M1–M2, M7

**Baseline.** [Allocation guidance](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/memory-allocation.rst) distinguishes physically contiguous pages, small allocations and virtually contiguous mappings, movable/high memory, DMA zones, reserves and reclaim context. The [physical-memory and allocator documentation](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/mm/physical_memory.rst) and [page allocator](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/mm/page_alloc.c) remain the source of zone/node/watermark behavior.

**Ordered port.** (1) Normalize firmware physical ranges with checked arithmetic, overlap resolution and preserved ownership of kernel/initrd/firmware/MMIO/crash/reserved regions; implement memblock-like early reservation and page metadata placement. (2) Model PFNs, nodes, zones and online memory separately from virtual pointers; account for holes, sparse memory, architecture page sizes, highmem and memory above direct-map reach. (3) Port buddy free areas, order splitting/coalescing, migration types, per-CPU page lists, watermarks/lowmem reserves, NUMA zonelists and fallback; transfer bootstrap pages exactly once. (4) Add high-order slow paths, watermark boosting, reclaim/compaction retries, reserve access and exact allocation-flag combinations. (5) Integrate CMA/contiguous isolation, memory hotplug, device-managed memory and RAS with their later mechanisms; DMA allocation goes through the driver's DMA/IOMMU contract, not just a low-address allocator.

**Reuse/shared machinery/simplification.** No general Rust heap crate is a replacement for Linux physical allocation. `core` bit operations, checked `Layout`, bounded bitmap helpers and audited page metadata abstractions are candidates; reject a generic buddy crate as a drop-in until zones, compound folios, flags, per-CPU caches, reclaim and NUMA semantics are proved. Share frame ownership with page tables, slabs, folios, DMA and hypervisors. A single-node debug allocator may precede zones/NUMA, but its configuration is explicitly partial. Do not use a final blanket no-heap policy or assert that one PFN always has an ordinary direct-mapped pointer.

**Security/invariants and improvement.** Every physical page has an auditable owner/state; free-list membership, metadata refs, mappings, pins and reserves agree. A reserved/MMIO/poisoned page cannot enter the buddy allocator. Never zero through an invalid direct-map alias. Overflow, duplicate free and order mismatches fail safely. Improve batched per-CPU refill/drain, locality and metadata cachelines only after accounting proof; measure allocation latency by order/context/node, fragmentation, stranded per-CPU pages, metadata bytes, reserve depletion and boot memory/time.

**Done gate.** Model tiny fragmented/holey maps and randomized allocate/free sequences with exact conservation; inject bootstrap metadata OOM and every slow-path failure. QEMU configurations include sparse/discontiguous RAM and emulated NUMA; physical tests require real high-memory/NUMA and supported memory hotplug before those cells close. Long-running mixed-order and DMA workloads compare failure behavior, allocator CPU and latency/fragmentation against baseline. No lost/reserved page or cross-owner allocation is allowed.

## 2. Fallible object allocation, slab, vmalloc, and allocation context — M1–M4

**Baseline.** [GFP/context and allocator rules](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/memory-allocation.rst) include NOWAIT/ATOMIC failure, chargeable user-triggered kernel memory, NOFS/NOIO recursion constraints and retry policies. [Linux Rust allocation APIs](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/rust/kernel/alloc.rs) expose fallibility/flags/node but depend on C bindings today; they are not an independently reusable Rust kernel runtime. [RT differences](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/real-time/differences.rst) constrain allocation and freeing inside raw/preemption-disabled regions.

**Ordered port.** (1) Specify task/reclaim-allowed, no-IO/no-FS scoped, nonblocking/reserve, earlyboot and forbidden NMI/raw allocation contexts; make contexts flow through APIs instead of a single global allocator silently choosing policy. (2) Implement page-backed slab caches/size classes with alignment, constructors, bulk operations, poisoning/redzones, hardened freelists and accounting; port baseline SLUB behavior/configuration rather than retaining removed historical allocators. (3) Provide fallible Rust-owned box/vector/string/container operations with caller-specified context, checked array sizes, stable pinned allocations and allocator provenance; failed growth preserves the original object. (4) Implement vmalloc/vmap address allocation, guard pages, page-array ownership, lazy unmap and TLB synchronization, per-CPU allocations, stacks and kvmalloc physical-to-virtual fallback. (5) Add shrinkers, deferred/context-safe free, usercopy cache bounds, RCU-delayed destruction and pressure/debug instrumentation.

**Reuse/shared machinery/simplification.** Adapt upstream Rust API/proof patterns only after replacing every backend with Rust. `alloc` collection internals are candidates only if their actual operation is fallible/context-correct; a `GlobalAlloc` path that panics/aborts on ordinary OOM is rejected. Reject `linked_list_allocator`, generic slab/buddy or `spin`-wrapped heaps as final solutions. Share physical allocator, memcg charging, lockdep, workqueue rescue, RCU and TLB batches. Initial size-class choices can be simple; final cache behavior, alignment, accounting and performance cannot disappear. RAII is suitable only when `Drop` is legal in the actual execution context; freeing may need an explicit deferred operation.

**Security/invariants and improvement.** Raw/NMI handlers do not invoke a sleeping allocator, including on drop. An object is freed to its originating allocator with original layout; retries do not double-charge. Zeroing/reinitialization and hardened usercopy prevent stale bytes reaching userspace. NOFS/NOIO scopes unwind correctly even on failure and nested calls. Optimize bulk allocation/free, hot cache paths and small object layout; report allocations per syscall/request, lock contention, internal/external fragmentation, virtual-space use, OOM behavior and tail latency.

**Done gate.** For each allocator API, test zero/maximum size, alignment, overflow, failure-before/after charge, realloc preservation, constructor failure, wrong-context detection and concurrent free/RCU retirement. Fault-inject real fork/exec/network/storage operations under strict memcg and global pressure. Physical SMP/RT tests demonstrate no allocator invocation from forbidden raw/NMI regions, no reclaim recursion deadlock, and at-least-baseline allocator/application results. A heap microbenchmark alone is insufficient.

## 3. Address spaces, page tables, TLBs, and user access — M1–M3, M7

**Baseline.** [Page tables](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/mm/page_tables.rst) describe five generic levels with architecture folding and huge leaves. [VMA locking](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/mm/process_addrs.rst) separates metadata stability from actual page-table/memory protection. mmap read, VMA read, rmap and PTE locks are not interchangeable.

**Ordered port.** (1) Introduce distinct physical/virtual/user addresses, PFNs, mapping owners and borrow-scoped table views; canonicality/alignment/overflow checks precede access. (2) Implement architecture page-table backends for permissions, hardware/software accessed/dirty state, cacheability, global/ASID/PCID tags, huge/special/migration/swap markers and architecture-defined ordering. Cover x86 four/five levels first without baking those levels/page sizes into every common path. (3) Build MM lifetime, VMA interval/range index, split/merge transactions, page-table locks and reverse mapping; distinguish mm users from references used by kernel threads/borrowed active MM. (4) Implement gather/unmap/flush/reclaim protocol with targeted SMP shootdowns, generation tracking, lazy TLB and CPU-entry races; free page-table pages only after hardware/software walkers cannot use them. (5) Supply fault-aware copy-to/from-user, clear/get/put/cmpxchg user operations, exception-table recovery, partial-copy counts, no-fault variants, access checks and architecture SMAP/PAN/SUM-like enable/disable. Integrate MMU notifiers/IOMMU invalidation before device memory consumers proceed.

**Reuse/shared machinery/simplification.** [`x86_64`](https://raw.githubusercontent.com/rust-osdev/x86_64/master/README.md) is a candidate for reviewed registers/instruction/table encodings; it does not supply Linux ASID lifetime, SMP shootdown or MM policy. Reject mapping helpers whose ownership assumes page tables never change or whose flush token can be dropped silently. Share table walkers, architecture barriers, CPU masks, RCU, hotplug, fault fixups and device notifiers. Full flushes may precede range batching, with measured overhead tracked; broadening user permissions or omitting an acknowledgement is not a safe simplification. Locked VMA lookup may precede RCU/per-VMA lookup but final scalability must satisfy gates.

**Security/invariants and improvement.** TLB permissions cannot outlive mprotect/unmap or page reuse. CPU migration/context entry cannot miss a generation change; offlined CPUs are drained before state destruction. Never create `&mut` references to memory concurrently mutable by userspace, hardware or another CPU. User pointers remain checked raw-access capabilities; validity is not stabilized by one range check. Preserve W^X/security policy, kernel isolation, protection keys, executable cache synchronization and speculation barriers. Improve range flush selection, ASID reuse and per-VMA faults only with proofs; measure shootdowns/IPIs, page-walk cost, fault latency, table bytes and cross-socket scaling.

**Done gate.** Differential MM selftests cover permissions, aliasing, concurrent mmap/mprotect/unmap/fork, signal-time usercopy and invalid/partially mapped buffers. Force CPU entry/exit and hotplug at shootdown boundaries; assert no old mapping accesses a reused frame. QEMU catches functional paths, while real PCID/ASID, noncoherent I-cache, weak ordering and architecture page-size combinations need actual hardware. Page-table checker, sanitizer-equivalent diagnostics and model tests supplement but cannot replace hardware results.

## 4. VMA syscalls, demand faults, anonymous memory, and COW — M3–M5

**Baseline.** [Process addresses](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/mm/process_addrs.rst) define VMAs, mmap/VMA/rmap lock ordering, shared and private mappings; [fault code](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/mm/memory.c) is authoritative for fault retries, COW and signal distinctions.

**Ordered port.** (1) Port mmap/munmap/brk/mremap/mprotect/pkey_mprotect/madvise/mincore/mlock families, placement/ASLR, MAP_FIXED versus MAP_FIXED_NOREPLACE, stack growth/guard gaps, resource limits and overcommit accounting. (2) Implement anonymous zero-page read faults, first-write zeroed allocation, file faults, private file-to-anonymous COW, fork write-protection and shared dirtying; distinguish ownership exclusivity from a convenient refcount value. (3) Add transactional VMA split/merge and page-table installation with revalidation after dropping locks for allocation/IO; preserve VM_FAULT retry, killable wait, SIGBUS/SIGSEGV and OOM handling paths. (4) Integrate truncate/hole punch, page migration, THP, device mappings, userfaultfd and `process_vm_readv/writev` access rules. (5) Cover shmem/memfd/seals/secret memory, remap_file_pages legacy behavior, advice variants, soft-dirty, pagemap visibility and architecture-specific VMA flags with their owners.

**Reuse/shared machinery/simplification.** No parser/allocator crate implements Linux VM semantics. Reuse audited range arithmetic and intrusive indexing; direct-port pinned algorithms behind Rust lifetime capabilities. Share rmap, page cache, folio state, allocation context and credential/security checks. Eagerly copying all fork pages is a debug stage, not acceptable final COW/performance behavior; replacing demand paging with upfront allocation changes OOM, overcommit, residency and latency. A conservative globally locked fault path may boot but is not a finished VMA design.

**Security/invariants and improvement.** Fork races pinned writable pages, writeback, COW and concurrent faults; a child must not acquire writable access to another process's private modifications. Re-check PTE identity after copying and free unused speculative pages without leaks/double charging. `mremap` rollback, partial unmap and split allocation failures must leave exact baseline-consistent mappings. Zero-fill BSS/tail pages before publication; preserve SIGBUS beyond EOF and faulting-usercopy fixup semantics. Optimize zero-page use, speculative allocation outside locks and COW exclusivity checks; measure minor/major fault tails, fork RSS/time, page copies and server startup.

**Done gate.** Run upstream MM/fork/exec tests and external LTP mapping cases with exact errno, signal code/address, visible contents and partial-success comparison. Include concurrent fork/write/unmap, private/shared file truncation, pin/write/COW races, grow-down stacks, `RLIMIT_AS/DATA/MEMLOCK`, overcommit modes, huge mappings and injected OOM at every VMA split/table/page allocation. Physical SMP stress plus Arch/CachyOS dynamic-loader/container workloads must meet correctness and at-least-baseline fault/startup/RSS targets; no libc fallback may mask an unsupported mapping ABI.

## 5. Folios, page cache, dirtying, writeback, and cache coherency — M3–M5

**Baseline.** Linux [page-cache design](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/mm/page_cache.rst) and [filemap implementation](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/mm/filemap.c) tie buffered IO, mmap, folio lifetime and invalidation together. The [MGLRU design](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/mm/multigen_lru.rst) distinguishes accesses through descriptors and page tables; ignoring one channel breaks cache policy.

**Ordered port.** (1) With VFS/storage owners define one address-space/indexed-folio cache, locked/uptodate/error/writeback/dirty state and stable references for lookups. (2) Implement read and fault population, asynchronous/readahead windows, partial-page zeroing and IO completion; concurrent miss must not publish conflicting folios. (3) Add dirty tracking, writeback tags, balance/throttling, per-backing-device and per-memcg accounting, write errors visible at the correct descriptor/sync boundary. (4) Implement truncate/invalidate/hole-punch/direct-IO/DAX exclusion and partial folio splitting with mapped PTE invalidation. (5) Integrate shrinkers, refault/shadow tracking, cache flush/I-cache alias operations and network filesystem invalidation.

**Reuse/shared machinery/simplification.** No generic LRU/cache crate supplies folio, writeback and mmap coherency. Reuse reviewed XArray-like structures and common folio reference/locking, not separate caches for read/write/mmap. Shared machinery spans shmem, swap cache, filesystems, reclaim, DMA pinning and memcg. Base-page folios may precede larger folios, but must preserve actual ABI and later satisfy throughput/footprint goals. Write-through-only IO or disabling readahead may aid diagnosis but is not baseline cache parity or durability semantics.

**Security/invariants and improvement.** Dirty data is not reclaimed before successful writeback or legal invalidation; IO completion cannot touch recycled folios. Truncate/direct IO and mapped faults serialize against each other with exact size/zeroing semantics. Do not confuse page-cache visibility with durable-media persistence. DMA/noncoherent caches follow architecture sync rules even on UP. Improve multi-page folio/readahead locality, batching and copy avoidance after proof; measure cache hit/refault rate, copy bytes, dirty throttling tails, CPU, RSS and IO amplification.

**Done gate.** Differential buffered/mmap/direct IO races, truncate/hole punch, fsync error propagation, short IO and writeback failure tests pass with filesystem owner's durability tests. Pressure and OOM during IO preserve data/accounting and forward progress. Physical real storage and noncoherent-DMA architecture tests close cache/IO cells; VM-backed storage alone does not qualify cache flush behavior. File and anonymous working sets compete under matched memory with per-workload throughput and tail latency at least baseline.

## 6. Reclaim, aging, shrinkers, compaction, and OOM — M2–M8

**Baseline.** [MGLRU](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/mm/multigen_lru.rst) has distinct aging/eviction, node/memcg `lruvec`s, descriptor/PTE access channels and refault feedback. Both selectable baseline reclaim configurations need closure. [OOM implementation](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/mm/oom_kill.c) distinguishes global/memcg/constrained OOM, already exiting tasks and IO-less reclaim; it does not simply kill the largest process on any allocation failure.

**Ordered port.** (1) Implement folio isolation/recheck/reinsert with unevictable/mlocked/pinned states; active/inactive LRU, refault/workingset detection, dirty/writeback handling and swap coordination. (2) Add kswapd/direct reclaim, reclaim recursion control, shrinker registration and memcg/node scanning, writeback congestion/throttling, slab shrink and emergency worker progress. (3) Port MGLRU generations/tiers, accessed-bit aging, feedback and controls alongside the baseline alternative; preserve observability and runtime enable/disable constraints. (4) Implement compaction/migration, high-order fragmentation handling and failure/retry policies. (5) Add OOM serialization, scope/constraint selection, score/adjustment/protection, victim marking, kill delivery and reaper safe ranges; integrate memcg group kill, fatal-signal exits, core dump and no-killable-task/panic policies.

**Reuse/shared machinery/simplification.** Reject a generic cache eviction crate and "panic on OOM" as kernel solutions. Port algorithms using common folios/rmap/charge ownership, waitqueues, worker rescue and task references. A basic LRU may precede MGLRU, but neither optional baseline configuration can be silently dropped. Internal heuristics may evolve only if observable controls, protections and release performance remain qualified; indiscriminately evicting anonymous memory or ignoring mlock/pins is not simplification. No blanket infinite retry for fallible allocations.

**Security/invariants and improvement.** Reclaim cannot recursively acquire its caller's filesystem/IO lock, destroy an in-use folio or evict protected/pinned pages. OOM honors unkillable init/score constraints and allocation-domain eligibility; memcg pressure must not kill unrelated host tasks. Reaper cannot unmap ranges with unsafe shared/pinned/notifier state. Pressure accounting does not overflow or leak under failed reclaim. Improve batched accessed-bit scans, refault feedback and node-local reclaim after measurement; track stall distributions, scan/steal ratios, kswapd CPU, refaults, IO amplification, killed-task scope and application tails.

**Done gate.** Stress anonymous/file/slab mixtures at global, NUMA-constrained and memcg limits, with swap both enabled/disabled, locked/pinned pages, dirty IO, failing disks, fork bombs, fatal-signal exits and OOM-immune tasks. Fault injection proves no reclaim dependency deadlock and exact baseline victim eligibility/observable OOM events; incidental victim choice under races may need invariant-based rather than PID-identical comparison. Real low-memory boots and physical workload sweeps meet pressure-throughput/tail/energy gates. A bounded successful smoke allocation is not OOM qualification.

## 7. Swap, swap cache, compression, and swapoff — M3–M7

**Baseline.** [Swap tables](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/mm/swap-table.rst) use per-cluster cache arrays with null/folio/shadow values, folio-before-cluster lock ordering and RCU-protected lookups. Implementing an older XArray-only design without checking the pinned source misses baseline changes.

**Ordered port.** (1) Define typed swap entries distinct from present/migration/poison PTEs; implement slot/refcount ownership, cluster allocation, backing-device/file validation, holes and priorities. (2) Add swapout unmap/dirty/writeback ordering, cache publication, concurrent swapin deduplication, readahead, error handling and charging. (3) Support huge/large folio split or native swap paths, shmem swap and forked entries. (4) Implement swapon/swapoff/unuse with concurrent fault/reclaim and low-memory rollback; slots cannot be reused until IO and references retire. (5) Port zswap/zsmalloc/zram interactions, compression algorithms through [extensions](extensions.md)/[drivers](drivers.md), writeback and compressed-pool policy, hibernation reservations and storage encryption dependencies.

**Reuse/shared machinery/simplification.** Compression crate candidates must be no_std, bounded, fallible, Rust-backed and exact-format compatible; acceptance belongs to [dependencies](../dependencies.md), not assumed from a familiar codec name. Reject user-space swap emulation and `std` IO. Share folios, cluster indexing, RCU, storage IO, memcg, workingset and reclaim. Plain disk swap can precede compression but is not final support closure; swap-disabled configurations are separate valid configurations, not a substitute for swap qualification. Preserve exact on-disk header/endian/device checks.

**Security/invariants and improvement.** Prevent stale-slot data exposure through zeroing/reference sequencing; compression errors or IO failures cannot become silently valid contents. Charge transfer between resident/swap/compressed states is atomic from the accounting perspective. Swapoff cannot free backing storage still referenced by a PTE or in-flight IO. Improve cluster locality, batched IO, decompression copies and shadow lookups; measure swapin tails, compressed bytes/CPU, IO amplification, memory efficiency and pressure throughput/energy.

**Done gate.** Differential swap enable/priority/fault/swapoff tests cover concurrent fork/exit/THP/shmem, IO errors, full swap, corrupted inputs, zswap pressure and OOM while unusing. Run only on dedicated lab swap media or isolated guest images; no default workstation swapon/raw writes. Real storage latency/power and pressure tests are required for disk swap qualification. No data mismatch, refcount leak, stale slot reuse or charge imbalance is permitted.

## 8. NUMA policy, migration, memory hotplug, and RAS — M2–M8

**Baseline.** [NUMA policy](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/admin-guide/mm/numa_memory_policy.rst) distinguishes task/VMA/shared policy and inheritance; cpuset restrictions take precedence. Task policy can survive exec while discarded VMA policy does not. Documentation has historical descriptions, so newer modes/flags must be derived from pinned UAPI/implementation, not omitted because an introductory page lists older modes.

**Ordered port.** (1) Integrate firmware topology, nodemasks/zonelists and allocation fallback, including memoryless CPUs, CPU-less nodes and restricted cpusets. (2) Port `set/get_mempolicy`, `mbind`, `move_pages`, `migrate_pages`, all baseline modes/flags including weighted/preferred-many behavior where present, and per-policy range/inheritance/error rules. (3) Implement migration entries, copying, rmap/PTE replacement, dirty/cache sync, pin/writeback exclusion, rollback and device-private/coherent/HMM notifier transitions. (4) Add automatic NUMA balancing sampling/placement and tiering/demotion with scheduler coordination. (5) Port online/offline pageblocks and memory sections, isolation/CMA, movable zones, metadata placement, hot-remove rollback and RAS poison/soft-offline/hard failure with SIGBUS and architecture notification.

**Reuse/shared machinery/simplification.** No topology or generic allocator crate supplies Linux policy or migration; reuse audited masks/range helpers and common folio move transactions. Share CPU hotplug, firmware, reclaim/compaction, huge-page splitting, MMU notifiers, memcg and devices. Single-node behavior is a bring-up subset with unqualified multi-node cells. Do not translate all policies to local allocation or claim emulated NUMA proves physical locality. Internal migration batching can simplify duplicated paths only after pinned special cases are preserved.

**Security/invariants and improvement.** Respect cpuset authority during concurrent rebind; task policy is not permission to escape a controller. Pinned/unmovable/device pages cannot be removed or copied while DMA proceeds. Partial migration returns exact counts/status/errors rather than an all-success flag. Poisoned pages never return to allocators; notify only correct affected mappings and preserve failure isolation. Measure local/remote faults, interconnect traffic, migration bytes/cost, balancing CPU, tail latency and energy; avoid moving hot pages merely to improve a synthetic locality ratio.

**Done gate.** NUMA selftests plus policy inheritance/cpuset changes, concurrent migration/fork/pinning, OOM-locality and poisoned-page cases compare to reference. QEMU injection develops state machines, but actual multi-socket memory latency, heterogeneous tiers, supported physical hotplug and RAS facilities need named lab hardware. On the currently available workstation unsupported facilities stay blocked. CPU/memory unplug failure leaves an internally coherent online system with no lost frames or invalid translations.

## 9. Transparent huge pages, hugetlb, KSM, and memory advice — M3–M8

**Baseline.** [THP design](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/mm/transhuge.rst) specifies graceful base-page fallback, PMD mapping split versus physical folio split, refcounts and pinned-folio split failure. Explicit hugetlb reservations are a different contract, not synonymous with opportunistic THP.

**Ordered port.** (1) Implement compound/large-folio metadata and safe head/tail ownership, PMD/PUD leaf handling and multi-size THP according to baseline. (2) Port allocation fallback/defrag policy, khugepaged/collapse, MADV_HUGEPAGE/NOHUGEPAGE/COLLAPSE, split/deferred split, partial unmap/COW and swap/reclaim interaction. (3) Implement explicit hugetlb pools, reservations/subpools/surplus, fault-time reservation consumption/rollback, hugetlbfs/shm/memfd and memcg/controller accounting. (4) Port KSM merge/unmerge, stable/unstable indexing, write-protection/COW, NUMA policy and tunables; preserve user opt-in/security controls. (5) Integrate DAMON/reclaim advice, idle/soft-dirty tracking and all baseline madvise variants through their exact UAPI rather than a reduced advice enum.

**Reuse/shared machinery/simplification.** Reuse folio/PTE/rmap primitives and checked arithmetic; no generic dedup or huge-page crate supplies Linux lifecycle/ABI. Shared machinery includes migration, pinning, swap, userfaultfd and memcg. Base pages alone are a valid partial configuration, not proof of transparent/explicit huge-page support. Do not use THP fallback to mask hugetlb reservation failures; explicit hugetlb may legitimately SIGBUS. KSM must not be always-on to win RAM benchmarks.

**Security/invariants and improvement.** A failed split leaves pins, refs and mappings correct; page-table split and physical split are distinguished. Reservation failure neither leaks pool pages nor double refunds. KSM never exposes cross-owner writes and retains baseline privilege/cross-domain controls. Huge folio accounting includes tails without overflow. Improve collapse selection, large-folio IO and deferred splitting while measuring TLB misses, memory waste, fragmentation, fault/compaction tails, CPU, application throughput and energy; wins in throughput cannot hide long blocking stalls.

**Done gate.** MM/hugetlb/KSM selftests exercise overcommit/reservation, pool exhaustion, fork/COW, partial unmap, poisoned pages, huge zero page, DMA pin split failure, migration, swap and concurrent collapse. Differential sysfs/proc controls and SIGBUS/errno match baseline. Real page-size/huge-leaf capabilities and fragmented long-lived physical workloads must meet per-cell correctness and performance gates. No huge-page cell is complete solely because a mapping flag was accepted.

## 10. memcg, memory protection, and pressure accounting — M3–M5, M8

**Baseline.** [cgroup v2 memory documentation](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/admin-guide/cgroup-v2.rst) covers hierarchy, ownership, limits/protection, swap, events, PSI and optional hugetlb accounting. Its `memory_recursiveprot`, `memory_localevents` and `memory_hugetlb_accounting` compatibility options deliberately preserve older behavior. Legacy cgroup v1 is retained under [process/cgroup core](process.md).

**Ordered port.** (1) Define charge handles covering anonymous/file/shmem/kernel/slab/socket/page-table/hugetlb and swap classes as applicable, with hierarchical ownership and rollback before publishing objects. (2) Implement per-CPU charge stocks, root/nonroot lifetime, migration/reparenting/offline handling, per-node lruvecs and statistics. (3) Port `memory.min/low/high/max`, reclaim/throttle behavior, events and local/hierarchical accounting; add swap/zswap controls and exact failure policies. (4) Integrate memcg OOM, group kill, victim/exiting task handling, reclaim protection and PSI stall accounting. (5) Add v1 limits/soft limits/memsw and migration semantics where selectable, controller compatibility options and interactions with cpuset/NUMA/hugetlb.

**Reuse/shared machinery/simplification.** No general hierarchical-counter crate handles Linux charge ownership; audited counters may be reused behind domain transactions. Share cgroup lifetime with process owner, resource accounting with IO/socket owners and folio state with reclaim. Initially unbatched counters simplify proof but are tracked for scaling; charging only resident user pages is not acceptable final accounting. Unified internal counters are allowed only if every v1/v2 interface and ownership distinction still maps correctly.

**Security/invariants and improvement.** Untrusted allocations are charged before they escape to consumers; OOM rollback and speculative pages cannot bypass limits. Moving a task does not blindly transfer all historical page ownership; shared file/cache ownership follows baseline rules. Dying cgroups remain live while charges/workers refer to them. Prevent protection double counting, per-CPU stock leakage and counter underflow under concurrent reclaim/exit. Measure charge fast-path CPU, memory.high latency, isolated-container throughput/tails, controller footprint and limit overshoot behavior against baseline; smaller counters cannot justify lost accounting.

**Done gate.** Upstream cgroup tests and container traces cover nested protections, threaded/domain restrictions, limits lower than current use, concurrent migration/exit/OOM/reclaim, page-cache sharing, charge failures and v1/v2 mount options. Verify event/PSI behavior and no host-domain kill from contained pressure. Physical parallel-container workloads under realistic memory pressure meet at-least-baseline metrics, not just a counter unit test. Missing socket/IO/hugetlb charging blocks memcg completion even if anonymous limits work.

## 11. Pinning, userfaultfd, DAX, HMM, and special mappings — M3–M8

### Pinning and device-visible memory

**Baseline.** [pin_user_pages](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/pin_user_pages.rst) distinguishes ordinary references, short DMA pins and more restrictive long-term pins. Large folios use separate pin counts; zero-page pins are special; long-term DAX pins are prohibited by that contract.

**Ordered port.** (1) Define distinct page reference/pin/DMA-mapping handles and separate short/long-term lifetimes. (2) Implement slow GUP first with faults, permissions and COW, then fast GUP with page-table/RCU revalidation and architecture atomicity rules. (3) Handle partial success/unpin rollback, dirty-on-unpin, huge/zero pages and long-term migration/isolation constraints. (4) Integrate MMU notifiers, IOMMU/SVA/HMM replayable faults, RDMA and direct IO: stop/invalidate device use before unpinning or freeing mappings.

**Reuse/bundling/simplification.** No generic `Pin<T>`/`Arc<T>` proves a physical DMA pin; Rust object pinning is a different concept. Share folio/PTE/rmap/DMA ownership; reject a crate claiming zero-copy solely because it holds a virtual reference. Slow GUP may precede fast GUP but final IO performance and all eligibility rules remain required. **Invariants/improvement:** prevent writable-pin COW bypass, overflow, dirty-writeback loss and freeing before DMA completion; eliminate repeated pin/map work only when invalidation remains correct. **Done:** upstream GUP tests, fork/COW/writeback/truncate/THP races and malicious partial mappings pass, pin-acquired/released counters balance after teardown, and actual IOMMU/NIC/storage DMA tests demonstrate no stale access with measured pin/IO tails and CPU at least baseline.

### Userfaultfd and userspace-managed faults

**Baseline.** [userfaultfd](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/admin-guide/mm/userfaultfd.rst) negotiates features and per-range ioctls, distinguishes missing/minor/WP faults and memory types, exposes fork/remap/remove events and `/dev/userfaultfd`; access to kernel faults has distinct security controls.

**Ordered port.** (1) Implement fd lifecycle, UFFDIO_API negotiation, unsupported feature rejection and syscall/device permission rules. (2) Add range registration/unregistration, queued event publication, poll/read/wake, synchronous fault blocking and close/exit cancellation. (3) Implement COPY/ZEROPAGE/CONTINUE/WRITEPROTECT/MOVE/POISON and all pinned-baseline ioctls with partial progress, atomic page publication and DONTWAKE rules. (4) Cover anonymous/shmem/hugetlb differences, WP-unpopulated/async tracking, fork/remap/remove and concurrent noncooperative managers.

**Reuse/bundling/simplification.** No generic pager crate supplies the ABI; use common fd/poll, VM fault, folio and waitqueue transactions. Do not expose feature bits before the real implementation passes its type-specific gates. Missing-only anonymous paging is an explicitly partial milestone, not final userfaultfd. **Invariants/improvement:** no half-populated page, lost event, unprivileged kernel-fault permission bypass or deadlock with a manager requiring the same held MM lock. Optimize event batches/PTE tracking without replacing faults by VMA proliferation. **Done:** upstream userfaultfd tests exercise every negotiated bit/type/ioctl, duplicate manager, fork, signal, close, OOM, stale ranges and POISON SIGBUS; physical live-migration/pager workloads measure stalls/CPU/RSS against baseline. Unsupported feature cells remain not_started, never fake success.

### DAX, PFN/device mappings, and cache persistence

**Baseline.** [DAX](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/dax.rst) bypasses page-cache copies, distinguishes persistent FS_XFLAG_DAX from active S_DAX, and requires filesystem-specific mapping/invalidation behavior. Cache coherency and power-fail persistence are separate properties.

**Ordered port.** (1) With filesystem/device owners define PFN/devmap/device-private and normal-RAM mapping kinds, ownership/ref lifetimes and allowed GUP/migration operations. (2) Implement DAX faults, direct access, exceptional cache entries, filesystem block lifetime and truncate/hole-punch synchronization. (3) Add flush/persistence ordering, MAP_SYNC/error semantics where supported, poison propagation, device remove/revoke and pin restrictions. (4) Close raw PFN remap, IO mappings, HMM/device-private migration and architecture cache-mode alias rules.

**Reuse/bundling/simplification.** Reuse kernel mapping/flush/DMA/notifier layers, not a userspace persistent-memory library or ordinary slice over MMIO. A page-cache-backed imitation is not DAX and cannot advertise S_DAX. One common special-mapping enum can remove duplicated unsafe paths without erasing distinct lifecycle rules. **Invariants/improvement:** no stale mapping after block reuse/device removal, illegal cache aliases or fictitious durability after a CPU-only fence. Minimize copies and mapping churn while measuring fault cost, cache traffic, throughput/tails and power. **Done:** differential DAX flags/mount/ioctl/mmap, truncate/direct IO, poison and long-pin rejection tests pass; actual persistent/device memory and filesystem owner's safe power-loss protocol are required. Emulation supports development only; unavailable physical media is a named qualification blocker.

## Runnable smoke versus qualification

The repository's [bounded Rust smoke suite](../bare-metal-suite.md) is executable on compatible reference Linux now and, after a candidate implements and boots the required Linux userspace environment, on that candidate; the present bootstrap cannot run it:

```text
cargo run -p baremetal -- run --output <new-directory> --label <label> --expect-release <exact-osrelease> --environment <reference|qemu|bare-metal>
```

Use the exact running release and a new output directory. The environment label is operator assertion, not hardware proof. Bounded memory/thread tests and proc/sysfs visibility are useful smoke evidence but do not exercise kernel OOM, reclaim, pinning, hotplug, adversarial MM races or performance parity. No reference smoke run is candidate-kernel evidence. This plan does not run tests, mount filesystems, enable swap, alter settings, perform raw IO or reboot the workstation. Additional privileged/destructive qualification requires the isolated lab and explicit operator procedures in [bare-metal qualification](../bare-metal.md); installing/selecting a future Arch package follows [packaging](../packaging.md).

For full qualification, use pinned external `tools/testing/selftests/mm` cases and the relevant cgroup/userfaultfd/GUP/hugetlb tests with recorded test names, arguments, configuration, required privileges and architecture. "Run all MM tests" is not an automatic safe command on a daily workstation: some tests alter global state or require dedicated devices. A Rust orchestrator must separate bounded smoke, privileged nondestructive, pressure/disruption and sacrificial-device tiers; unavailable/skip is explicit and cannot satisfy a required cell. Every per-mechanism gate above adds normal, boundary, resource-failure, concurrency, security, recovery and performance evidence to [definition of done](../definition-of-done.md), including configuration/legacy behavior discovered during source porting. None is waived because no ready-made crate or convenient hardware exists.
