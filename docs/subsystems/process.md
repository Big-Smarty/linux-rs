# Tasks, executable ABI, credentials, and containment

## Status and integration contract

**Implementation status: not_started.** This is a proposed Rust-only direct port of **Linux 6.18.57** task/process behavior, not an implemented syscall table, executable loader, init process or compatibility claim. The [roadmap](../roadmap.md) places initial task support after M1 architecture/boot and M2 MM/SMP/scheduler; M3 supplies process/ELF/syscall/IPC, M5 qualifies server/container workloads and M6–M8 close the complete ABI/architecture/security surface. First userspace is **Arch/CachyOS userspace** on the baseline Linux behavior, not downstream CachyOS kernel patches. The target performance profile is balanced server operation, without eliminating desktop, RT, embedded, legacy or other-architecture behavior.

The approved design is a modular monolithic Rust kernel with a fixed 6.18.57 feature baseline plus explicitly reviewed security deltas. Later feature-baseline changes require a separate decision. Architecture entry/return may use unavoidable local `asm!`/`naked_asm!` only with reviewed register/memory/clobber/privilege contracts and disassembly checks; no `global_asm!` or standalone assembly implementation. In-baseline module functionality must be replaced in Rust; arbitrary proprietary/out-of-tree modules are separate, unapproved additional scope.

[Core](core.md) owns scheduling, waitqueues, locks, RCU, timers and CPU context; [memory](memory.md) owns mappings/usercopy; [IPC](ipc.md) owns pipes, AF_UNIX/SCM_RIGHTS, SysV/POSIX IPC, eventfd/signalfd/timerfd; [filesystems](filesystems.md) own executable files and procfs/nsfs/pidfs integration; [security](security.md) owns capabilities/LSM/seccomp enforcement and policy; [observability](observability.md) owns tracing/perf/audit consumers. This document owns lifecycle and ABI coordination across those boundaries, including credential/cgroup/namespace transitions. Neither a C shim nor loading existing C modules is allowed.

Every numbered mechanism is independently incomplete until all ordered steps, UAPI/configuration variants, failure/race/security cases, consumer integrations, differential tests and physical/performance gates pass under [definition of done](../definition-of-done.md), [verification](../verification.md), [performance](../performance.md) and [bare-metal qualification](../bare-metal.md). Cite pinned source for observed behavior, record proposed design choices as proposals, and preserve [source provenance](../licensing.md). Internal Rust layouts need not match internal C structs; externally visible register state, UAPI bytes, errno, signals, ordering and security checks do. Future test invocations here have **not been run** by this planning task.

**First-userspace slice (A18).** Sections 3–5 now have a bounded kernel-side start: `/init` discovery, a `load_elf_binary`-ordered load plan for static `ET_EXEC`, the `create_elf_tables` stack and auxv, a four-syscall dispatch (`write`, `getpid`, `exit`, `exit_group`) and the init-death/segfault/trap text, as host-tested pure logic in `kernel/src/exec/` and `kernel/src/syscall/mod.rs`. There is no task object, scheduler, `execve` syscall, signal delivery or ring-3 entry yet; see [the slice record](../implementation.md#first-userspace-slice-kernel-side) for design answers, shortcuts and evidence. The `Implementation status` above stays `not_started` for the complete mechanisms.

**Task-model slice (lane `task-model`, [record](../implementation.md#task-model-and-process-syscalls)).** A pure, host-tested [`Tasklist`](../../kernel/src/task/tasklist.rs) (pids, parentage, process groups and sessions, exit/reparent/`SIGCHLD`, `wait4`/`waitid`, the `kill` family, orphaned groups, credential snapshots) now backs `getppid`/`getpgid`/`getpgrp`/`getsid`/`setsid`/`setpgid`, `wait4`/`waitid` (their argument and `ECHILD` paths on the machine) and the `execve`/`execveat` commit path; the status of section 1 and 2 above stays `not_started` for `fork`/`clone`, stacks and the scheduler, which are other lanes.

**Pipes, `poll` and job control ([record](../implementation.md#pipes-poll-and-job-control)).** Reads and writes of a pipe sleep and wake across tasks and keep their partial progress, `poll` reports the readiness of pipes, the console and files, and the stop signals stop the process group: group stop, `SIGCONT`, once-only `wait` reports, `SIGCHLD` with `CLD_STOPPED`/`CLD_CONTINUED`, the orphaned-group rules and `kill`/`setpgid`/`setsid` with real children. It adds no lock-order edge (`PROCESS -> RQ` wake-ups, as `child_event`); the rows T8 and T14 changed and T16-T18 are new.

### Lock order and non-parity table for the task lane

Acquire left to right, never the reverse (the shared DAG; `kernel/src/services.rs` repeats it next to the locks that exist):

```text
TASKLIST -> VFS -> heap -> FRAMES
TABLES -> FRAMES                         (the kernel template tree only; a task's own page tables are not a lock)
TASKLIST -> TIMERQ -> TIMER_HW
any lock -> RQ
PROCESS -> VFORK_DONE                       (a leaf: the address space a vfork child gives back to its parent)
PROCESS -> VFORK_FORWARD                    (a leaf: the lender a dead vfork borrower owes the space to; never held with VFORK_DONE)
```

* `TASKLIST` collapses `tasklist_lock`, `siglock` and `pidmap_lock` (a named coarsening; Linux orders them in that sequence and one CPU makes them one section). It must be IRQ-saving, because the interval-timer expiry will take it from hardirq.
* `TABLES` (`kernel/src/services.rs`) is, since the fork lane, only the kernel-only page tables: the template every task's tree copies its kernel half from and the tree CR3 holds while no task's may be. It is taken alone (a copy of its top level, a group load) before `FRAMES`. The page tables a task edits, `execve`'s commit and user-memory faults included, are its own (`userspace::TaskLocal`), reached by that task only and under no lock; a fork copies the parent's with `FRAMES` held and no heap allocation.
* `VFS -> TASKLIST` is forbidden: `SIGPIPE` is sent after the VFS borrow ends. `TIMERQ -> TASKLIST` is forbidden: expiry drains due entries under `TIMERQ`, releases it, and only then wakes (`RQ`) or signals (`TASKLIST`). `RQ` is a leaf that every other lock may take; its holders call nothing.
* No guard may be alive across `schedule()`. The task model never sleeps: blocking is the caller's re-check loop (`wait_event_interruptible`), and the model reaches sleepers only through `task::exit::Waker`. **True since the fork lane**: a system call takes `PROCESS` on first use (`userspace::Shared`) and `Task::wait` drops it before `ktask::sleep_current`.
* The `/proc` lane adds no class of its own: the mount table, the superblocks and the procfs mirror live inside `VFS`, the per-task views are published by their owner while it holds `PROCESS`, and a `/proc` read takes two leaves under `PROCESS` (`LOAD`, the load-average samples, and the `cpu_facts` cache of the CPUID snapshot), each of which calls out of nothing: `PROCESS` -> `LOAD`, `PROCESS` -> `cpu_facts`.
* Today the task list lives inside `PROCESS` (no `TASKLIST` lock exists yet); `PROCESS` stands for `TASKLIST` plus `VFS` until the VFS is promoted, which only splits the lock.

**Scheduler core (lane `sched`).** A single-CPU scheduler core now exists below these sections: per-task kernel stacks with guard pages, the register context switch, a FIFO run queue with generational task handles, wait keys, a timer queue and the idle loop (`kernel/src/sched/`, `kernel/src/ktask/`); `/init` runs as a scheduled task. It is the seam sections 1, 2 and 6 plug into: a task is a `SchedId`, blocking is `Task::wait(key, deadline)` and waking is `wake_up_key` / `signal_wake_up`. **Lock-order edges it adds to the shared DAG** (acquire left to right): `RQ` is a leaf taken under any lock and from hardirq (so `TASKLIST`/`VFS`/`PROCESS` -> `RQ` are legal, and nothing is taken from under `RQ`); `TIMERQ` -> `TIMER_HW`; `RQ` and `TIMERQ` are never held together (expiry drains under `TIMERQ`, then wakes under `RQ`); no guard may be alive across `schedule()` once a second user task exists (today the single user task sleeps with `PROCESS`/`TABLES` held, documented in `services.rs`). See [the record](../implementation.md#scheduler-core) for the seam, shortcuts and evidence. The `Implementation status` above stays `not_started` for the complete mechanisms.

## 1. Task identity, lifecycle foundations, clone, and fork — M2–M3

**Baseline.** [`copy_process`](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/kernel/fork.c) validates clone relationships, establishes resources and cgroup/scheduler placement before publication, and has extensive rollback. CLONE_THREAD requires shared signal handlers; CLONE_SIGHAND requires shared VM; namespace and shared-FS combinations have restrictions. [`pid.c`](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/kernel/pid.c) distinguishes stable PID objects from recyclable numeric IDs and supports pidfd flags beyond a process-only handle.

**Ordered implementation.** (1) Define pinned task/kernel-stack ownership and separate task/thread-group, PID object, PID namespace, mm, files/fs, sighand/shared signal, credentials and namespace proxy. RCU lookup yields guard-bounded access; long-term references must be explicitly promoted. Include idle/kernel/user-worker tasks and scheduler context state. (2) Implement namespace-aware PID/TID/TGID, process groups/sessions and proc/pidfs identities, with allocation failure and delayed release; never use a recyclable integer as an owned task handle. (3) Port fork/vfork/clone/clone3 architecture argument conventions, flag relationships, unknown bits/structure extension checks, stack/TLS validation, set_tid arrays, exit signal and clone-into-cgroup behavior. (4) Prepare all fallible duplicated/shared resources with transaction-style rollback, apply RLIMIT_NPROC/pids/ucount/cgroup/scheduler checks and resolve pending-signal/fork publication races. (5) Publish parent-child/group/PID relationships once coherent, write parent/child TID and pidfd results at the exact baseline stages, then wake the child. Implement vfork parent blocking and release-on-exec/exit, robust-list/rseq inheritance/reset and child-cleartid futex wake.

**Reuse/shared machinery/simplification.** Direct-port pinned validation/lifetime algorithms behind Rust types; no task/executor/thread-pool crate is a Linux process runtime. Candidate intrusive/ID structures must have fallible allocation, pinned membership and RCU-safe reuse; ordinary `Arc<Task>` alone is insufficient for task exit and stack reclamation. Share MM COW, fd tables, credentials, waitqueues, PID registry and cgroup references. A kernel-thread-only or fork-only stage may precede clone3, but cannot claim userspace/thread compatibility. Use one common prepared-child transaction with ABI-specific decoders, not duplicated fork logic or an ignored-flags shortcut.

**Security/invariants and improvements.** Child visibility occurs only after accounting and security decisions; failed clone cannot leak fd/PID/charge or expose partially initialized task state. Preserve exact user-write fault behavior, not a fictitious guarantee that all user writes happen atomically at one commit. Parent death, fatal signal, namespace init death and concurrent cgroup movement cannot strand a child. Stack memory is released only after final schedule-out/unwind/RCU consumers retire. Optimize inline task metadata, reusable caches and shared immutable resources after proof; measure fork/clone latency, allocations, peak RSS, page copies, scheduler locks and threads/sec under container limits.

**Done gate.** Differential native/compat clone flag/size/stack/TLS/TID/pidfd/error tests, concurrent fork/exit/exec/signal and injected allocation/usercopy faults at every stage pass. Force PID wrap/reuse and pids/RLIMIT exhaustion, fork during cgroup migration, vfork signal/exec failures and CPU hotplug. Run Arch/CachyOS libc pthread/fork workloads, shell pipelines and real service managers on QEMU and the operator-booted workstation. Physical SMP stress proves no duplicate/lost task, leaked stack/identity/charge or prepublication observability; relevant startup/throughput/tail/RSS/energy cells meet baseline.

## 2. Exit, wait, reparenting, pidfds, and process relationships — M3–M5

**Baseline.** [`do_exit`](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/kernel/exit.c) coordinates group exit/coredump, ptrace, asynchronous IO cancellation, signals, timers, perf, mm, files, namespaces, cgroups, notifications and final scheduler death. Resources do not all disappear at one reference-count decrement. [`pidfd_getfd`](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/kernel/pid.c) synchronizes with exec credentials and distinguishes disappearing files during exit.

**Ordered implementation.** (1) Define live/exiting/zombie/reaped/dead transitions and separate group exit from individual pthread exit. (2) Implement fatal/normal exit preparation, robust-futex/child-cleartid/vfork release, task-work/IO cancellation, timers, memory/file/namespace release, accounting and scheduler retirement in baseline order. (3) Port parent-death signal, subreapers, PID-namespace init, orphan process groups, SIGHUP/SIGCONT, controlling-terminal/session interactions and exit signal selection. (4) Implement wait/waitpid/wait4/waitid selection by PID/PGRP/pidfd, WNOHANG/WNOWAIT/stopped/continued/clone-thread flags, rusage and restart semantics; synchronize observation/reaping against tracer and competing waiters. (5) Integrate pidfd_open/send_signal/getfd/poll/read/ioctl behaviors present in the baseline, thread pidfds, pidfs information and namespace-visible identity. Route task management prctls, kcmp, process_mrelease and relevant process-memory operations through shared permission/lifetime paths.

**Reuse/shared machinery/simplification.** Reuse common completion/waitqueue, refcount and RCU primitives; reject OS-host child-process abstractions or a single destructor doing arbitrary exit work. Share stable PID objects with signals, procfs, pidfd and namespaces; share shutdown phases with coredump/async IO. A synchronous close phase may simplify early implementation if it preserves observable order and progress; cannot skip cancellation, zombies, subreapers or traced stops to avoid complex waits. PIDFD and numeric-PID paths share target resolution but preserve distinct race guarantees.

**Security/invariants and improvements.** Only eligible parents/tracers reap; WNOWAIT does not consume the zombie. Multiple waiters cannot both release one child; ptrace and parent notifications remain coherent across exec changing thread-group leadership. No callbacks run against a freed mm/task after exit. A pidfd never retargets a recycled numeric PID. Kernel/PID-namespace init semantics match baseline rather than accepting an unhandled init death. Batch accounting/reference retirement where safe; measure exit/reap latency, retained zombie memory, pidfd fanout and fork/exit throughput under load.

**Done gate.** Differential stopped/continued/exited/core-dumped wait status, siginfo/rusage, WNOWAIT/competing waiter, ptrace-parent, pidfd and reparenting traces pass under concurrent kill/exit/exec. Include parent/tracer death, group leader exiting before siblings, namespace-init death, IO blocked during fatal exit, coredump and OOM reaper races. Assert eventual reclamation without post-mortem execution. Real physical low-memory and high-process-count workloads match baseline latency/CPU/RSS/power; a successful `Command::status` smoke is not lifecycle closure.

## 3. Exec transaction and binary-format dispatch — M3–M7

**Baseline.** [`exec.c`](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/fs/exec.c) coordinates credential preparation, exec serialization, mm replacement and the point of no return. The [binary-format Kconfig](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/fs/Kconfig.binfmt) includes native/compat ELF, script, binfmt_misc, ELF FDPIC and architecture-dependent FLAT, old FLAT and compressed ZFLAT. Do not port obsolete a.out behavior not present merely because ELF documentation mentions it historically; do not discard old FLAT that is actually selectable.

**Ordered implementation.** (1) Port execve/execveat filename/fd/AT_EMPTY_PATH/NOFOLLOW behavior, executable-open/write exclusion, permissions, limits on argv/env and recursion, safe usercopy and fd references. (2) Prepare new mm, binfmt and immutable prospective credentials; capture interpreter/file security context and dumpability under exec/cred locks. (3) Implement format dispatch and interpreter recursion, script shebang whitespace/truncation/argument semantics, binfmt_misc registration/matching/flags/lifetime and mount/user-namespace rules. (4) Implement single-threading/de_thread, sibling termination, thread-group leader/PID transfer, tracing event semantics, close-on-exec, signal-disposition reset, TLS/FPU/rseq/robust-list resets, timer/accounting and namespace implications. (5) Mark the exact point of no return: earlier failures return errno to the original image; later fatal failures must not resume the old image or publish half-installed credentials. Finalize mm layout/auxv/registers, clear stale state and return to user mode. (6) Port FDPIC and FLAT/no-MMU/legacy compressed loaders with architecture owners rather than embedding MMU-only assumptions in common exec.

**Reuse/shared machinery/simplification.** ELF/parser libraries may assist byte decoding, never format policy or credential transitions. Share a prepared-exec transaction, fd/VFS access checks, architecture register setup, MM mappings and security hooks. Initial static ELF support is an explicit bring-up subset; scripts/dynamic ELF/binfmt_misc and no-MMU formats remain work. Reject a generic "load bytes then jump" loader or an exec emulation that forks a new identity. Centralize rollback and finalization without assuming rollback remains legal after mm replacement.

**Security/invariants and improvements.** ptrace attach/exec/setuid races serialize against credential decisions; credentials commit at baseline point, dumpability follows interpreter/executable readability and security policy. All lengths/offsets and argv limits are overflow-checked and fallible. A failed exec must not leak opened executable handles or privilege state; CLONE_VFORK parent release occurs even in fatal exec failure. Optimize bounded header reads, mapping setup and argv copies after differential proof; measure exec tail, startup allocations, CPU, RSS and energy for dynamic services and script chains.

**Done gate.** Differential execve/execveat errors, script edge cases, recursion, fd flags, traced multithreaded exec, vfork and setuid/no_new_privs/nosuid behavior pass with allocation/IO/usercopy fault injection on both sides of the commit boundary. External exec/binfmt selftests and shell/service-manager workloads run. FDPIC/FLAT cases require matching target executables and hardware, not x86 emulation claims. No half-exec image or privilege leak is acceptable; per-workload startup/tail/footprint meet pinned baseline.

## 4. ELF loading, user-entry state, core dumps, and vDSO — M3–M8

**Baseline.** [`binfmt_elf.c`](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/fs/binfmt_elf.c) validates executable/interpreter headers, GNU properties, segment layout and architecture personality before/after exec commit. [x86 vDSO mapping](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/arch/x86/entry/vdso/vma.c) has special faults, native/compat images, vvar clocks and mremap/landing-pad behavior. Existing upstream vDSO implementation cannot be linked as C/standalone assembly to shortcut Rust-only implementation.

**Ordered implementation.** (1) Implement bounded native/compat ELF header/program-header decoding, machine/class/endian/ABI flags, ET_EXEC/ET_DYN, segment alignment/congruence, file/memory sizes, overflow and overlapping segment cases using exact pinned loader behavior, not invented stricter validation. (2) Map file-backed PT_LOAD, BSS/tail zeroing, interpreter/load bias, stack/heap layout, personality/ASLR, GNU_STACK/GNU_PROPERTY architecture features and auxv including AT_RANDOM, HWCAP/HWCAP2, PHDR/BASE/ENTRY and secure mode. TLS image interpretation/relocations for ordinary dynamically linked ELF belong to the user-space dynamic linker; kernel supplies correct mappings, auxv and thread TLS machinery, not a second dynamic linker. (3) Set native/compat initial registers, stack alignment, argv/envp/auxv, architecture function descriptors and no-MMU/FDPIC requirements. (4) Build Rust-produced architecture-specific vDSO/vvar artifacts with exact versioned symbols, syscall fallback, clocksource validity, time namespaces, getcpu/getrandom and all baseline exported functions; preserve legacy vsyscall policy and ia32 sysenter/vDSO landing semantics where supported. (5) Implement coredump group freeze/lifetime, ELF notes/regsets, filtering/limits, file/pipe helper modes, naming and suid security with observability/filesystem owners.

**Reuse/shared machinery/simplification.** [`object`'s upstream security statement](https://raw.githubusercontent.com/gimli-rs/object/master/README.md) explicitly targets trusted inputs, has limited DoS mitigation and does not promise loader equivalence. It is a conditional low-level decoding candidate after no_std/fallibility/complexity audit, not an approved hostile-input exec loader. Alternative `goblin`/`elf` candidates require the same audit; no parser crate replaces baseline mapping/ABI logic. Share bounded byte readers, ELF definitions, MM mapping transactions, architecture regsets and core timekeeper data. Begin with syscall fallback when vDSO clock mode is unsuitable, but do not omit ABI symbols, auxv or final vDSO performance. Removing vsyscall/old compat frames without baseline policy is scope loss.

**Security/invariants and improvements.** Untrusted ELF cannot cause unbounded allocations/loops, integer-wrap mappings, stale bytes or accidental kernel executable aliases. Preserve architecture CET/BTI/PAC-related properties where applicable and the same security policy as baseline. vDSO reads use a valid sequence/memory-order protocol and fall back when source/namespace state is unsuitable; user writes cannot change shared kernel time state. Core files do not leak inaccessible/setuid process memory. Improve zero-copy bounded decode and map batching; measure real dynamic loader startup, vDSO function latency, fallback ratio, core dump pause/throughput and memory.

**Done gate.** Fuzz ELF/script/FLAT parsers and differential-load overlapping/truncated/malformed segments, huge counts, zero-size files, unusual alignment and faulting interpreters. Test real Arch/CachyOS libc/loader, PIE/static binaries, setuid transitions and native/compat auxv byte layouts. Upstream vDSO tests compare every exported symbol and clock relationship, including source changes, namespace offsets, mremap and suspend on real hardware. Debugger reads produced core notes/regsets correctly; coredump security/filter/limit/pipe races pass. Host parser unit tests and vDSO availability alone do not qualify exec or timing.

## 5. Syscall entry, dispatch, restart, and compatibility ABIs — M1–M8

**Baseline.** [Adding-syscalls compatibility rules](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/process/adding-syscalls.rst) explain pointer-containing/long/time/off_t structure differences, split 64-bit arguments, separate x86 x32 handling and architecture syscall tables. [x86 signal/restart code](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/arch/x86/kernel/signal.c) shows ERESTART variants and native/compat restart-number rules. A table of numbers is not behavioral implementation.

**Ordered implementation.** (1) Inventory every baseline architecture syscall table/UAPI structure, including conditional/obsolete/reserved entries; associate each with owning subsystem and ABI-specific semantics. (2) Implement real exception/syscall entry/return and register frames, kernel stack/TLS/GS handling, speculation/privilege mitigations, saved flags, interrupted/reentrant paths and bad user return recovery. (3) Decode x86_64, ia32 `int 0x80`/sysenter and x32 separately, then every architecture's native/compat ABI, including split-register 64-bit values, endian/alignment, old/time64/select/stat/signal/ioctl forms and return-register conventions. (4) Implement typed kernel-internal syscall operations behind narrow ABI decoders with bounded usercopy and exact errno/partial-success semantics. (5) Integrate audit, ptrace, seccomp, syscall-user-dispatch, restart blocks, signal/rseq/task-work/reschedule loop and architectural return work without skipping state after an early return. (6) Preserve baseline-specific unsupported/reserved/removed calls and errors; ENOSYS is correct only where the baseline actually returns it, not a wall hiding unimplemented calls.

**Reuse/shared machinery/simplification.** Rust `repr(C)`/extern calling conventions are allowed ABI syntax, not permission for C implementation. `linux-raw-sys` or hand-audited UAPI definitions may supply constants/layout candidates; host `libc`/`nix` are test-side conveniences only and cannot define the entire kernel ABI from the current host. Pin/provenance review is required under [dependencies](../dependencies.md). Share syscall metadata, usercopy, errno/restart and architecture-regset definitions. Decode compat once then call common semantic operations where truly equivalent; never cast a 32-bit struct to a native struct. A native-only stage is explicitly partial, with all legacy/compat tables retained in final scope.

**Security/invariants and improvements.** Preserve sign/zero extension, padding initialization, pointer-width truncation, versioned struct tail/unknown-bit behavior and ioctl command-size interpretation. Never construct a Rust reference over attacker-mutable user bytes. Return-path validation prevents noncanonical/privileged register state and speculation leaks. Restart must not repeat a completed side effect or expose internal ERESTART errno. Optimize dispatch/static metadata and avoid needless decode allocations/copies only after ABI proof. Measure null/common syscall costs, usercopy throughput, interrupt/restart tail and real application CPU/startup at identical mitigations.

**Done gate.** Per-entry acceptance ledger covers arguments, outputs, error ordering, pointer faults, signals/restart, privilege and concurrency for every ABI/configuration. External LTP/kselftest/strace-style workloads differential-check observed behavior; tests include 32-bit and x32 binaries where selected, time32 boundaries/Y2038/time64, invalid returns and async interrupts at entry/return. Architecture hardware evidence is mandatory before that ABI is qualified. seccomp/audit/ptrace observe the right ABI/number/arguments after rewrites; native smoke never certifies compat closure.

## 6. Signals, job control, alternate stacks, and restart races — M3–M8

**Baseline.** [Generic signal implementation](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/kernel/signal.c) and [architecture signal frames/restart](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/arch/x86/kernel/signal.c) couple group stops, ptrace, siginfo and machine state. Frame setup differs for ia32, x32 and x86_64, and syscall restarts depend on SA_RESTART plus internal restart class.

**Ordered implementation.** (1) Define per-thread masks/private pending and shared process pending queues, standard-signal coalescing and realtime ordering/queued siginfo with limits and fallible allocation. (2) Implement kill/tkill/tgkill/pidfd_send_signal/rt_sigqueueinfo variants, namespace-aware target/permission checks, thread selection and wakeup of interruptible/killable tasks. (3) Port dispositions, rt_sigaction/procmask/pending/sigtimedwait/sigsuspend, alternate stacks/SS_AUTODISARM, default fatal/core/ignore actions and unblockable signals. (4) Implement architecture native/compat frame/trampoline/restorer and sigreturn validation: FPU/vector/xstate, debug/TLS/control state, stack alignment/red zone and nested signals. (5) Integrate job-control stop/continue/orphaned groups, ptrace signal-delivery/group stops, parent/tracer SIGCHLD, exec/fork/exit resets, POSIX/CPU timer queues and restart/pselect/ppoll/signalfd interactions.

**Reuse/shared machinery/simplification.** Reject user-space signal-handler crates and generic channels as pending-signal implementations. Reuse common queue/wait mechanisms, ABI siginfo definitions and architecture regsets with explicit padding/union handling; IPC owner consumes signalfd, core owns timers. One signal code path can share native/compat semantic operations, not frames. Initial synchronous fault signals are partial; deferring all delivery until the next syscall, collapsing realtime queues or treating every interruption as EINTR drops observable behavior.

**Security/invariants and improvements.** A signal can arrive during usercopy, MM fault, clone publication, group exit, ptrace stop or return-to-user; no lost pending state, double queue release or missed wake is allowed. SIGKILL/SIGSTOP cannot be masked; namespace init has special baseline rules. Validate attacker-built sigreturn frames so privileged flags/XSAVE state cannot be restored, and avoid leaking kernel padding in siginfo/frame. Signal-queue OOM follows exact baseline semantics rather than panicking. Improve pending bitmap/queue locality and avoid allocation for coalesced standard signals; measure send-to-handler tails, signal storm CPU/RSS, stop/continue latency and timeout restart error.

**Done gate.** Differential concurrent thread-directed/process-directed standard/realtime sends, queue exhaustion, masks, nested altstack, async IO SIGIO, timers, signalfd and stop/continue traces pass. Adversarial sigreturn/XSAVE/compat frames, page faults while building a frame, SA_RESTART versus partial IO and signal-vs-timeout wake races are covered. Debugger/shell job-control and real service shutdown tests run physically as well as in QEMU. All architecture-specific frames and FPU/vector feature sizes require their own hardware/configuration evidence and at-least-baseline relevant tails.

## 7. ptrace, process inspection, regsets, and debugging authority — M3–M8

**Baseline.** [`ptrace.c`](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/kernel/ptrace.c) explicitly documents detach/tracer-death versus group-stop transitions and transient RUNNING visibility. Memory access uses task/mm permission/lifetime paths rather than uncontrolled direct page-table walking. Exec can change the leader identity and leave an unconsumed exec event.

**Ordered implementation.** (1) Implement centralized ptrace access modes/credential snapshots, dumpability, user namespace capability and LSM checks used by ptrace/proc/process_vm/pidfd_getfd. (2) Port attach/seize/interrupt/listen/detach, tracer reparenting, signal-delivery/group/syscall/event stops and wait reporting; model transitions with signal/job-control locks. (3) Add PEEK/POKE, GET/SETREGS/REGSET, debug registers, single-step, syscall modification/emulation/options and event-message/siginfo operations; map all native/compat regsets. (4) Integrate fork/vfork/clone/exec/exit/seccomp events, PTRACE_O_EXITKILL, tracer death, multithreaded exec and kernel workers. (5) Coordinate proc inspection, process_vm read/write, kcmp and core dump regsets with stable references and exact permissions.

**Reuse/shared machinery/simplification.** No debugger protocol crate supplies ptrace state semantics. Share architecture register serialization with signals/core dumps and one permission checker with all inspection paths; do not centralize distinct access modes into a single root boolean. Basic stop/continue may precede syscall tracing but is not debugger parity. Reject pretending that synchronous `wait` alone means target is stably stopped for arbitrary modification.

**Security/invariants and improvements.** A privilege-changing exec cannot race attach to produce an unauthorized tracer. Detached/exiting tracers cannot leave tasks indefinitely TASK_TRACED, suppress required group stops or retain stale parent/credential refs. User memory writes preserve COW and cache/permission semantics; no arbitrary kernel state is restored from a regset. Optimize register packing and stop notifications without erasing observable intermediate states. Measure debugger syscall/event overhead, stop/resume tails, remote memory bandwidth and untraced fast-path cost.

**Done gate.** Upstream ptrace/regset/breakpoint tests plus real debugger/strace sessions cover attach to running/stopped/execing/exiting tasks, tracer death, EXITKILL, seccomp stops, single-step over signals, TLS/vector regsets and competing waiters. Differential errno/stop reason/status/reg bytes match baseline under race-tolerant allowed outcomes. Physical debug-register/vector architecture features and cross-CPU migration are required; missing features are blockers, not stubbed success. Untraced workloads must not regress to pay for tracing machinery they do not use.

## 8. Futex, robust ownership, priority inheritance, and futex2 — M3–M8

**Baseline.** [`waitwake.c` ordering proof](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/kernel/futex/waitwake.c) guarantees a waiter either sees the changed user word or is observed by the waker; barrier pairing protects the empty-bucket fast path. [Futex UAPI](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/include/uapi/linux/futex.h) includes legacy operations, PI2, futex2 flags/vector waits and robust-list constants. Presence of a historical opcode/size flag does not imply every combination is accepted; derive exact support/errors from pinned syscall implementation. [Robust futex design](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/locking/robust-futexes.rst) explains list_op_pending and owner-death cleanup; its old historical architecture statements are not the current support matrix.

**Ordered implementation.** (1) Port private/shared key derivation using stable mm/inode/page offset identities, address alignment/permissions and safe lifetime references across faults/unmap; shared aliases must rendezvous correctly without keying solely by virtual address. (2) Implement WAIT/WAKE/BITSET with atomic compare-and-enqueue, timed/realtime/monotonic distinctions, signal/restart and lockless waiter-count ordering. (3) Implement REQUEUE/CMP_REQUEUE/WAKE_OP with deterministic two-bucket locking and no-fault user atomic operation/retry; cover same-key/overlapping-address cases. (4) Port robust registration/native/compat list walking, bounded malformed/cyclic input, pending-operation handling, OWNER_DIED/WAITERS and child-cleartid; cleanup on exit and exec paths follows pinned behavior. (5) Implement PI LOCK/TRYLOCK/UNLOCK/PI2 and REQUEUE_PI using core rtmutex with owner TID validation, state caching, donation/deboost, owner death, timeout, signals and task-exit races. (6) Port all baseline futex2 entry points/vector waits, supported size/NUMA/policy flags, reserved fields and error ordering; multiwait cleanup must dequeue every unselected waiter exactly once. Include baseline per-mm/private hash allocation/control behavior, not just an older global hash design.

**Reuse/shared machinery/simplification.** Reuse kernel PI/waitqueues/timers, MM user cmpxchg and stable ID refs. Reject `parking_lot`, generic concurrent queues, std mutexes and a user-space futex crate as the kernel engine. Share semantic wait machinery while keeping futex ABI keying and ordering proofs explicit; one PI graph with core avoids mismatched donation implementations. Non-PI WAIT/WAKE is a bring-up subset, not pthread compatibility completion; mapping all PI ops to ordinary waits is wrong. Avoid kernel allocation for uncontended userspace locks and preserve baseline robust fast path.

**Security/invariants and improvements.** Never hold a raw bucket lock across a potentially sleeping fault/reclaim; retry with key/state revalidation. Timeout, wake, unmap, requeue and signal compete for one waiter ownership transition. Userspace can corrupt lists, lock words and owner IDs at any time; bounded cleanup must not fault the kernel, unlock another owner's word or loop indefinitely. PI refcounts and donation paths retire on every failure. Improve hash locality, wake batching and empty-bucket fast paths only with memory-model proof; measure uncontended syscall overhead, contended handoff tails, requeue throughput, collision pressure, memory per waiter and PI inversion.

**Done gate.** Upstream futex functional/performance/PI tests and libc pthread mutex/condvar/rwlock/semaphore suites pass native/compat. Stress wake-vs-enqueue litmus, timeout/signal/requeue, private/shared aliases, malicious robust lists, owner death/exec/TID reuse, vector partial failure, hash-resize/control operations and deep PI chains under RT. Physical SMP/NUMA and relevant weak-memory hardware tests supplement QEMU; rt-tests PI stress and application contention show at-least-baseline handoff tails/throughput without weakened ordering. A bounded Rust thread-join smoke does not qualify robust or PI futexes.

## 9. Restartable sequences, TLS, per-thread state, and CPU migration — M3–M8

**Baseline.** [rseq UAPI](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/include/uapi/linux/rseq.h) includes cpu_id_start/cpu_id, aligned critical-section descriptors, node_id and mm_cid. [`rseq.c`](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/kernel/rseq.c) describes the half-open critical range ending before the commit point, abort target validation and updates before return to userspace. This is not simply a fast `getcpu` syscall.

**Ordered implementation.** (1) Port registration/unregistration pointer, size, alignment, flags and signature validation, including original-size versus extended ABI behavior and per-thread duplicate registration rules. (2) Integrate scheduler preemption/migration and signal notification into return-to-user processing; read descriptors through fault-aware bounded user operations and redirect only when the interrupted IP is in the specified critical range. (3) Update CPU/node/mm concurrency IDs with required single-copy atomicity and exact failure behavior; allocate/reuse mm_cid with scheduler/MM lifecycle. (4) Define fork/clone/exec reset/inheritance and interactions with ptrace single-step/flags, CPU hotplug and time spent in the kernel. (5) Complete architecture TLS, set_thread_area/arch_prctl or equivalent, task names/prctl state, CPU affinity/getcpu and per-thread ABI state needed by libc.

**Reuse/shared machinery/simplification.** No user-space rseq crate implements kernel fixups; librseq/upstream tests are external test clients only. Reuse checked usercopy, architecture register manipulation, MM IDs and scheduler notification bits. A shared return-work loop with signals/ptrace/syscalls prevents missed rseq processing; keep their ordering exact. Omitting mm_cid/node fields, accepting registrations without abort support or using the CPU sampled before final migration is not a safe simplification. Initially unsupported registration must remain reported as incomplete, never fake success.

**Security/invariants and improvements.** Descriptor memory can change/unmap; never trust a saved pointer as stable Rust data. Validate overflow in post_commit_offset, abort signature/target and flags according to baseline; invalid descriptors must produce correct user-visible failure, not kernel control transfer. Ensure no post-commit store is replayed. mm_cid uniqueness and release do not leak IDs or let one thread index another's per-CPU state after migration. Optimize notification bits and only necessary field updates, measuring rseq abort rate, per-thread registration cost, return-path CPU and allocator/server throughput.

**Done gate.** Run upstream rseq tests for each supported architecture with forced migration/preemption/signals at instruction boundaries, membarrier interactions, ptrace single stepping, malformed descriptors, inaccessible memory and fork/exec. Differential registration/errors/field contents and critical-section results match baseline allowed outcomes. Real SMT/NUMA and hotplug stress verifies no lost/duplicate commits or stale per-CPU updates; physical architecture evidence is required before enabling its rseq feature claim. Compare real libc allocator/per-CPU workloads rather than timing registration alone.

## 10. Credentials, capabilities, user accounting, and resource limits — M3–M8

**Baseline.** [Credential documentation](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/security/credentials.rst) distinguishes subjective/objective context, real/effective/saved/fs IDs, supplementary groups, capabilities, keys and security labels. Published credentials are immutable except carefully defined exceptions; files may retain opening credentials independent of the current task. Policy/security implementation is coordinated with [security](security.md), not duplicated here.

**Ordered implementation.** (1) Model immutable refcounted credentials and typed kernel IDs versus namespace-mapped user IDs, ucounts/user accounting, groups and security/key references; separate real_cred from temporary subjective overrides. (2) Implement prepare/commit/abort and override/revert protocols with RCU publication and allocation rollback. (3) Port UID/GID/group/fs-ID syscalls, capget/capset, securebits, ambient/inheritable/permitted/effective/bounding sets and per-thread Linux semantics; libc's all-thread set-ID coordination remains userspace behavior, not an invented kernel-wide credential update. (4) Integrate exec's setuid/file caps/nosuid/no_new_privs/ptrace/dumpability/LSM/keyring transitions and user-namespace mappings. (5) Implement get/setrlimit/prlimit, accounting inheritance/exec effects, scheduler permissions, NPROC/pids/core/memlock/AS/DATA/FSIZE/CPU/NOFILE/SIGPENDING and every remaining baseline limit with owning subsystem; port keyctl/session/credential-dependent process prctls through security owner.

**Reuse/shared machinery/simplification.** Reuse kernel hardened refcount/RCU and security hooks; reject an authentication/web RBAC crate or a single `is_root` field as Unix/capability policy. Share ID mapping, per-user accounting, opened-file credentials and ptrace permission modes across VFS/network/IPC. Centralize common checks without flattening capability namespace ancestry or per-operation real/fs credential distinctions. Root-only debug operation is an early restricted environment, never final permissions behavior.

**Security/invariants and improvements.** No mutation of shared published credentials, refcount resurrection or override surviving an error path. Check privileges in the correct namespace at the correct operation point; stale credential snapshots cannot authorize an unrelated later action. Resource charge/limit failure rolls back before object publication and cannot be bypassed through clone/exec/namespace transitions. No forgotten capability/ambient state after exec. Optimize immutable sharing, group lookup and charge batching only after authority/ordering proof; measure per-operation checks, credential-update tails, memory per task and container startup CPU.

**Done gate.** Differential ID/capability/rlimit/security selftests cover every transition and error, threads with different raw-syscall creds, nested user namespaces, supplementary groups, file caps, no_new_privs, setuid/nosuid and ptrace/exec races. Inject OOM during prepared credentials/groups/keys and limit-accounting rollback. External container and Arch/CachyOS service-manager tests preserve least privilege and resource isolation on physical hardware. Security owner signoff and baseline-equivalent denied operations are completion requirements, not an optional slowdown to disable during benchmarks.

## 11. cgroup core, controllers, and namespaces — M3–M8

### cgroup lifecycle, hierarchy, and delegation

**Baseline.** [cgroup v2](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/admin-guide/cgroup-v2.rst) defines process/thread placement, domain/threaded constraints, controller propagation, no-internal-process rules, delegation, asynchronous destruction and v1 coexistence. [v1 index](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/admin-guide/cgroup-v1/index.rst) retains multiple hierarchies and legacy controllers; v2-first is not v1 removal.

**Ordered port.** (1) Implement cgroup filesystem node/state lifetime, css/css_set-like membership links, controller registration, references and asynchronous offline/free. (2) Port mount/remount options, hierarchy/controller association, subtree control, delegation/ownership/namespace boundaries and v1 coexistence constraints. (3) Implement transactional process/thread attach/migrate, fork/exit hooks, clone-into-cgroup, threaded/domain transitions and task iteration under concurrent exit. (4) Add freezer/events/pids/cpuset core semantics, populated notifications and poll; integrate CPU/accounting with core, memory with MM, IO with storage and remaining devices/RDMA/hugetlb/misc/DMEM/network/perf facilities with their owners. (5) Qualify every selectable v1 controller and v2 control file, legacy mount option and write/error behavior against the pinned reference.

**Reuse/shared machinery/simplification.** No generic hierarchy crate supplies resource ownership/delegation; share refcount/RCU, VFS/kernfs-style nodes, IDs, controller transaction hooks and hierarchical counters. Reuse attach validation/rollback for task creation and migration without merging their distinct publication rules. V2-only server bring-up is partial; no-op controller files or always-success resource writes are prohibited. **Invariants/improvement:** no privilege escape through subtree movement, stale css use after offline or missing charges while membership changes. Optimize common immutable css_set sharing, task iteration and batched counters; measure fork/migration/exit cost, controller CPU/RSS, fairness/isolation and freeze tails. **Done:** upstream cgroup/controller tests and real container/service-manager workloads cover delegation, nested controls, concurrent migration/fork/exit/controller removal and OOM. Differential files, errors/events and resource effects match baseline; each controller owner supplies physical/performance evidence before cgroup closure.

### Namespace objects, creation, joining, and teardown

**Baseline.** [`nsproxy.c`](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/kernel/nsproxy.c) separates current versus for-children PID/time namespaces, validates CLONE_NEWIPC with shared semaphore undo, and destroys partly constructed namespace bundles in reverse order. Namespace ownership by a user namespace determines authority; a namespace is not simply a dictionary of renamed IDs.

**Ordered port.** (1) Define independently refcounted user/PID/mount/UTS/IPC/network/cgroup/time namespace objects, namespace-proxy sharing, nsfs fd identity/ioctls and owning-user/parent relationships. (2) Port clone/unshare/setns including multi-namespace pidfd-target joining, constraints on sharing threads/fs/mm, capability ancestry and atomic validation/install rules. (3) Implement UID/GID maps/setgroups policy, PID hierarchy/init/reaper, UTS state and time offsets with exact current/children differences. (4) Integrate mount propagation/root/cwd/idmapped-mount semantics with filesystems, IPC undo/limits with IPC, network object lifetime with networking, cgroup view/delegation and vDSO time namespace data. (5) Handle namespace init death, orphan/reparent/zombie behavior, last-fd versus last-task lifetime, asynchronous destruction, quotas/limits and creation rollback.

**Reuse/shared machinery/simplification.** Reuse common immutable namespace bundle transactions, typed IDs, RCU and fd references; no container library/runtime or user-space namespace crate replaces kernel semantics. Namespace identity and controller/security policy share machinery but not ownership: joining a network namespace does not transfer all task credentials. Begin with initial namespaces but retain every creation/join/error path as incomplete until implemented. **Invariants/improvement:** no partial multi-join privilege escalation, escape through mount/fs sharing, foreign PID disclosure, namespace ID confusion or premature device/network teardown. Avoid cloning unchanged namespace state and duplicated reference churn while measuring clone/unshare/setns cost, memory per container, teardown tails and startup. **Done:** nested namespace/capability/selftests and real OCI/container lifecycle tests cover fd pinning, join order, invalid bundles, multithreading, parent death, time offsets, mount propagation and resource exhaustion. Real network/storage/device namespace consumers and physical boot tests are mandatory; namespace ID files alone do not prove isolation.

## Acceptance execution, retained behavior, and current limitations

The [actual bounded Rust smoke suite](../bare-metal-suite.md) has this interface:

```text
cargo run -p baremetal -- run --output <new-directory> --label <label> --expect-release <exact-osrelease> --environment <reference|qemu|bare-metal>
```

It verifies the exact running release and records the operator's environment label; neither label nor running successfully on the reference proves a new kernel exists. Bounded threads/memory, exec/wait/exit, sandbox filesystem operations, loopback IPC and proc/sysfs visibility can exercise basic process plumbing on an operator-booted candidate. They do **not** certify clone3, compat, ptrace, signals, futex PI/robustness, rseq, namespaces, security, cgroups, OOM or at-least-Linux performance. A skip/unavailable result cannot close a required gate. All broad qualification suites above remain future implementation work; no tests are run by this documentation task.

For exhaustive execution, a Rust orchestration layer must select named/versioned external kselftest/LTP/libc/rt-tests/container cases, serialize configuration-changing cases, bound time/resources, collect full errno/siginfo/register/content/status traces, restore controlled state and separate unsafe lab tiers. Test harnesses must record reference commit/config, candidate revision, toolchain, suite revision, actual arguments, seeds/durations, privilege/environment, hardware topology/firmware, serial logs and per-case outcomes. Never run fork bombs, arbitrary setuid tests, cgroup reconfiguration, namespace mount tests or RT priority stress by default on the daily workstation. Only that workstation is currently available; new platform/NUMA/weak-memory/legacy-ABI hardware and independent timing capabilities remain named blockers until obtained.

Kernel completion follows [definition of done](../definition-of-done.md), not "a shell boots" or "all syscall numbers are listed." Retain every baseline-present UAPI/prctl/personality/binfmt/configuration/architecture variant, including legacy interfaces with deliberate baseline errors. Each discovered case gets implementation/provenance/normal-boundary-failure-race-security-recovery-performance evidence; no placeholder return or test narrowed to the implemented subset can close it. Use repeated per-workload/hardware statistics for throughput, p50/p99/p99.9/max latency, CPU, peak/resident memory, service/container startup and energy under matched mitigations/configuration. Report each regression or unproven non-inferiority; no geometric mean hides one. Physical qualification begins with M1/M2 bring-up and continues through these process milestones, never waits until M8. Future operator installation/selectable Limine/systemd-boot packaging preserves the existing kernel and follows [packaging](../packaging.md); this plan supplies no fake kernel/package artifact and authorizes no install/reboot action.
