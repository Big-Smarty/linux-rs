# Drivers, buses, devices, and sound

## Scope and evidence boundary

The driver/sound facility program below remains future work, with no hardware or performance qualification. Limited early ACPI discovery is owned and bounded by [firmware](firmware.md); all other unimplemented driver/sound workstreams remain **not_started**, and no driver family is complete. The pinned Linux **6.18.57** tree contains **143 first-level `drivers/` directories** and **25 first-level `sound/` directories**. Both exact lists were reconciled with the inventory owner. Each has an individual row below; grouping does not erase devices, bindings, quirks, firmware dependencies, or UAPIs within it. Directory coverage is not device coverage. The complete path inventory and longest-prefix ownership are in [coverage](../coverage.md).

Accepted architecture: modular monolithic Rust kernel, fixed 6.18.57 feature baseline with explicit reviewed security deltas. Every baseline module's functionality requires a Rust replacement; loading legacy C modules is forbidden, and arbitrary proprietary/out-of-tree module functionality is not silently promised. Function-local `asm!`/`naked_asm!` is allowed only where unavoidable under the [architecture proof contract](architectures.md); no `global_asm!` or standalone-assembly escape.

Observed source evidence: [drivers tree](https://github.com/gregkh/linux/tree/v6.18.57/drivers), [driver build ordering](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/drivers/Makefile), [driver configuration](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/drivers/Kconfig), [sound tree](https://github.com/gregkh/linux/tree/v6.18.57/sound), and [sound configuration](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/sound/Kconfig). Family names in tables mean the exact upstream directory, not a newly invented API. The source tree, UAPI headers, binding schemas, per-device manuals and Linux behavior together define the eventual device-level work register. The following designs are proposals; no crate, board or peripheral is admitted or qualified by being named.

Cross-subsystem contracts: [architectures](architectures.md), [firmware](firmware.md), [memory and DMA](memory.md), [storage](storage.md), [networking](networking.md), [security](security.md), [virtualization](virtualization.md), [performance](../performance.md), [bare-metal execution](../bare-metal.md), [verification](../verification.md), and [dependency admission](../dependencies.md).

## Ordered foundations, including physical machines from M1

1. **M1: recoverable physical boot and register access.** Bring up x86_64 QEMU plus user-operated current-workstation boot only after safe candidate/recovery gates exist; independent power/serial or remote-console infrastructure is a named acquisition blocker if absent. Preserve known-good boot entry, isolate network, and use only approved sacrificial storage for later destructive tests. Capture non-secret machine/CPU/firmware/PCI identities. Implement Rust-only early UART and clock/interrupt primitives; map MMIO with device attributes and explicit width/endian semantics. Port only unavoidable privileged operations to reviewed local `asm!`/`naked_asm!`; no `global_asm!`, `.S`, hidden C entry code or C module loading. Missing physical evidence blocks qualification rather than making VM output equivalent.
2. **M1–M2: device lifetime and enumeration.** Implement resource ownership, reference/lifetime rules, bus/class/device hierarchy, ID matching, deferred probe, dependency links, exclusive resource claims and transactional probe unwind. Port platform/ACPI/DT discovery, then PCI config/BARs/bridges and IRQ routing. Device objects survive open file descriptors; removal first stops new work, revokes access, drains IRQ/DMA/work/timers, and only then reclaims memory. Expose Linux-compatible sysfs, modalias and uevents when VFS/userspace gates exist; early in-kernel observations are not proof of those ABIs.
3. **M2: DMA, IOMMU and interrupt domains before bus mastering.** Distinguish CPU virtual, physical and device-visible addresses; support DMA masks, scatter/gather, coherent and streaming ownership, noncoherent cache maintenance, bounce buffering, peer limitations, mapping failure and IOTLB invalidation. Keep devices quiescent until translations and IRQ ownership exist. Implement hierarchical IRQ domains, shared/threaded handlers, MSI/MSI-X affinity, edge/level acknowledgement and lost-interrupt recovery. Physical Intel and AMD IOMMUs and a noncoherent platform are separate proof cells.
4. **M2–M4: buses and coordinated power.** PCI, platform and serial dependencies precede USB host controllers/hubs/transfers, then USB classes and gadget/dual-role support. Port reset, clock, regulator, pinctrl, PHY, runtime PM, system suspend/resume, wake routing and hotplug ordering. Use fallible, context-aware allocation: no sleeping in hard IRQ/atomic context; no blanket no-heap constraint. Exercise plug/unplug, probe failures and power transitions on hardware alongside emulator fault cases.
5. **M4–M5: genuine server I/O.** Co-develop NVMe/SATA/SCSI and Ethernet on physical devices, not only virtio; then multiqueue, recovery, offloads, SR-IOV and container interfaces. Durable storage work is owned with the storage plan. Network protocol and wireless policy semantics belong with the networking plan. Device reset must not invalidate shared driver state or another tenant's memory.
6. **M6–M7: breadth without C fallbacks.** Add graphics, sound, media, embedded/RT, unusual buses, accelerators, remote processors, legacy devices and every device-specific branch represented by the inventory. Preserve required Linux quirks and UAPI. An unavailable manual, legal firmware or physical device is a named closure blocker, not permission to delete the family.
7. **M8: per-device closure and maintenance.** Close every device/configuration/architecture cell with the definition of done below; compare every supported workload against pinned Linux on the same hardware. Retain recovery and security gates for every future update.

The source [device model overview](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/driver-api/driver-model/overview.rst) motivates a shared hierarchy, not copying its historical attribute examples as the current ABI. [DMA mapping rules](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/dma-api-howto.rst) explicitly distinguish the three address spaces. [USB PM](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/driver-api/usb/power-management.rst) distinguishes runtime and system suspend. [Internal API policy](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/process/stable-api-nonsense.rst) permits replacing internal APIs, not breaking userspace.

## Reuse, sharing and simplification rules

The common reuse baseline in **every row** is a direct GPL source port of its pinned directory and associated `include/`, `Documentation/`, binding and test files, preserving provenance. Existing Linux Rust drivers may still depend on C-backed Linux abstractions: they must be retargeted to genuine Rust primitives, not linked unchanged and called a Rust-only kernel. The [existing Rust Binder option](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/drivers/android/Kconfig) and Rust GPU code are starting evidence, not autonomous replacements.

Candidate libraries, all subject to [licensing](../licensing.md), `no_std`, allocation, panic, concurrency, code-generation and transitive native-code review:

- [virtio-drivers](https://github.com/rcore-os/virtio-drivers): useful queue/device reference, but its published support table explicitly has feature gaps; do not equate it with Linux virtio parity. Adapt DMA ownership and synchronization; reject its standalone assembly examples for project implementation.
- [embedded-hal](https://github.com/rust-embedded/embedded-hal): reuse bus transaction vocabulary for suitable leaf devices; it is not Linux I2C/SPI/IRQ/PM/sysfs/UAPI implementation. PAC/HAL crates require board/SoC-specific admission and cannot dictate a single-threaded global peripheral model to SMP Linux.
- [acpi](https://github.com/rust-osdev/acpi), [uefi](https://github.com/rust-osdev/uefi-rs), and FDT parsers are firmware candidates, not C ACPICA/libfdt wrappers; detailed gaps and license review are in [firmware](firmware.md).
- Architecture crates may inform register encodings; they do not establish Linux barriers or DMA correctness. There is **no selected drop-in Rust crate for the complete DRM, ALSA, V4L2, RDMA, USB or legacy-driver matrix**. Those are direct-port work, not a reason to expose reduced APIs.

Share resource guards, regmap-style checked register access, bus transactions, scatter/gather queues, firmware loading, timestamps, work scheduling, PM dependency links, ABI validation and tracing where semantics match. Simplify internal callback plumbing and duplicate probe unwind with explicit state transitions. Do not unify different DMA coherency, reset, IRQ acknowledgement, device power or ioctl semantics merely because interfaces look similar. Eliminate avoidable per-I/O allocation/copying and global locks only after behavior is proved. Every optimization below is a hypothesis until [non-inferiority measurements](../performance.md) establish at least baseline behavior on each device/workload with matching security settings.

## Family implementation register

Each row answers implementation order/dependencies; reuse and safe sharing/simplification; security/compatibility traps; and a specific optimization plus observable proof. `→` denotes order, not implemented code. **P** means genuine physical hardware proof in addition to host/parser and emulator tests. For purely software facilities, P means executing on a qualified physical-host kernel. Every row inherits the mandatory crate screening and full definition of done, not merely its example test.

## Sound is a separate complete workstream

Sound is outside `drivers/`, not an implicit checkbox under media. First implement ALSA core PCM/control/raw-MIDI/sequencer/timer/hwdep APIs and 32-bit compat, period accounting, mmap synchronization, timestamp/clock domains and suspend state. Then transport/controller drivers, codecs, machine routing, DSP firmware and all legacy interfaces. Share DMA-buf only where actual semantics permit; audio clock drift and XRUN rules are not interchangeable with video fences. No general Rust audio crate is selected as a Linux ALSA implementation. Userspace ALSA/PipeWire/JACK applications are external workloads, not kernel implementations.

All rows below reuse the pinned `sound/<family>` source plus relevant transport primitives; all remain **not_started**. A digital loopback alone does not prove analog codec, microphone privacy, amplifier sequencing or real-time latency.

## Exhaustive definition of done and runnable proof obligations

A family row is **not done** because one device probes, a crate compiles, a QEMU screenshot exists, or a happy-path workload runs. The device-level register must enumerate every pinned source leaf, Kconfig branch, hardware ID/revision, transport, binding and externally visible interface. Link each to its implementation files, provenance, maintained test cases and exact qualification cells. Generated inventory is a discovery aid, never an implementation percentage.

For **each family and each sound family**, closure requires all of the following:

1. **Source and ABI closure:** every relevant upstream file is ported or has an explicit evidence-backed non-executable/generated/dead-configuration disposition; no unexplained C runtime dependency. All associated ioctls, compat layouts, sysfs/debugfs/configfs/netlink attributes, mmap/poll/read/write semantics, uevents, parameters and device-tree/ACPI bindings have differential tests. No blanket ENOSYS or silently ignored feature.
2. **Lifecycle closure:** boot probe and deferred probe; every injected resource-allocation/probe failure; multiple devices and consumers; open/close/unbind races; IRQ/timer/work/DMA cancellation; shutdown/reboot; hotplug where supported; CPU/memory/device topology changes; runtime and system suspend/resume; firmware absence/update/failure; all advertised resets and recovery paths. Every failure must preserve ownership and isolation without leaks, deadlocks or stale DMA.
3. **Data-path closure:** valid/invalid boundary requests, malformed descriptors, alignment/endian/width variants, short I/O/residuals, ring wrap and exhaustion, noncoherent DMA, memory pressure, timeout, cancellation, concurrency, RT/preemption and NUMA. Check integrity, ordering, timing and error codes against pinned Linux, not just exit status.
4. **Security closure:** least-privilege access, namespace/tenant boundaries, user-copy and integer bounds, DMA/IOMMU isolation, firmware authenticity policy, key/secret disposal, hostile peripheral/peer behavior and mitigation-equivalent execution. Independent unsafe/assembly and device-firmware trust reviews are required.
5. **Physical closure:** all claimed hardware-ID/revision/firmware/platform cells run on actual hardware or carry an explicit unqualified/blocker status. Multiple vendors and controller generations cannot be inferred from one board. Virtual devices require a qualified physical host and truthful guest/partition labels. Emulation complements physical proof; it never substitutes for real electrical, power, interrupt, cache or timing behavior.
6. **Performance closure:** match the baseline on per-device/workload throughput, median/tail latency, CPU, memory, startup and power with identical topology, firmware, configuration and mitigations; repeated measurements and confidence intervals; no aggregate hides a regression, no arbitrary regression allowance, no unsafe benchmark-only mode. A missing or inconclusive result blocks that claim.
7. **Maintenance closure:** reproducible Rust build and dependency provenance, test manifest ownership, reset/recovery instructions, regression artifacts, supported configuration matrix and known limitations kept current through upstream changes. All blocker rows remain visible until genuinely closed.

The broader qualification suite must contain independently selectable cases, with input artifacts and expected outputs, rather than one unstructured "hardware smoke" command. These are future kernel/hardware qualification cases, not features of the bounded smoke runner delivered now:

| Case group | Concrete future execution and oracle | Safety/recovery |
| --- | --- | --- |
| M1 serial/boot | Rust lab controller powers the named machine, selects the candidate boot entry, captures serial from reset, asserts boot identity/memory-map/interrupt selfcheck records, and verifies recovery boot after an intentional early failure. Repeat on pinned Linux for platform metadata. | Independent power/console path; candidate cannot overwrite known-good entry; timeout is failure, not pass. |
| M2 device/DMA | Enumerate PCI/firmware topology; run per-device DMA copy/guard-page and interrupt-affinity tests; inject invalid IOVA; bind/unbind during transfers; compare error/IRQ/DMA logs with reference. | Isolated IOMMU domains and sacrificial devices; no arbitrary DMA into host RAM. |
| M4 storage | Run external `fio` verification jobs on manifest-approved scratch files/volumes, block transport selftests and controlled reset/power-cut tests; verify acknowledged durable data after reboot. Exact fio jobs/configuration are versioned case inputs. | Explicit disposable-device identities, destructive opt-in and independent recovery; never root/system media. |
| M5 network | Run external `iperf3` against isolated peer, packetdrill and relevant networking selftests; capture packets and per-feature offload/MTU/link-reset results. The current workstation is the only available physical system. The user will personally select and boot any future candidate; no assistant action may install, reboot, update firmware, change system settings or run destructive host testing. Additional devices, independent console/power infrastructure and other-vendor systems are named acquisition blockers, not assumed resources. The first userspace is Arch/CachyOS userspace (not CachyOS kernel patches), with a balanced server profile. [Packaging](../packaging.md) separates an isolated storage-free M1 diagnostic trial from the later Arch-like Linux-replacement package selectable through Limine/systemd-boot. Neither may remove the working kernel or waive its own recovery prerequisites.

The **actual runnable suite delivered now** is [the bounded Rust bare-metal smoke runner](../bare-metal-suite.md):

```text
cargo run -p baremetal -- run --output <new-directory> --label <label> --expect-release <exact-osrelease> --environment <reference|qemu|bare-metal>
```

Choose exactly one environment value; it is an operator assertion, not hardware detection or proof of physical execution. The runner covers bounded memory/threads, sandbox filesystem operations, TCP/UDP/Unix loopback, process lifecycle and proc/sysfs visibility. It does not exercise raw device writes, mount/reboot/firmware operations, the table's external suites, electrical behavior, DMA faults, reset/suspend, performance qualification or full Linux parity. Running it on the current reference kernel validates only the runner and that environment; the [bootstrap](../implementation.md) lacks the Linux userspace stack needed to execute it.

The table's broader lab controller, device images and instrumented fixtures remain **not_started**. The [bare-metal plan](../bare-metal.md) owns orchestration and physical manifest policy; [verification](../verification.md) owns evidence conventions; [global definition of done](../definition-of-done.md) forbids converting a smoke pass into closure. Broader qualification runs must record kernel/reference commit, build config, compiler, test-suite commit, approved device/firmware identities, case parameters, seed, serial logs, exit/oracle results, recovery, measurements and unsupported/skipped reasons. Publish no hardware serial identifiers or secrets in ordinary reports. Required hardware or fixtures absent means **blocked/unqualified**, never a fabricated pass.
