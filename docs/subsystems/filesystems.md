# VFS and every baseline filesystem family

## Contract and evidence boundary

**Current `ws-fs` progress is only selected borrowed ELF metadata/native-admission checks**, consumed by real boot-module inspection in [the publication checkpoint](../implementation.md#publication-checkpoint). Every actual VFS/filesystem family below remains unimplemented/not started. The direct GPL source-port baseline remains Linux6.18.57 commit `2ff600d29ee478d0a8d46ef8a58afb5e038fe692`; nothing here makes a disk safe to mount. Arch/CachyOS userspace and server priority do not import downstream kernel patches or remove other filesystem scope.

Follow [storage](storage.md), [memory](memory.md), [processes](process.md), [IPC](ipc.md), [networking](networking.md), [security](security.md), [verification](../verification.md), [performance](../performance.md), [bare metal](../bare-metal.md), the standing [definition of done](../definition-of-done.md), and [packaging/recovery design](../packaging.md). The [coverage inventory](../coverage.md) routes every pinned `fs/` directory and every file; directory coverage is not semantic completion. Root `io_uring/` and filesystem code outside `fs/` remain part of their actual owners' workstreams, not gaps excused by directory names.

The accepted design is a **modular monolithic Rust kernel**. Filesystems and VFS are kernel subsystems; baseline FUSE/host protocols retain their own specified userspace roles rather than replacing native filesystems wholesale. Feature scope is fixed at upstream 6.18.57 with explicit reviewed security deltas. Every in-baseline module's functionality requires a Rust replacement; arbitrary proprietary/out-of-tree filesystem modules and later feature baselines are not silently included and need separate enumerated approval. Only unavoidable architecture-owned function-local `asm!`/`naked_asm!` with proofs is permitted; no `global_asm!` or standalone assembly escape.

The pinned [filesystem index](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/index.rst), [Kconfig](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/fs/Kconfig) and [source directory listing](https://github.com/gregkh/linux/tree/v6.18.57/fs) are the scope authority. The 77 inventoried first-level directories include implementation families and shared foundations. All are explicitly retained below. There is no separate `ext3/` implementation directory: ext3 format/behavior remains covered through the pinned ext4/JBD2 implementation where applicable. Conversely, an external test suite mentioning a filesystem absent from this pinned kernel does not automatically add it to the baseline.

Observed upstream constraints:

- [VFS](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/vfs.rst) distinguishes superblocks, inodes, dentries and open file objects. Open files keep objects alive after unlink. Dentries are not on-disk directory entries and an fd is not an inode or an open-file description.
- [Path lookup](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/path-lookup.rst) distinguishes REF-walk and RCU-walk, final-component rules, symlinks and revalidating network dentries. Textual path normalization cannot replace `namei` or enforce confinement under rename races.
- [Locking rules](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/locking.rst), [mount API](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/mount_api.rst) and [idmapping](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/idmappings.rst) are semantic constraints, not C layouts to transliterate without concurrency/credential design.
- [JBD2/ext4 journal documentation](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/ext4/journal.rst) describes commit/replay, revocations/checksums and data modes; JBD2 is big-endian while ext4 is little-endian, and both ext4 and OCFS2 use JBD2. Journal consistency does not guarantee durability of every unsynchronized application write.
- [iomap design](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/iomap/design.rst) shares extent-range iteration and buffered/direct/DAX/fiemap/seek/swapfile operations. This is a substantial shared porting bundle; filesystem allocation and crash invariants remain format-specific.

## Ordered implementation program

All steps are proposals with status `not_started`; prerequisites are gates, not calendar estimates.

The existing [ELF inspector](../../kernel/src/image/elf.rs) is not an exec loader: structural parsing deliberately differs from selected native eligibility, and neither creates mappings, validates VFS permissions, executes a program or stores a rootfs. The proposed owned-rootfs extension stopped at research, before code/scaffolding/tests. Generic extended program numbering, actual unpack/partial-effect semantics, decompression, hardlink ownership and every VFS lifecycle gate remain open.

1. **M2–M3: object and syscall foundations.** Port inode/dentry/superblock/path/file/fdtable lifetimes, references/RCU, fallible allocations, user-copy helpers, wait queues, credentials, LSM dispatch and errno/compat layouts. Integrate process exec/fork and IPC fd passing through one shared open-file-description implementation. Build ramfs/initramfs and namespace-free VFS tests, not an ad hoc path-to-byte-array API.
2. **M3–M4: path and mount semantics.** Implement reference-based name lookup with exact final-component/open/link/rename checks, mount topology and modern mount API, idmapped mounts and namespaces. Preserve all supported ABI flags and errors before exposing container workloads. Add RCU lookup once its sequence validation and lifetime prerequisites exist; REF-walk-only is a temporary correctness stage, not a performance-qualified release.
3. **M4: page-cache and a selected durable baseline filesystem.** Connect folios/readahead/writeback/error sequencing, buffer-head/extent mappings and direct I/O to [block persistence](storage.md). The initial filesystem, mount options and devices remain unresolved under [Q12](../decisions.md); ext4/JBD2 is the proposed M4 choice, not an accepted selection. The selected baseline filesystem must create/modify/link/rename/truncate, fsync and unmount, survive power interruption, and be recovered and read/written by pinned Linux on virtual and sacrificial physical storage. If ext4 is selected, port full JBD2 transaction/replay before calling ext4 writable-usable and satisfy the detailed ext4 gate below; another selection requires its own complete format-specific durability/recovery implementation and equivalent gates. A read-only crate demonstration or toy filesystem cannot satisfy M4.
4. **M4–M5: server/container facilities.** Close tmpfs/memfd/seals, proc/sysfs/devpts, overlayfs, bind/propagation/idmaps, ACL/xattr/quota, notifications, POSIX/OFD/flock/leases, poll/epoll, native AIO and the complete pinned io_uring operation/feature surface. Bring up Arch/CachyOS userspace, package operations, services and containers on the real writable baseline filesystem selected under Q12 and physical storage alongside QEMU; ext4 is proposed, not required as the initial choice.
5. **M5–M6: broader filesystems.** Port remaining XFS/Btrfs, network filesystems/servers and FUSE/virtiofs, then flash/cluster/stacked families as dependencies become available; advance any family selected under Q12 to the M4 durable baseline gate. Full ext4/JBD2 parity remains unconditionally required by baseline closure even if another filesystem is chosen first. Begin corruption/recovery and physical-media work at each family's first writable step, not after feature completion.
6. **M6–M7: closure.** Finish every baseline disk/flash/pseudo/network/stacked/legacy family and every architecture-specific endpoint, format feature, mount option, ioctl, server/client and shared foundation. Each family owns a per-feature compatibility ledger and appropriate repair/recovery tools as external test oracles. Missing hardware or peers block the affected qualification; they do not erase the family.
7. **M8: parity qualification.** Require every definition-of-done condition and test matrix below, reproducible source/provenance, all supported feature interactions and per-workload/hardware at-least-Linux performance. No geometric mean or successful smoke boot is a substitute.

## Mechanism-level design, compatibility traps and gates

### Object graph, fdtable and file operations

**Proposed design:** retain Linux's separate ownership domains: filesystem instance/superblock, inode, dentry, mount/path, open-file description and fdtable slot. An inode can have many names; an open description survives unlink and may be shared by dup/fork/SCM_RIGHTS. File offsets and status flags are shared where Linux shares them; `FD_CLOEXEC` is per-descriptor. Distinguish `O_PATH`, append, nonblocking, access mode, `O_TMPFILE`, close-on-exec, large-file, direct and sync semantics. Do not use Rust `File` from the host standard library as the kernel VFS implementation.

Port descriptor installation, close/close_range, dup variants, fd limits, fork/exec races, file-position serialization, final `fput`, async notification, error propagation, compat stat/statx/getdents/ioctl and file handles. Last-reference cleanup may need deferred process context; `Drop` cannot perform arbitrary blocking writeback from an IRQ or silently discard a fallible flush. `close` is not a universal persistence request. Share regular-file, device, pipe, socket, anon-inode, eventfd/signalfd/timerfd/pidfd/nsfs/pidfs operations via the appropriate owners; no second fdtable for IPC or networking.

**Optimization:** protected fd lookup and batched ref retirement, fallible slab/cache allocation and compact stable object identities; avoid per-read name/string allocation and unnecessary buffer copies. **Gate:** compare shared offsets, unlinked-open files, fd reuse, close-vs-poll/SCM_RIGHTS, `O_APPEND` concurrency, partial copies/signals/short I/O and exec-close races to pinned Linux under resource pressure.

### `namei`, dcache and mount topology

Port path components as bytes, not assumed UTF-8. Implement empty/absolute/relative/dirfd paths, `AT_EMPTY_PATH`, trailing slash, `.`/`..`, symlink/magic-link limits, automount and final-component create/open behavior. Handle negative dentries, aliases, parallel lookup, inode eviction, rename sequence validation, dentry revalidation and shrinkers. A negative local cache entry and an expiring network cache entry are not interchangeable.

Confinement requires race-safe `openat2` `RESOLVE_*` handling, rooted/beneath/no-magiclink/no-symlink/no-xdev and cached-only resolution, alongside capability/LSM checks. Never authorize one textual path and act on another after a rename. Preserve cross-directory rename lock order, exchange/noreplace/whiteout flags, directory cycles, mountpoint exclusion and hard-link protections. Port RCU-walk fallback/restart rules without blocking in a read-side section or using reclaimed names.

Mount work includes legacy mount/remount/umount/lazy-unmount, `fsopen`/`fsconfig`/`fsmount`/`fspick`, `open_tree`, `move_mount`, `mount_setattr`, `statmount`/`listmount` where exposed by the pinned baseline, bind/rbind, shared/slave/private/unbindable propagation, mount namespaces, pivot_root/chroot interactions, freeze/thaw and busy checks. [Pinned mount UAPI](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/include/uapi/linux/mount.h) defines actual flag/structure values; do not infer support merely because an old flag still has a numeric definition.

**Optimization:** cache hashes and component names with correct casefold/revalidation rules, parallel lookup, RCU hit path and topology snapshots where allowed. **Gate:** LTP/kselftest and adversarial lookup/mount/rename races across namespaces, openat2 escape attempts, lazy detach with open descriptions, propagation loops, resource exhaustion and memory reclaim. Compare results, errno, visible mountinfo and stable object reachability—not only path strings.

### Credentials, idmapped mounts and metadata policy

Keep userspace uid/gid, kernel kuid/kgid, filesystem ownership representation and mount idmap translations distinguishable. Translate credentials at the operation's actual mount and credential domain; preserve overflow/unmapped behavior, setgid inheritance, setuid stripping, sticky directories, umask and capability semantics. One global numeric offset is not idmapped mounts. Coordinate with LSM/user namespaces; an unprivileged namespace cannot acquire authority over host inodes by changing its view.

Port `xattr` namespace dispatch (`user`, `trusted`, `security`, `system`), size/list/create/replace and filesystem-specific handlers; POSIX access/default ACL inheritance and chmod interaction; quotas for users/groups/projects, reservations, grace periods, limits and quotactl/compat interfaces, including recovery/accounting. Include inode flags/file attributes, timestamps/time granularity and update rules, NLS and Unicode tables/casefolding. Do not normalize all filenames or invent ACL support for a format that lacks it.

**Security:** all permission paths include DAC, ACL, capabilities, LSM, mount restrictions, immutable/append and delegated/remote checks in pinned order; cache credentials/ACLs only with valid invalidation. Share [fscrypt](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/fscrypt.rst) key/policy/filename and [fs-verity](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/fsverity.rst) integrity primitives without conflating encryption, authenticated roots and ordinary checksums. Upstream explicitly notes fscrypt does not encrypt most metadata and does not guarantee authenticity against hostile offline modification.

**Optimization/gate:** typed cheap ID conversions, shared ACL caches and batched quota transactions after correctness proof; differential mapped/unmapped ownership and ACL/LSM/capability denial tests, encrypted names without keys, corrupt verity data through buffered/direct/mmap paths, quota ENOSPC/EDQUOT under concurrent writeback and crash-replayed accounting.

### Buffered/direct/mapped I/O and persistence

The [memory workstream](memory.md) owns shared folio/page-cache/reclaim machinery; filesystems own mappings and transaction hooks. Port read/write iterators, sparse/unwritten/delalloc extents, readahead, dirty throttling, partial writes, EOF/tail zeroing, truncation, hole punch, fallocate modes, FIEMAP, `SEEK_DATA`/`SEEK_HOLE`, copy_file_range, reflink/dedupe where supported, splice/sendfile, swapfiles and DAX. Mapping invalidation must serialize buffered, direct and mmap writers with truncate/punch/reflink. Direct I/O requires alignment, page pin lifetime and baseline fallback/error behavior, not bypass of permission or coherency checks. Report writeback errors through Linux-compatible per-open/error-sequence mechanisms even if the write itself earlier returned success.

Implement fsync/fdatasync/sync/syncfs, range-sync, `O_SYNC`/`O_DSYNC`, directory and parent durability, freeze/remount-readonly/unmount, and block flush/FUA propagation. Preserve each filesystem's actual contract: rename atomic visibility does not imply a crash-durable directory entry; a committed metadata journal does not imply every unsynchronized data write is safe. An error must not be converted to successful zero-filled data. ENOSPC and memory pressure can occur during writeback, transaction reservation or orphan cleanup, not only in `write`.

**Optimization:** iomap range iteration, extent batching, folio-aware readahead, bounded per-CPU caches and zero-copy transfers with proven lifetimes; keep baseline buffer-head paths for formats that need them until equivalent behavior is proven. No new shared journaling abstraction may merge incompatible JBD2, XFS log, Btrfs transaction or UBIFS replay formats. **Gate:** mmap/direct/buffered races, truncate/extend stale-data attacks, fallocate/reflink boundaries, SIGBUS/short-write behavior, writeback error visibility and crash histories over DM/MD as well as plain disks.

### Readiness, async I/O and notifications

Share wait queues and file lifetime across `select`/`pselect`/`poll`/`ppoll`, epoll level/edge/oneshot/exclusive modes, nested epoll cycle limits, readiness changes, close/fd reuse, signal masks, timeouts and cancellation. Readiness is a snapshot, not a guarantee a later operation cannot block. Port fasync/SIGIO interactions and nonblocking rules per file type.

Native Linux AIO (`io_setup`/`io_submit`/`io_getevents`/`io_pgetevents`/`io_cancel`/`io_destroy`) and io_uring are distinct ABIs, not aliases for a host async runtime. Treat [pinned io_uring UAPI](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/include/uapi/linux/io_uring.h) and pinned `io_uring/` implementation as the operation/flag enumeration authority. Build a ledger for **every** setup/register/enter feature, opcode, per-op flags, result and architecture/compat form. Port shared rings and memory ordering, SQ/CQ overflow, registration and pinned-memory accounting, personalities/restrictions, linked/hardlinked/drain requests, timeouts, cancellation, multishot/buffer selection, task-work/io-wq, SQPOLL/IOPOLL, uring-command and zero-copy/network integration where baseline exposes them. Cancellation must arbitrate with completion and retain pins until the real producer is finished; it does not imply the disk never performed a write. Never advertise feature bits/opcodes whose implementation is a stub or always-success no-op.

For every io_uring opcode, record credential/personality capture and lifetime, plus real capability/LSM/audit checks at the pinned submission, issue and retry points. A worker's current credentials do not automatically authorize the submitter's operation, and seccomp filtering of `io_uring_enter` is not per-SQE syscall filtering. Coordinate this ledger with [security](security.md) and [extension/security boundaries](extensions.md); preserve baseline rings/opcodes rather than disabling them to make safety easier. Gate cross-personality/namespace access, credential revocation, worker migration and retry-after-policy-change against the pinned implementation.

For `fs/notify`, port fsnotify hooks, inotify/fanotify/dnotify, mark lifetimes, event ordering/coalescing, rename cookies, overflow and fanotify permission-response mediation. Preserve credentials/visibility, limits and event metadata/FD ownership across namespaces, mount destruction and recursive watches. Notify only after the operation reaches the same visibility point as Linux; a notification isn't a durable commit.

**Crates/simplification:** no approved drop-in crate for these kernel ABIs. A userland io_uring library or Tokio executor consumes a kernel API; it does not implement that API. A synchronous internal first implementation is allowed only as an unqualified intermediate that preserves blocking and cancellation contracts; cannot claim asynchronous scalability or final feature parity. **Optimization/gate:** shared completion records and batching without avoidable per-event allocations; liburing regression tests, LTP async/event tests, saturation/overflow and cancel-vs-complete model tests, lost-wakeup/deadlock stress, fd reuse and untrusted shared-ring mutation.

### Locks, leases, export and distributed cache foundations

Port POSIX record locks, OFD locks, flock, blocked/deadlock handling, owner identities, close/fork semantics, leases/delegation break signals/timeouts and lock-manager interfaces. Preserve what baseline removed or rejects rather than implementing obsolete mandatory-locking behavior merely because a header flag exists. Network and cluster lock recovery is protocol state, not an in-memory mutex shared by local threads.

`fs/exportfs` supplies file-handle encoding/decoding and stale-generation checks, not only path lookup. `fs/lockd`, `nfs_common` and NFS state recovery coordinate locking. `fs/netfs` and `cachefiles` share folio, subrequest, writeback and local-cache integration; see [netfs library](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/netfs_library.rst). A local cache is not authoritative server durability. `fs/dlm` and per-filesystem cluster coordination must preserve fencing/membership and recovery; [GFS2 glock rules](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/filesystems/gfs2-glocks.rst) make distributed cache validity depend on lock states.

**Optimization/gate:** share protocol-independent request/pin/error accounting but retain filesystem-specific identity, lease and cache invalidation rules. Exercise partition/rejoin, stale handles, server reboot, revoked locks/leases, node death, malicious peers, local cache corruption and writeback failure. No clustered filesystem is qualified by mounting one node with local locking disabled.

## Per-family port decisions and gates

Every row remains `not_started`. Each names candidate/rejection, shared foundations, a **temporary** simplification boundary, security/performance work and ordered port steps with observable gates. **LP** means direct Linux source port with provenance; **no approved crate** means no complete replacement has demonstrated the kernel contract, not that no similarly named library exists. External tools are test oracles; they do not authorize C kernel code. Primitive crate choices must pass [dependency](../dependencies.md) and [licensing](../licensing.md) review, including pinned features, `no_std`, allocation context, unsafe and build-script/native closure.

## Crate evidence and adoption decisions

- [ext4-view upstream](https://github.com/nicholasbishop/ext4-view-rs) says read-only ext2/ext3/ext4, `no_std` with `alloc`, write support an explicit non-goal, and corrupt-filesystem recovery a non-goal. Useful parser/test ideas do not supply writable ext4, JBD2 commit/recovery or Linux VFS semantics. No adoption is approved.
- [rust-fatfs upstream](https://github.com/rafalh/rust-fatfs) advertises FAT12/16/32 read/write, LFN, formatting and basic `no_std`. Evaluate its exact code/license/feature graph and failure behavior; Linux mount options, NLS, permissions, cache/writeback, concurrency and crash semantics still require explicit ports. Its ordinary `Read`/`Write` abstraction alone cannot model all block flush/FUA obligations.
- [ntfs Rust API](https://docs.rs/ntfs/latest/ntfs/) exposes `no_std` reader/index/attribute APIs. The reviewed evidence does not establish a writable Linux ntfs3 substitute, log replay or filesystem recovery. Treat as decoding/oracle candidate unless demonstrated otherwise.
- [fuser upstream](https://github.com/cberner/fuser) explicitly implements the **userspace** library between a daemon and a separately supplied kernel driver. It is an external/harness candidate, not the kernel FUSE implementation; any project-owned harness use must disable native libfuse integration and review all dependencies. Existing non-Rust external daemons are permitted test peers, not kernel runtime shims.
- [littlefs2 API](https://docs.rs/littlefs2/latest/littlefs2/) explicitly wraps `littlefs2-sys`, describes a C backend and its `strcpy` dependency. Reject it from the Rust-only runtime. Even a wholly Rust implementation of another format would not replace JFFS2, UBIFS, F2FS or baseline disk formats.
- No other family receives a guessed crate recommendation. Evaluate verified primitive candidates centrally through [dependencies](../dependencies.md); for complete Linux fidelity, direct pinned-source ports are the planned default. Before accepting any parser, prove endian/alignment, hostile-input bounds, fallible/context-aware allocation, no hidden native code/build scripts, license compatibility, maintenance and exact missing semantics. `no_std` does not imply kernel-safe or crash-safe.

## Proposed ext4 M4 durability implementation gate in detail

Ext4/JBD2 is the proposed M4 choice pending Q12, not an approved initial filesystem. The following ordered work is mandatory before “usable ext4” can be claimed and gates M4 if ext4 is selected. If another baseline filesystem is selected first, M4 still requires its real writable crash-recoverable implementation and equivalent VFS, application, Linux-interoperability, virtual/physical-media and fault-test gates; the ext4 work below remains required for unconditional full-baseline ext4 parity. Every item remains `not_started`.

1. Extract feature/mount/ioctl/format matrix from pinned ext4/JBD2 source and e2fsprogs; retain compat/ro-compat/incompat rules, block/cluster/inode sizes, UUID/checksum seeds, 64-bit/endian handling, external journals, extents/indirect maps, directory indexing/casefold, inline data, encryption/verity, quotas and all remaining enabled combinations. Early supported subsets are named and unsupported combinations rejected before mutation, not misread as ordinary extents.
2. Port bounded metadata parsing and validators, then JBD2 scan/replay with sequence wrap, descriptor tags, escape/revoke semantics, checksums, incomplete commits and external-journal identity. Preserve a failing image before any replay. A read-only mount can have recovery implications: enforce baseline writable-recovery/noload policy and never silently mutate a supposedly evidence-preserved image.
3. Port transaction credits/reservations/locking, metadata access/dirtying, commit ordering and checksums, checkpointing/log-space reclamation, revoke records, abort/error propagation and freeze/unmount. Guarantee forward progress under writeback/reclaim pressure and journal ENOSPC. Model power cuts at every write/flush boundary; replay must be idempotent and bounded.
4. Connect create/mkdir/link/unlink/symlink/rename/tmpfile/truncate/extend and data allocation to transactions; include orphan lists/orphan-file handling, unwritten extent conversion, stale-data zeroing, delayed allocation and allocation rollback. Preserve atomic visibility under concurrent VFS operations; directory-entry durability is tested separately.
5. Implement ordered data mode, fsync/fdatasync, syncfs, `O_SYNC`/`O_DSYNC`, directory fsync, dirty-time/error-sequence handling and preflush/FUA dependencies through all lower mappings. Qualify physical volatile-cache and PLP devices. Complete remaining data modes, fast commit/replay, resize, discard, DAX, export, project/user/group quota and every feature before full ext4 parity; no feature's implementation status is inferred from mkfs accepting a flag.
6. Test two-way interoperability: Linux formats/writes → candidate reads/updates/replays → Linux replays/checks/reads/writes, and candidate writes → Linux checks → candidate reopens. Use e2fsck, debugfs and byte/application checks; a clean fsck alone does not prove user data or fsync obligations. No repair is allowed to erase the sole failure artifact.
7. Require bounded application WAL histories (e.g. SQLite integrity/transaction checks and PostgreSQL recovery) on exact supported configurations; acknowledged transactions survive according to the application's real sync contract. Add container/package unpack + rename + hardlink + xattr/ACL/quota workloads, not just sequential file copying.
8. Run fstests generic/ext4, LTP syscall and targeted regression/corruption/model tests on virtual disks and dedicated physical controllers/media. Compare error, durability and recovery outcomes to the pinned Linux baseline, including journal abort, flush failure, read-only transition, quota/space exhaustion and reset during commit. Only then consider correctness-qualified optimization and, if Q12 selects ext4 as the initial filesystem, M4 promotion.

## Executable smoke versus full qualification suite

The repository's actual bounded [bare-metal smoke suite](../bare-metal-suite.md) runs with:

```text
cargo run -p baremetal -- run --output <new-directory> --label <label> --expect-release <exact-osrelease> --environment <reference|qemu|bare-metal>
```

The user runs it on the already-selected/booted compatible Linux system. It exercises its own sandbox and functional facilities; it never mounts, touches raw disks, changes system settings/boot/firmware or invokes the destructive suites below. Environment is an operator assertion, not physical attestation. On the present host it validates only the runner, not candidate-kernel filesystem behavior. The bootstrap cannot run this userspace suite; filesystem workstreams remain `not_started` regardless of reference smoke results.

The following **future full qualification cases are not implemented by that smoke suite and have not been run by this planning task**. External executors are named so the future Rust orchestrator has concrete integration targets, not a fabricated test pass. Apply the storage document's destructive identity/authorization interlock before **any** TEST/SCRATCH setup. Current workstation only: no destructive device, firmware, mount, boot/install/reboot actions by agents. Other systems/media/fabric peers remain named missing prerequisites.

| Case | Executor / matrix | Observable pass and evidence |

## Exhaustive definition of done

These conditions extend the global [definition of done](../definition-of-done.md). “Every” means a versioned manifest/ledger with no unresolved baseline-applicable entries, not a declaration based on family names. All conditions must hold before future complete filesystem parity is claimed:

1. **Inventory closure:** every pinned filesystem and foundation path, including all 77 `fs/*` directories, root VFS code, root `io_uring`, pseudo-filesystem producers outside `fs/`, compat and architecture variants has Rust implementation provenance and mapped test evidence. All old callers migrate; no C runtime, fake success, ENOSYS wall, obsolete alias or unqualified external-crate assumption remains.
2. **ABI closure:** every applicable syscall, ioctl, file attribute, mount option/type, fsconfig parameter, flag, result/error, proc/sysfs/configfs/control interface, async opcode/feature, compat structure and unsupported-combination rule matches pinned Linux. All file types and credential/namespace contexts covered; no missing behavior counted as a valid feature-disabled result unless the reference configuration itself disables it.
3. **Family format closure:** every supported on-disk/on-wire version, feature, checksum/endian/layout, format size and access mode is implemented and cross-tested. Reference read-only families remain read-only; reference writable families have durable writable/recovery implementations, not readers. Fixture scarcity is a blocker, never permission to drop obscure families.
4. **Data and recovery closure:** every durability operation, journal/transaction/replay/GC/orphan path, error/abort/read-only transition, corruption boundary, space/quota limit and relevant stacked mapping has reproducible test evidence. Recovery is bounded/idempotent and preserves acknowledged obligations. Filesystem consistency, application data correctness and security are checked separately; clean fsck or successful remount alone is insufficient.
5. **Concurrency/security closure:** inode/dentry/mount/file/fd/page/pin/crypto/event/lock lifetimes and lock orders are documented and reviewed; all exposed metadata, image, daemon and network inputs are adversarially tested. DAC/ACL/LSM/capability/idmap/mount policy, keys, leases and distributed fencing match the baseline. No panic, stale data, cross-tenant leak, unbounded wait or known soundness failure remains.
6. **Physical/architecture closure:** each promised device/media/firmware/CPU/architecture and filesystem-feature combination has actual qualified evidence, including real volatile-cache/PLP, flash and zoned/persistent media where relevant, suspend/hotplug/error recovery and noncoherent DMA dependencies. QEMU is the first debug target, not a physical substitute. Additional hardware absent from the sole current workstation is an explicit qualification blocker.
7. **Test and workload closure:** FS-01 through FS-10 and each family's specific cases have archived commands/configuration/seeds/results, plus exact justified applicability/skips and baseline comparison. Arch/CachyOS services, package and container workflows and balanced server workloads run on actual candidate boots; bounded smoke alone proves neither this nor full parity. Flaky failures remain unresolved, not silently excluded.
8. **Performance closure:** every promised workload/hardware/configuration is demonstrably at least pinned Linux for throughput, latency/tails, CPU/memory, startup/recovery and power with controlled repeated measurement and confidence intervals. No weakening of checks, sync, encryption, mitigations or quotas. Avoidable allocations/copies/lock contention addressed based on measurements without substituting a narrower workload.
9. **Operational closure:** users can install/select a separate real kernel package in Limine/systemd-boot while preserving recovery, administer filesystems with existing tools, recover failed media, reproduce builds/tests and follow current provenance/license/maintenance documentation. These remain filesystem/package requirements; an early storage-free diagnostic artifact does not satisfy or waive them.

## Current limitations and unresolved prerequisites

No VFS, filesystem port, on-disk-write validation, power-cut test or filesystem performance comparison exists yet. The [bootstrap](../implementation.md) is not a storage/rootfs implementation. Crate candidates are evidence-backed research options, not adopted dependencies. Only the present workstation is available; the user personally performs any future candidate installation/selection/boot. Dedicated sacrificial physical media/controllers, remote recovery/power-switch equipment, additional vendors/architectures, raw flash, zoned/PI/pmem devices, cluster/fabric peers and legacy fixture sources remain explicit prerequisites. Their absence cannot be repaired by fabricated test passes, unconditional read-only substitutions or claiming inventory completion equals behavioral support.
