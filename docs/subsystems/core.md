# Kernel core, execution contexts, concurrency, and scheduling

## Status, scope, and evidence discipline

**Active routes:** `ws-kernel` for bootstrap, `ws-lib` for consumed bitmap/byte primitives, `ws-kernel-locking` for raw exclusion/saved-IF, and `ws-init` for selected raw CPIO framing and actual pre-CR3 boot-module inspection. The [publication checkpoint](../implementation.md#publication-checkpoint) records current consumers and the latest wrap-up boundary. No rootfs/init/process/scheduler/RCU/SMP completion follows; other independently owned facilities remain `not_started` and all M1–M8 gates stay open.

Accepted architecture: a **modular monolithic Rust kernel** with a fixed 6.18.57 feature baseline and explicitly reviewed security deltas; later feature-baseline changes require a separate decision. Only unavoidable function-local `asm!`/`naked_asm!` is permitted, with operation/register/memory/clobber/privilege proofs, reviewers and disassembly checks; `global_asm!` and standalone assembly are not escape routes. Every in-baseline module's functionality needs a Rust replacement. Arbitrary proprietary/out-of-tree modules are not implicitly added to scope.

This document owns `init/`, common `kernel/` and `lib/` machinery, IRQ/deferred execution, clocks/timers, CPU lifecycle, schedulers, and synchronization. The path inventory is routing evidence, not semantic completeness: every configuration-dependent mechanism and user interface still needs a behavioral ledger. [Architecture](../architecture.md), [architecture ports](architectures.md), [firmware](firmware.md), [memory](memory.md), [processes](process.md), [security](security.md), [observability](observability.md), and [extensions](extensions.md) own their respective consumers. No C runtime, legacy C module loader, standalone assembly implementation, `std`, Tokio, or generic `spin::Mutex` becomes a kernel solution.

The full completion gates below remain **open**, with bounded early execution evidence identified separately rather than treating all gates as unrun or all as passed. Apply [verification](../verification.md), [performance](../performance.md), and [bare-metal qualification](../bare-metal.md): pinned reference and candidate must use comparable workload/configuration, topology, firmware, mitigations, toolchain settings, storage, and power policy. Report repeated distributions and confidence intervals for throughput, latency/tails, CPU, memory, startup, and energy; each relevant workload/hardware cell must demonstrate at-least-baseline performance, not merely an aggregate mean. Unknown/non-inferior-unproved results and missing physical hardware remain blockers. Performance never excuses weaker ordering, disabled security, or discarded legacy behavior.

### Current routed bootstrap and evidence

`ws-kernel` routes to [bootstrap sequencing and terminal failure](../../kernel/src/main.rs), [allocation-free diagnostic output](../../kernel/src/console.rs) and the [scalar Rust memory provider](../../rt/src/lib.rs). One BSP establishes trusted entry, checked handoff, frame/table ownership and exception state before the real PIT/PIC experiment. The IRQ handler updates bounded atomic state without allocation, logging, a scheduler or deferred work; this does not implement Linux's scheduler-dependent initialization graph or timer API.

[Frozen cell9 evidence](../implementation.md#observed-execution-and-retained-failures) retains eight 30-second-bounded QEMU cases: positive exit33; panic, unexpected vector6, production bad-map rejection, unarmed breakpoint, unknown external interrupt, missing PAT and genuinely unmasked timer each exit35 without success. The positive case observes two actual PIT wraps with PIC masking and IRQ delta0; the unmasked mutation records delta1 and fails the same assertion. Both final artifact profiles have retained symbol/layout/disassembly evidence. The `freestanding` diagnostic uses a bounded 32bpp framebuffer and safe halt, with no COM1/f4 path or automatic reboot; QEMU self-test ports are feature-isolated.

These results and the [five host parser tests/strict owned Clippy](../implementation.md#final-owned-strict-lint-gate) are not Linux printk, clocks, watchdog, crash, synchronization, RCU, scheduling, SMP/RT or process functionality. Initial choices are engineering decisions, not extra user approvals. Independent review, physical console/recovery, calibrated reference timing and all remaining mechanism gates stay open; the [isolated M1 trial](../packaging.md) is not a rootfs/userspace package or authorization to operate the workstation.

Current module inspection decodes the harness-generated initramfs (one module per case, plus a true zero-byte module in `empty-module` and a gzip-magic corrupt module that is skipped with a warning in `bad-module`; formerly two hash-bound external reference archives), ends every payload/name/ELF borrow before owned CR3 and verifies all retained payload pages lack a direct-map alias afterward. Physical reservations remain held; no fake `free_initrd_mem`, decompression, VFS unpack or PID1 execution exists. Future owned per-inode/data/name unpack and object allocation were research only when the user stopped expansion. Shared [byte decoding](../../kernel/src/image/bytes.rs) also serves actual ACPI parsing; there is no second endian/range convention.


## 1. Boot, init ordering, shutdown, and recovery — M1, then M3–M7

**Baseline.** [`start_kernel` and `rest_init`](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/init/main.c) establish architecture/per-CPU state and memory before the scheduler; the scheduler exists before timer interrupts; early workqueue registration precedes worker execution; RCU, IRQ, timers, timekeeping, entropy, credentials, namespaces and caches have distinct initialization points. Early IRQ-disabled state is intentional. This is not equivalent to calling a Rust global constructor for every subsystem.

**Ordered implementation.** (1) With architecture/firmware owners, specify actual image/entry protocols, relocation, physical address reservations, initial stack and exception tables, boot CPU identity, early page tables, command line, initrd and firmware memory map. Support a Rust-produced Linux-compatible boot image/hand-off rather than quietly replacing Linux's boot protocol with a QEMU-only loader. (2) Build an allocation-free serial/panic path and explicit early-boot context; validate reserved ranges before any allocator consumes RAM. (3) Port the pinned initialization dependency graph, splitting registration from activation. Typed boot-phase handles prove availability; linker sections may describe registrations, but no invisible allocation or arbitrary constructor order. Parse early parameters, normal parameters, `--` init arguments and bootconfig with baseline length/quoting/error behavior. (4) Initialize raw synchronization, MM, scheduler idle task, per-CPU state, exception/IRQ entry, clocks, RCU and deferred-work registrations before enabling device IRQs. (5) Start kernel workers and PID 1 with the exact initramfs/root-mount and `init=`/`rdinit=` fallback semantics, initcall levels, deferred probes, asynchronous init synchronization, init memory reclamation and read-only-after-init transition. (6) Port reboot/poweroff/halt, panic policy, watchdog interactions, crash/kdump/kexec coordination, suspend/hibernate/freezer entry and recovery with the respective owners; old BIOS/platform paths remain scheduled, not removed.

**Reuse/bundling/simplification.** Consider audited `x86_64` instruction/descriptor helpers and firmware parsers from [dependencies](../dependencies.md); no bootloader crate proves the Linux boot ABI. Existing Linux Rust wrappers are design/source candidates only when all backing operations are Rust. Share a registration/dependency graph with drivers and filesystem initialization. Start with one explicit debug configuration and synchronous init execution to localize failures; do not claim full parity until asynchronous/deferred behavior, boot parameters and every supported architecture's legacy entry path are covered. Retain one authoritative hand-off representation, not parallel boot-specific allocators with inconsistent reservations.

**Invariants and improvements.** Init-only memory cannot be freed while a registered callback, work item, exception fixup or secondary CPU entry still references it. Firmware tables, initrd and command line are untrusted bounded inputs. Never run entropy-dependent secrets before the real RNG is ready or treat a predictable early value as secure. Measure boot critical path, init allocation count, resident init memory and root-to-first-service time; remove redundant copies/registrations only after tracing dependency and lifetime equivalence.

**Definition of done.** Repeated cold/warm QEMU boots and genuine Intel/AMD physical serial boots reach a real PID 1 and service, record boot parameters/init ordering, survive missing/corrupt initrd, invalid root, init exec failure, allocation failures at every fallible boot stage, secondary-CPU failure and panic/reboot. Firmware and crash paths are qualified on their actual platforms. Recovery uses remote power/console and known-good boot media, never destructive testing of the host disk. Boot memory accounting balances before/after init reclamation; no callable pointer targets reclaimed init sections. Compare boot latency, startup energy and steady footprint to the pinned reference with identical mitigations.

## 2. Common primitives and wait/wakeup machinery — M1–M3

**Baseline and boundaries.** Linux's [core API index](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/index.rst) and [workqueue design](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/workqueue.rst) expose shared mechanisms rather than one executor per driver. Port behavior from `lib/`, `include/linux/`, wait/completion code and each consumer; internal C layout is not an external ABI requirement.

**First consumed native-word bitmap contract**

The post-integrated-004 source revision ports the `FIND_NEXT_BIT` / `_find_next_zero_bit` algorithm from pinned [lib/find_bit.c](https://raw.githubusercontent.com/gregkh/linux/2ff600d29ee478d0a8d46ef8a58afb5e038fe692/lib/find_bit.c), blob `d4b5a29e3e7283ae415671d22a0f71720929f20a`, into [the shared borrowed native-word bitmap](../../kernel/src/bitmap.rs) consumed by the existing physical allocator. [include/linux/find.h](https://raw.githubusercontent.com/gregkh/linux/2ff600d29ee478d0a8d46ef8a58afb5e038fe692/include/linux/find.h), blob `9d720ad92bc15d25ac2abd0f0353310dc73cc2c7`, defines the size sentinel and offset semantics; [lib/bitmap.c](https://raw.githubusercontent.com/gregkh/linux/2ff600d29ee478d0a8d46ef8a58afb5e038fe692/lib/bitmap.c), blob `b97692854966e0073e32dfd4589b42ae3359c9cb`, explains unused tail bits. The translated500-bit test fixture comes from `lib/test_bitmap.c`, blob `c83829ef557f58029f5693035076e97aa2314018`. Those headers and all other bitmap operations remain broader unfinished scope, not whole-file translations. Existing project bit mutation is consolidated rather than keeping a second byte-bitmap backend. [Revision evidence](../implementation.md#consumed-native-word-bitmap-revision) separates new source review/checks from immutable earlier results.

1. **Reuse a crate?** Use `core` native integers, slices and trailing-zero operations without allocation or a new dependency. Pinned `rust/kernel/bitmap.rs` explicitly wraps C bindings and assumes concurrent atomic access in its shared raw view, so it is not admitted as a Rust-only backend. The algorithm's original GPL-2.0-or-later grant and all notices remain alongside GPL-2.0-only new wrapper/integration material; no counsel or distribution clearance is invented.
2. **Bundle functionality?** One checked borrowed bitmap owns logical length, native-word search and replace/previous-value semantics. The real frame allocator uses it for metadata reservation, allocation and release; paging still consumes that same allocator. No second free-frame inventory, global heap or per-subsystem allocator is introduced.
3. **Simplify?** Private storage changes from bytes to native words; physical-frame indexing, zero-before-reference, alignment/error/accounting and ownership remain intact. Search wraps using two bounded ranges rather than per-bit modular arithmetic. This is not buddy/NUMA/atomic bitmap completion, and native word layout is not a serialized little-endian ABI.
4. **Secure?** Validate storage capacity without overflowing ceiling arithmetic; out-of-range replacement does not mutate, offsets at/beyond logical size return the size sentinel, and unused clear tail bits never become frames. Metadata is page-reserved and aligned, with raw initialization of every complete word before the first typed reference. Only the BSP's exclusive allocator borrow may mutate; IRQ/NMI/AP/firmware/DMA have no access. This does not make plain word operations atomic or supply SMP synchronization.
5. **Improve?** The pinned word search skips full words with one trailing-zero selection, avoiding per-frame modulo and new allocation/copy/locking. This is an algorithmic mechanism, not a measured Linux performance claim; matched physical/per-workload qualification remains open.

**Ordered implementation and observable acceptance:** establish the checked word view and exact source notices; migrate every byte-bitmap reservation/allocation/release caller; cover empty/short storage, maximum offset/size rejection, first/last-word boundaries, arbitrary unused tail bits, previous-value and out-of-range nonmutation against independent bit-by-bit expectations; exercise real aligned/unaligned selection, full frame exhaustion/restoration and every page-table allocation rollback in a fresh source-bound guest. Independent algorithm and unsafe consumer review, strict host/target checks, both-profile provider inspection and a fresh default visual review are required for this candidate revision. Preserve integrated-004/diagnostic-001 unchanged. Physical, 32-bit/big-endian, SMP, complete bitmap APIs and performance remain explicitly unqualified rather than inferred from the initial x86_64 cell.

| Transition | Required invariant and counterexample rejected |
| --- | --- |
| Raw metadata RAM → word view | Every complete aligned word initialized before references; a rounded-up final word cannot read beyond initialized bytes or overlap a free frame |
| Free bit → allocated frame | Only a logical, unreserved bit with valid physical alignment is claimed once; a zero in unused tail storage cannot become a fabricated frame |
| Frame/reservation → free bit | Address/index and metadata exclusion hold, old bit was claimed, accounting changes once, token consumed; foreign/double/metadata release cannot create free RAM |
| Rejected search/allocation | Empty/exhausted/alignment-filtered searches terminate at the logical bound and retain ownership/accounting; wrap does not skip a lower-index free frame or overflow an index |


**Ordered implementation.** (1) Establish errno, checked size/range arithmetic, endian/unaligned reads, bit operations, cpumasks/nodemasks, intrusive pinned lists, red-black/interval trees, bitmap allocators, reference-counted IDs and generation-safe handles. (2) Implement XArray/radix and IDR/IDA semantics, maple-like range indexing and iterators needed by MM/VFS; define allocation failure and transactional insert/split before optimizing. (3) Implement task-state publication, waitqueue enqueue-before-condition-recheck, exclusive/nonexclusive wakeups, autoremove, interruptible/killable/uninterruptible/freezable waits and timeouts. Pair scheduler state transitions with explicit barriers; a condition change may race enqueue, timeout, signal, CPU migration and exit. (4) Add completions, counting semaphores, polling callbacks, task work and blocking/atomic/raw/SRCU notifier chains with exact context, priority and unregister synchronization. (5) Port bit waits, per-CPU counters, percpu_ref switching, static keys/calls and specialized common helpers as their users arrive; notifications and static patching require architecture synchronization and lifetime protection.

**Reuse/bundling/simplification.** `core` arithmetic/atomics and bounded no-heap collection candidates may be reused after layout/context audit. Reject generic hash maps with infallible resizing, randomized seeds unavailable at early boot, or hidden locks; reject user-space event channels as waitqueues. Reuse one common wait state machine for futex, poll, IPC, locks, reclaim and drivers, while retaining distinct ABI policies. A locked, fallible tree is a valid bring-up alternative to a lockless internal index only while concurrency/performance gates are explicitly unmet; a single global lock is not the final scalable implementation. Do not replace all waits by busy polling or all completion counters by booleans.

**Invariants and improvements.** Pin intrusive nodes before publication; membership, ownership and callback removal must be explicit. A wakeup must not access a node after the waiter has detached and freed it. No synchronous notifier unregister from within its own protected callback unless the baseline contract permits it. Define callback recursion and lock ordering. Improve cache-locality, bulk ID allocation and wake batching without losing exclusive-wait ordering or poll wake masks; measure false wakeups, allocations, cache misses and wake-to-run tails.

**Definition of done.** Differential Rust-side operation traces match baseline externally visible errno/order/count behavior under randomized insert/delete/iteration and failure injection. Wait-vs-wake, timeout-vs-signal, poll unregister-vs-notify and worker cancellation tests have no lost/double wake or UAF; model small interleavings and stress millions of concurrent transitions on physical SMP as well as QEMU. Scaling tests include sparse ID spaces, wrap/reuse, oversized CPU counts, memory pressure and OOM. Existing upstream tests may be external non-Rust programs; project-owned executable test orchestration remains Rust.

## 3. Atomics, LKMM, locking, sequence counters, and refcounts — M1–M8

The current [consumed IRQ-save revision](../implementation.md#raw-irq-save-exclusion-revision) implements one native raw ownership bit, CPU-local saved-state nesting and actual PIC/PIT consumers. Integrated-006 actually exercised its positive/out-of-order/early-restore mutation contracts; its separate later-discovered error-code entry ABI defect remains subject to the [current physical hold](../diagnostic-handoff.md). Director's safe out-of-order-drop finding is corrected by packed root-IF/depth ownership, not a LIFO promise or `!Send` alone. NMI/fault paths never enter this nesting/locking domain. The still-global BSP word, descriptors/stacks/fault state, allocator/page-table ownership and IRQ/TLB lifecycle must migrate before AP concurrency.

For this narrow consumer, the five design choices are: (1) reuse native `core` atomics, not a new crate or opaque fallback; (2) share one saved-state wrapper and one controller-lock domain across programming/latch/mask paths, while EOI and emergency output remain nonblocking; (3) use original TTAS rather than mislabel a partial qspinlock/RT port; (4) enforce unique raw ownership, arbitrary-order nesting, checked count transitions and complete port transactions, with compiler and CPU ordering stated separately; (5) avoid repeated locked RMW while another owner holds the raw lock, without claiming measured fairness, bounded latency or baseline performance. These choices do not discharge the broader section's Linux/LKMM/RT/hotplug requirements.

**Baseline.** [Lock categories](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/locking/locktypes.rst), [LKMM ordering](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/tools/memory-model/Documentation/ordering.txt), and [refcount ordering](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/refcount-vs-atomic.rst) are separate contracts. Disabling local interrupts is not SMP exclusion. `raw_spinlock_t` remains raw under RT; ordinary spin/local locks change semantics. Atomic operation names do not imply identical ordering: conditional RMW failure, non-returning operations and get-unless-zero need deliberate analysis.

**Ordered implementation.** (1) For each architecture define atomic widths/alignment, IRQ save/restore, preemption/migration nesting, compiler barriers, CPU barriers, dependency rules, device/DMA barriers and instruction patching primitives. Map each ported LKMM use to a legal Rust access discipline and target instruction sequence; never mechanically translate `READ_ONCE` to `read_volatile`. Rust's prohibition of data races still applies to supposedly benign races and sequence-counter snapshots. (2) Implement raw IRQ-safe short critical sections plus CPU-local guards that cannot migrate or be sent to another task. Store and restore the *previous* IRQ state, including nested use. NMI does not take a lock held by the interrupted context; use proven NMI-safe per-CPU structures or defer via irq_work. (3) Add owner-tracked sleeping mutexes, rwsems, completions, ww-mutex deadlock backoff and PI rtmutexes. Distinguish unlock ownership, cancellation and non-owner read-release variants. (4) Add ordinary spin/rw/local locks with configuration-correct PREEMPT_RT behavior, queued lock implementations and lockdep classes/subclasses/IRQ-context tracking. (5) Build sequence-count/latch structures using atomic or otherwise language-valid shared fields and writer exclusion; retrying a racy ordinary Rust read is not sound. Add reader handoff/PI behavior for RT, bounded NMI readers and retry fallbacks. (6) Implement saturating hardened refcounts, increment-unless-zero/acquire variants, release decrement and acquire-before-final-free; separate reference existence from object publication and RCU reuse.

**Reuse/bundling/simplification.** Use Rust atomics where the target guarantees the required behavior; target-specific kernel primitives cover missing widths and Linux ordering differences. `portable-atomic` is a candidate only with a reviewed target backend: an opaque fallback critical section or lock may recurse in NMI or deadlock. Reject generic `spin`, `parking_lot`, `std::sync`, Tokio locks and ordinary `Arc` as a complete answer to kernel lock context, saturation, allocation or deferred-drop semantics. Share primitive proof obligations with MM, scheduler, drivers and [unsafe review](../skills.md). Initially stronger ordering may simplify a proof but is tracked as an optimization item; it cannot hide an unsupported atomic or be assumed to establish DMA ordering. Plain raw locks remain limited to bounded core regions; do not convert every lock to raw to avoid implementing RT.

**Invariants and improvements.** No sleep, faulting usercopy, reclaim-capable allocation or fallible hidden drop under a raw/IRQ/NMI guard. Destructor behavior is part of the locking contract. No exposed `&mut` aliases while hardware/concurrent readers own memory; shared mutable fields use appropriate `UnsafeCell` encapsulation plus synchronization. PI chains handle nested donation, cancellation, owner exit, deadlock detection and changes to donor policy. Preserve counter saturation rather than wrapping into premature free. Reduce fence strength or contention only with a written happens-before/litmus argument and disassembly review; measure contended/uncontended lock latency, IRQ-off maximum, cacheline traffic and RT inversion duration, not just throughput.

**Definition of done.** Run LKMM/herd litmus equivalents for publication, wakeups, RCU, refcounts, double-locking and MM teardown; compare Rust compiler semantics as well as hardware outcomes. Host Loom/Miri-style models may aid Rust ownership/interleavings but do not model the complete kernel, LKMM, IRQ, DMA or hardware. Port locktorture/refscale/atomic selftests to Rust-owned kernel tests or run eligible external cases; inject preemption/IRQ/NMI at lock boundaries, saturation and final-drop races. Physical weak-memory architectures are mandatory before their qualification; x86 QEMU success cannot qualify ARM/Power/RISC-V. Lockdep-equivalent detection and measured RT inversion/IRQ-off bounds pass with baseline security/debug settings documented.

## 4. RCU, SRCU, tasks RCU, and deferred destruction — M2–M8

**Baseline.** [RCU overview and APIs](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/RCU/whatisRCU.rst) separate removal from reclamation. A grace period covers pre-existing readers; a reference may need promotion to a counted reference before a read-side guard ends. Preemptible readers and sleepable SRCU are not interchangeable flavors.

**Ordered implementation.** (1) Define publication/load primitives, read guards and object reclamation protocol with the locking layer; encode guard-bounded borrows so safe code cannot retain a reference after the grace period guarantee ends. (2) Implement boot/uniprocessor correctness followed by tree-based SMP grace-period tracking, quiescent states at idle/user/context switch, preempted/blocked readers, nested IRQ/NMI entry and CPU online/offline. A context switch is not automatically quiescent for a preempted RCU reader. (3) Add callback queuing/batching, `synchronize`/expedited/barrier distinctions, polling APIs, callback offload, nohz/context tracking, stall detection and forward progress under memory pressure. (4) Implement independent SRCU domains and their sleepable readers, then tasks/tasks-trace/rude flavors required by tracing/livepatch and extensions; do not silently route all flavors through ordinary RCU. (5) Integrate shutdown, CPU unplug, module/extension unload and MM table release; `rcu_barrier` drains callbacks, unlike merely waiting for a grace period.

**Reuse/bundling/simplification.** Directly port pinned algorithm/proof ideas with notices; reject Crossbeam epoch or a user-space hazard-pointer crate as drop-in RCU because scheduling, IRQ/NMI, CPU hotplug, callback context and grace-period ordering differ. Share reclaim queues with allocator and object-specific teardown, not a single arbitrary `Drop` executor. A simple verified boot-only RCU stage is temporary and must switch before SMP/preemptible use; refusing unsupported readers is preferable to pretending a global epoch is a grace period. Every baseline flavor remains in final scope.

**Invariants and improvements.** Reader and updater memory ordering both matter; grace periods alone do not publish initialized objects. Callback nodes stay live through invocation, callbacks do not sleep unless their flavor/context permits it, and OOM cannot indefinitely starve destruction needed to make memory. Handle wraparound, repeated enqueue and offlined CPUs owning pending callbacks. Tune hierarchical aggregation, batching and offload only after proof; measure read overhead, grace-period p50/p99/max, callback backlog/retained bytes, jitter and energy on idle/isolation workloads.

**Definition of done.** Rcutorture-equivalent tests cover all implemented flavors/configurations, recursive callbacks, stalls, nohz, forced preemption, RT, idle/NMI nesting, expedited periods, OOM, suspend and hotplug failure rollback. Physical high-core-count and weak-memory tests establish no premature destruction or unbounded backlog; lockless lookup plus get-unless-zero reuse tests show no ABA/UAF. Tracing/livepatch consumers cannot claim done before their flavor and unload guarantees are exercised.

## 5. IRQ controllers, exceptions, and bottom halves — M1–M7

**Baseline.** [IRQ domains](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/irq/irq-domain.rst) distinguish hardware-local IRQs from kernel IRQ numbers, including firmware mappings and hierarchical/cascaded chips. [RT differences](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/real-time/differences.rst) require explicit threaded/nonthreaded behavior, not the assumption that every handler is hard IRQ or every RT handler can sleep.

**Ordered implementation.** (1) Implement architecture entry/return, dedicated exception/NMI stacks, interrupt priority/EOI and precise interrupted context tracking with hardware owner. Audit unavoidable Rust inline assembly for clobbers, red zone, stack alignment and privilege transitions. (2) Port descriptor allocation, chip/domain hierarchy, firmware translation, chained/shared handlers, edge/level/fasteoi flows, spurious/storm handling, masking/unmasking, wake IRQs and suspend. Include legacy PIC/IOAPIC alongside APIC/MSI/MSI-X, managed affinity, interrupt remapping and device hotplug; other architectures' controllers remain scoped. (3) Implement request/free/synchronize/disable depth semantics and teardown barriers before descriptor/vector reuse; coordinate in-flight hard and threaded handlers. (4) Implement per-CPU pending softirq vectors, bounded immediate processing and ksoftirqd fallback, BH disable nesting, tasklet serialization/kill and irq_work, including NMI producers. Deprecated tasklets are still behavioral consumers to migrate, not abandoned functionality. (5) Add forced threading and precise primary/threaded/oneshot/per-CPU/no-thread flag semantics under RT; chip operations required in hard context remain raw-safe.

**Reuse/bundling/simplification.** Audited architecture instruction and register crates are candidates, not interrupt-policy implementations. Generic embedded `critical-section` single-core assumptions and generic spin locks are explicitly rejected for SMP/NMI/RT correctness. Share descriptor lifetimes, per-CPU guards, RCU, hotplug state graph, wake queues and tracing. Begin with one controller/device pair but preserve domain/flow separation; a global IRQ number equated to an APIC vector cannot be the architecture-neutral final design. Batching bottom halves is safe only within baseline ordering/progress expectations.

**Invariants and improvements.** No unbounded allocation, sleeping lock or ordinary console lock in hard IRQ/NMI. EOI/unmask order must match controller semantics; a level IRQ must not endlessly retrigger because work was deferred before the device was quiesced. Device removal masks the source, synchronizes callbacks and DMA, then frees resources. Preserve IRQ affinity/accounting interfaces and isolation semantics. Optimize fast dispatch, cacheline ownership and budget selection; measure interrupt delivery/ack latency, storms, lost/spurious interrupts, softirq backlog, CPU consumed per packet/IO and RT wake tails.

**Definition of done.** Inject edge/level/shared IRQ storms, concurrent disable/free, affinity changes, CPU unplug, NMI nesting and suspend wake under QEMU, then physical Intel/AMD machines with real PCIe MSI-X storage/NIC, interrupt remapping and legacy controller coverage. Check `/proc/interrupts`-equivalent accounting against generated events and no post-free callback; latency under contention must meet baseline per platform. QEMU controller success does not qualify physical firmware routing or electrical wake behavior.

## 6. Workqueues, kernel threads, and cancellation — M2–M7

**Baseline.** [Concurrency-managed workqueues](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/workqueue.rst) share per-CPU/unbound pools, integrate scheduler concurrency tracking, distinguish BH workqueues, and reserve reclaim workers for forward progress. `max_active=1` on an unbound queue is not a substitute for an explicitly ordered queue.

**Ordered implementation.** (1) After task lifecycle basics, add kernel thread creation/stop/park/unpark, freezer and CPU binding with failure-aware ownership. (2) Implement queued/running/requeued/cancelled work state transitions and memory publication; repeated submission must not duplicate an intrusive node. (3) Add shared normal/high-priority pools, CPU-bound/unbound placement, affinity pods/NUMA attributes, concurrency control and ordered queues. (4) Add reclaim rescue workers before any reclaim path uses workqueues, delayed work through timers, BH queues with nonsleeping callbacks, freezable queues and CPU-intensive accounting. (5) Port cancel/flush/drain/disable semantics, callback self-requeue and worker/pool destruction with lock ordering against timers, hotplug and suspend.

**Reuse/bundling/simplification.** Reject Tokio, async-std, a thread per driver, and arbitrary `Future` executor semantics as workqueue replacements. Pure bounded queue/data-structure crates are candidates only after intrusive pinning and context audit. Share scheduler task states, waitqueues, timer lifetime, RCU and hotplug; allow specialized Rust futures only above explicitly kernel-owned scheduling contracts if a consumer needs them. A single worker is a boot stage, not a final reclaim-safe implementation. Ordered queues intentionally serialize only consumers requesting ordering.

**Invariants and improvements.** Avoid flush cycles, self-flush deadlock and rescue workers blocked on allocations that depend on the same queue. Cancel synchronizes callback completion before freeing its owner; timer cancellation alone is insufficient when timer-to-work requeue is possible. Drop cannot synchronously wait in atomic context. Measure pool count/stacks, submission-to-start tail, rescue latency, locality and idle power; improve batching and pool sharing without violating order or max concurrency.

**Definition of done.** Deterministic enqueue/run/cancel/requeue/freeze state-machine tests plus stress from IRQ and task contexts cover self-requeue, cancellation racing execution, pool creation OOM and reclaim dependency cycles. Run physical low-memory IO workloads and hotplug/suspend loops while delayed/unbound work executes. All queued items are accounted, forbidden post-destruction execution is absent, ordered queues preserve ordering and reclaim makes progress with workers exhausted.

## 7. Timers, timekeeping, accounting, and tick management — M1–M8

**Baseline.** [Clocksource/clockevent/sched_clock contracts](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/timers/timekeeping.rst) distinguish timeline, event delivery, scheduler timestamps and delays. `sched_clock` must be callable from IRQ/NMI. [RT timer differences](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/real-time/differences.rst) change default callback context and forbid spin-until-complete cancellation that can starve the callback thread.

**Ordered implementation.** (1) Bring up conservative clocksource and clockevent backends with explicit wrap mask, multiplier/shift, overflow and minimum/maximum event horizon; calibrate against independent hardware. (2) Port jiffies/timer-wheel expiry, high-resolution timer queues, absolute/relative and pinned/deferrable/hard/soft modes, slack/coalescing and callback restart/cancel/shutdown. Distinguish deleting an armed timer from terminal shutdown that prevents rearm. (3) Implement sequence-protected timekeeper reads using Rust-valid atomic snapshots, wall/monotonic/raw/boottime/TAI offsets, clock adjustment, leap-second/NTP discipline and suspend injection. (4) Integrate POSIX/CPU timers, interval timers, nanosleep/restart blocks, timerfd consumers, process accounting and time namespaces with process/IPC owners. (5) Add periodic/tickless/nohz-full operation, broadcast timers for deep idle, clocksource watchdog/failover and unstable cross-CPU counters, frequency transitions and RTC/persistent-clock restoration.

**Reuse/bundling/simplification.** Reject wall-clock/date crates as kernel timekeepers and generic async timers as lifecycle mechanisms. `core` checked/wrapping arithmetic and audited hardware register helpers may be reused; no third-party crate supplies Linux clock adjustment and cancellation semantics. Share ordered timer nodes, wait/wake, hotplug, vDSO time data and PM state. Fixed periodic tick and one reliable source simplify early debugging, not final resolution, nohz or power qualification; do not round all ABI timeouts to ticks. Keep monotonic and realtime domains distinct rather than one timestamp type.

**Invariants and improvements.** No callback UAF when cancel races rearm or CPU migration; RT cancellation uses a blocking/PI-compatible completion handshake where required. Time cannot move backwards in monotonic domains despite source wrap/failover. Realtime jumps have their specified effects on absolute waits and cancellation. Validate signed time64, old 32-bit overflow, negative intervals and far-future deadlines. Optimize counter read paths and timer locality; measure vDSO/syscall read cost, drift, timeout error, timer storm CPU, wakeups, deep-idle residency and energy without hiding late wake tails by coalescing.

**Definition of done.** Upstream timers/vDSO/timens tests and targeted overflow/leap/clock-set/restart races compare outputs, errno and clock relationships to baseline. Physical tests cover TSC stability across sockets, HPET/APIC or platform fallback, deep idle, suspend/resume, CPU frequency changes and unplug with active timers. An independent clock measures drift and wake latency; unavailable suspend/RTC hardware is an explicit blocker. A VM-only virtual clock is never evidence for physical timekeeping correctness.

## 8. SMP, topology, CPU hotplug, isolation, and power coordination — M1–M8

**Baseline.** [CPU hotplug documentation](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/cpu_hotplug.rst) distinguishes possible/present/online maps and PREPARE/STARTING/ONLINE callback contexts, ordered startup/reverse teardown and rollback. Offlining migrates tasks, IRQs and timers before architecture shutdown.

**Ordered implementation.** (1) Discover topology/CPU capabilities from firmware and architecture sources; reserve per-possible-CPU storage before publishing CPUs, including sparse IDs and maximum counts. (2) Implement secondary startup and rendezvous using Rust-generated entry code with justified inline assembly, coherent publication, per-CPU stacks and failure timeout/recovery; no fabricated online bit before all services are ready. (3) Add cross-CPU calls/IPIs, reschedule/TLB/stop-machine rendezvous, memory-ordering handshakes and nested callers. (4) Port callback state machine and rollback with constraints on fail-able stages; drain work, timers, IRQs, RCU, local allocators and runqueues before final CPU death. Race CPU unplug with task affinity/cpuset updates and in-flight cross-calls. (5) Integrate SMT/core topology, asymmetrical capacities, NUMA locality, housekeeping/isolation, CPU idle/frequency, suspend/hibernate and architecture-specific physical hot-add/remove/RAS paths.

**Reuse/bundling/simplification.** Candidate topology/CPUID parsers must be audited against vendor manuals and baseline quirks; reject treating `raw-cpuid` or a bootloader's CPU array as complete topology/hotplug support. Share cpumasks, transactional callback registration, per-CPU ownership, scheduler domains and MM TLB state. Initial UP and fixed topology are explicitly partial debug stages; do not compile away hotplug permanently or cap final scope at a machine-word CPU mask. Avoid a global rendezvous for operations that can safely target only affected CPUs once correctness is proved.

**Invariants and improvements.** No CPU executes with freed per-CPU state, unflushed translations, outstanding callback ownership or an invalid mitigation configuration. Offline CPU destinations cannot strand a synchronous caller; cancellation/retargeting has an acknowledged terminal state. Stop-machine is not a normal fast-path locking primitive. Measure boot parallelism, IPI cost, cross-socket cache traffic, offline latency, idle energy and interruption of isolated workloads; optimize topology-local targeting without breaking affinity or thermal/power controls.

**Definition of done.** Fault-inject every fail-able hotplug stage and verify complete rollback of masks/resources and callback order. Stress concurrent fork/exit, migration, mmap/unmap, IRQ affinity, RCU and timer work during repeated online/offline and suspend. Qualify genuine multi-vendor SMP, SMT, multi-socket NUMA and architecture-specific hotplug hardware alongside QEMU; physical hot-remove requires supported sacrificial lab hardware. No stranded tasks/cross-calls, leaked resources, missed TLB acknowledgements or falsely online CPUs are permitted.

## 9. Scheduler foundation and fair scheduling — M2–M8

**Baseline.** [EEVDF](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/scheduler/sched-eevdf.rst) selects eligible entities by virtual deadline and tracks lag, including deferred dequeue for sleepers; merely implementing an old textbook CFS tree does not reproduce this baseline. Exact corner cases must be ported from pinned `kernel/sched/fair.c` and shared scheduler code, not inferred solely from introductory documentation.

**Ordered implementation.** (1) Implement kernel/user register context switch, FPU/vector/debug/TLS state, task state transitions, idle/stop classes, runqueue locking, reschedule flags, preemption entry/exit and remote wakeup with migration serialization. (2) Port EEVDF vruntime/lag/deadline arithmetic, slice selection, enqueue/dequeue/reweight, fork placement, yield, sleeper/deferred dequeue and cgroup hierarchy. Validate wrap and fixed-point arithmetic rather than changing to floating point. (3) Add PELT/utilization accounting, capacity/SMT/NUMA domains, load balancing, wake placement, idle balancing, migration, energy awareness and schedutil hooks. (4) Implement scheduler UAPIs, nice weights, SCHED_NORMAL/BATCH/IDLE, affinity, utilization clamping, group shares/quota/burst, autogroup, cpusets, pressure/accounting and nohz interactions. (5) Integrate core scheduling/SMT security cookies and [sched_ext/BPF](extensions.md) without displacing baseline policies; every selectable baseline scheduling facility needs independent closure evidence.

**Reuse/bundling/simplification.** Reuse audited intrusive trees and fixed-point helpers, not a general-purpose priority queue that allocates on each enqueue. No user-space executor or scheduling crate supplies Linux runqueue, ABI or PI semantics. Share task ownership, waitqueues, clock accounting, topology, cgroups and lockdep. Round-robin-only scheduling is a bring-up dependency for tasks, not a final substitute for EEVDF. Initially conservative placement may simplify correctness, but final baseline performance includes NUMA/SMT/energy-aware configurations. Internal representation may be leaner without changing observable scheduling controls.

**Invariants and improvements.** A task cannot run on two CPUs, be lost between sleeping/runnable states, retain a stale CPU assignment after migration or have its stack freed while switched out. Ordering between task-state store and wakeup condition is explicit. Fairness is measured over adversarial sleep/yield workloads; containers cannot gain extra quota via fork/migration/reweight tricks. Tune entity layout, remote-wake batching and balancing scope based on cache/lock profiles. Required measures include scheduler CPU, context-switch and wake-to-run p50/p99/p99.9/max, fairness/share error, server/container tail latency, throughput, RSS and power.

**Definition of done.** External `perf bench sched messaging`/`perf bench sched pipe`, scheduler selftests, hackbench/schbench and real container/server workloads execute on candidate and pinned reference. Compare runtime shares, quota boundaries, affinity/errno and trace-level state invariants; do not require identical incidental interleavings. Adversarial fork/sleep/yield, affinity changes, CPU unplug, IRQ pressure and OOM never lose or double-run tasks. Physical single/multi-socket, SMT, heterogeneous and isolated-CPU cells all meet correctness and per-workload at-least-baseline performance; a good aggregate cannot mask a tail regression.

## 10. FIFO/RR, deadline, PI, and PREEMPT_RT — M2–M8

**Baseline.** [Deadline scheduling](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/scheduler/sched-deadline.rst) combines EDF with CBS bandwidth isolation, admission control and optional GRUB reclaim. The active/noncontending/inactive transitions and inactive-timer migration race are material. [RT differences](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/real-time/differences.rst) span locks, per-CPU state, allocation/deallocation, timers, IRQ work and RCU, not just a scheduler switch.

**Ordered implementation.** (1) Add SCHED_FIFO/RR priority queues, RR slice expiry, wake/preempt rules, RT push/pull migration, bandwidth throttling/group policy and capability/rlimit checks. (2) Complete PI rtmutex chains and scheduler priority donation/deboost across futex and ordinary kernel locks, including timeout/signal/owner-exit, deadlock detection, multiple donors and class changes. (3) Port deadline parameter validation, overflow-safe admission, root-domain/cpuset/affinity constraints, CBS budget/replenishment, overruns/SIGXCPU, reclaim flag behavior and GRUB active bandwidth accounting with synchronized inactive timers. (4) Integrate priority inheritance involving deadline tasks, fork/reset-on-fork behavior, hotplug admission and migration, bandwidth transfer and runtime accounting. (5) Qualify PREEMPT_RT as a full configuration: threaded IRQ and softirq execution, ordinary sleeping spin locks, raw core locks, RT-aware local locks, allocator restrictions, RCU callback threads and cancel handoffs.

**Reuse/bundling/simplification.** Direct Rust port of pinned policies is the primary path; reject generic EDF/RTIC/Embassy schedulers as Linux replacements. Share runqueues, clocks, PI graph, futex waiter objects, topology and cgroup policies; policy-specific accounting remains separate. Implement features in the order above, but do not declare RT done with only FIFO or deadline done without reclaim/admission/fork behavior. Conservative admission cannot reject requests accepted by the pinned baseline in a qualified configuration. No unbounded spin or global IRQ masking may replace a missing PI protocol.

**Invariants and improvements.** Validate runtime ≤ deadline ≤ period according to exact baseline constraints and error ordering, not just a generic formula. Prevent quota/admission oversubscription through migration or affinity changes; stop budget accounting for nonexecuting tasks correctly. Never promise a hard real-time bound from a finite stress run. Bound raw sections and interference sources with analysis plus measurement; measure cyclic wake jitter, PI inversion, deadline misses/overruns, per-class throughput, CPU and energy at matched load. Improvements must not starve fair tasks beyond baseline RT policy or bypass throttling/security.

**Definition of done.** Run external rt-tests `cyclictest` and `pi_stress` with explicitly recorded priorities, affinity, memory locking, duration, IRQ and IO load; run deadline selftests and reservation/reclaim/overload traces. Permission failures, limits, fork and policy transitions differential-match baseline. Inject donation-chain cancellation, owner death, inactive-timer migration, suspend and hotplug while tasks run. Physical machines with representative NIC/storage interrupts and firmware power states are required from M2; report maximum observed latency separately from proven bounds. Every supported preemption/RT configuration has its own completed evidence cell.

## Closure and retained scope

A mechanism is done only when its ordered implementation is Rust-backed end to end, every related pinned-source path/configuration/UAPI entry has provenance and behavior evidence, all listed normal/error/race/resource-pressure cases pass, consumer integrations are exercised, architecture-specific cases have physical qualification, and its performance cells demonstrate at-least-baseline behavior. No "not tested" cell counts as a pass. Missing CPU vendors, weak-memory targets, NMI injection, real hotplug, independent timing instruments or RT firmware isolation are named blockers, not reasons to lower scope.

Maintain a per-mechanism evidence record containing pinned reference commit/config, candidate revision/toolchain, target hardware/firmware, commands and workload versions, seed/duration, serial/trace output, failures, resource counters and statistical results. External upstream suites are allowed to contain C; they are reference programs, not a C kernel shim. Any rewritten project-owned orchestration/test executable is Rust. Root boot, core primitives, legacy configurations, uncommon scheduler policies, debug facilities and obsolete-but-present helpers remain in the [coverage ledger](../coverage.md) until behavior is implemented or its baseline-only non-runtime role is explicitly accounted for. Cross-subsystem completion requires [memory](memory.md), [process](process.md), [drivers](drivers.md), [security](security.md), [observability](observability.md), [virtualization](virtualization.md) and [extensions](extensions.md), not merely passing microbenchmarks.

## Runnable smoke, operator boot, and standing rule

The [bounded Rust smoke suite](../bare-metal-suite.md) is a separate executable deliverable, not the future kernel qualification suite:

```text
cargo run -p baremetal -- run --output <new-directory> --label <label> --expect-release <exact-osrelease> --environment <reference|qemu|bare-metal>
```

Use the exact running release and a new output directory. Its environment label is operator assertion, not proof of physical hardware. A reference-host run tests the runner only. Its bounded threads/memory, exec/wait, sandbox filesystem and loopback tests cannot close IRQ/NMI, CPU hotplug, scheduler, RT, timekeeping, OOM or performance gates above. The current bootstrap lacks the Linux userspace ABI needed to run this suite; its early cell9 QEMU cases remain separate evidence.

Only the current workstation is presently available. First userspace is Arch/CachyOS userspace, not downstream kernel patches, with the approved balanced-server performance profile. Multi-vendor, NUMA, weak-memory, physical hotplug and independent timing instruments remain named qualification blockers until real hardware/evidence is available; they are not assumed assets. The user personally selects/boots any diagnostic or later replacement candidate under the distinct [trial and package procedures](../packaging.md), retaining the working kernel and independent recovery. This task authorizes no install, reboot, system-setting, firmware or destructive-device operation.

Apply the [standing definition of done](../definition-of-done.md) independently to each mechanism, configuration and hardware/ABI cell: all pinned functionality implemented in Rust, lifecycle/security/race/failure/recovery behavior exercised, upstream/provenance closure, real consumer execution and at-least-baseline per-workload performance evidence. Planning completeness is never kernel completeness, and a skipped/unavailable gate cannot be marked passed.
