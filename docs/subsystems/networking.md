# Networking port program

## Status, baseline, and completion meaning

**Status: `not_started` for every implementation and qualification item below.** This is a researched port plan, not a network stack, a bootable kernel, or evidence of passing a network test. The behavioral reference is Linux **6.18.57**, commit `2ff600d29ee478d0a8d46ef8a58afb5e038fe692`. Server/container ordering at M5 does not remove legacy, wireless, management, or architecture-specific networking from M7–M8 scope.

Port the actual kernel networking implementation to Rust under the project's GPL/provenance rules. A TCP-only proxy, host Linux forwarding service, userspace TCP/IP stack, TAP bridge to the host, C kernel shim, or Linux module loaded behind a Rust wrapper is **not** implementation of this program. QEMU networking is a debug environment, not physical-NIC qualification. External Linux userspace, firmware, reference kernels, and test suites are permitted comparison tools, not secretly linked kernel implementations.

The accepted architecture is **modular monolithic Rust**. Its feature scope is fixed at the pinned upstream baseline, with explicitly reviewed security deltas tracked in [decisions](../decisions.md); later feature-baseline changes require a separate decision. Every in-baseline module's functionality needs a Rust replacement, but arbitrary proprietary/third-party out-of-tree modules are not implicitly included. Any unavoidable machine-specific operation uses only reviewed function-local `asm!`/`naked_asm!` under the architecture safety contract; no `global_asm!`, standalone assembly or C escape path is allowed. Differential/security/performance evidence must identify each approved security delta and explain expected differences without suppressing its tests.

Read with [architecture](../architecture.md), [coverage](../coverage.md), [compatibility](../compatibility.md), [verification](../verification.md), [definition of done](../definition-of-done.md), [performance](../performance.md), [bare-metal qualification](../bare-metal.md), [runnable smoke suite](../bare-metal-suite.md), [packaging](../packaging.md), and [dependencies](../dependencies.md). Directory coverage is structural only: every socket option, protocol variant, device mode, ioctl, netlink operation, and lifecycle needs its own downstream evidence record before claiming support. Initial userspace is Arch/CachyOS userspace against the unmodified upstream behavioral baseline, not downstream CachyOS kernel patches; use the approved balanced-server measurement profile.

M8 admits only configurations meeting all semantic, security, recovery, bare-metal and at-least-baseline performance gates. Earlier priorities are dependency ordering, never final omissions.

## 1. Socket facade, VFS integration, and endpoint lifetime

**Ordered port:** (1) enumerate `socket/socketpair/bind/connect/listen/accept/accept4/shutdown`, send/recv/read/write/vector/mmsg variants, sockopts, ioctls, poll, mmap, splice and asynchronous integration for every architecture/compat ABI; (2) port family/protocol registration and dispatch plus sockfs/open-file-description references; (3) port endpoint locks, wait/error queues, listen/request/accept queues, close/linger and protocol callbacks; (4) add namespace/cgroup/LSM checks in the original order; (5) migrate every protocol caller to this single facade before claiming that family implemented.

**Boundary traps:** fd numbers are not endpoint identity; `dup`, fork, SCM transfer and io_uring references extend open-file-description lifetime. Preserve `SOCK_CLOEXEC` versus shared `O_NONBLOCK`, `MSG_DONTWAIT` versus persistent flags, partial transfers, zero-length datagrams versus stream EOF, `MSG_PEEK/TRUNC/CTRUNC/WAITALL/OOB/NOSIGNAL`, address-length copy-back, pending `SO_ERROR`, `POLLERR/HUP/RDHUP/PRI` with queued data, signal/restart precedence, accept flags and interruption, failed nonblocking connect completion, protocol-specific sockopt length/errno behavior, and 32-bit cmsg/time layouts. Never normalize all errors to one Rust error enum at the ABI boundary.

**Reuse/bundle/simplify:** no existing userspace socket crate implements this layer. Reuse VFS fd transactions, uaccess/iov iterator, wait registration, accounting and security hooks; keep Rust enums/newtypes behind exact UAPI serialization. One typed registration/dispatch mechanism may replace C callback boilerplate without changing registration availability, hook ordering or lifetime. A single global socket lock is only a development comparison point, not a parity design.

**Threats and improvements:** protect fd reuse, refcount resurrection/overflow, usercopy faults under locks, recursive close, callbacks after namespace/device death and request-socket exhaustion. Move ownership rather than clone payloads; keep uncontended operations allocation-free where baseline permits, split read-mostly registry state from endpoint hot fields, and avoid per-packet trait-object allocation. Optimize dispatch only after protocol semantics are proved.

**Done gate:** differential raw-syscall matrices for every operation/type/family/flag and copy-fault position, lifecycle races under fd recycling and process exit, epoll edge/level/oneshot/exclusive integration, LSM/cgroup refusal, `/proc/net`, sock_diag and fdinfo observations. Run on QEMU and physical SMP machines; physical NIC unplug/reset while blocked in connect/accept/recv/send must finish with reference-compatible outcomes and no dangling DMA or wait registrations.

## 2. Owned packet buffers, queues, NAPI, and device data path

N3 distinguishes sharing one metadata object from cloning metadata while sharing packet storage. Proposed Rust types must preserve both cases instead of representing every packet as one copied `Vec<u8>`.

**Ordered port:** (1) implement checked packet geometry (headroom/tailroom, linear head, non-linear page fragments/frag lists, inner/outer header offsets, total/data lengths); (2) implement owned metadata plus independently refcounted fragment storage and copy-on-write/exclusive header mutation; (3) attach socket/memcg charge, destructor, route/device/namespace/security references and protocol-private control data with explicit layer handoff; (4) port queue enqueue/dequeue/clone/segment/reassemble and destructor callsites; (5) connect page-pool/DMA and NAPI receive/TX completion; (6) add scatter-gather/checksum/GSO/GRO and queue offload negotiation only after software fallbacks exist.

**Ownership invariant:** one owner for a mutable fragment range; shared payloads are immutable unless made exclusive. CPU, NIC, XDP frame and user UMEM ownership transitions need distinct states. A raw DMA pointer must not manufacture Rust-exclusive references while hardware or another clone can access it. DMA completion, logical send success and user-buffer-release notification are distinct events. Layer-private control data must not remain borrowed after another layer overwrites it.

**NAPI/lifetime traps:** budget zero allows TX completion work but not RX/XDP/page-pool APIs or completion; finishing exactly at budget needs the reference's repoll semantics. Disable waits for poll ownership, not necessarily arbitrary code after completion; no access to freed queue state after releasing ownership. Preserve threaded NAPI, IRQ masking, busy-poll IDs/settings, queue stop/wake, TX timeout/reset, BQL and netdevice teardown ordering.

**Reuse/bundle/simplify:** shared MM page and DMA primitives, a common packet cursor and a common completion owner replace duplicated unsafe pointer arithmetic. `etherparse` is a bounded parser/fixture candidate only, `heapless` only for bounded scratch. Do not replace skb fragment semantics with a linear-only buffer or refcounts with a universal weak-reference graph. Typed storage classes and explicit clone/COW transitions simplify internal reasoning without removing clones, frag lists, deferred frees or socket destructors.

**Performance/security:** reuse page pools and metadata slabs, batch completions, cache-align independently written ring indices, preserve NUMA locality, select hardware queues without global locks, eliminate unnecessary linearization/refcount updates. Bound/account retained fragments and validate all offsets/length addition before use; reject stale descriptor generations; synchronize noncoherent DMA and IOMMU unmap before reuse. Page recycling must clear metadata/security provenance, not leak previous packets.

**Done gate:** geometry/COW/clone/destructor model tests, allocation failure at each transition, ring wrap and out-of-order completion, zero-budget and disable/reset races, multi-buffer packets, memory-pressure and CPU-hotplug stress. On real NICs from multiple vendors, compare offloads on/off, SG on/off, small/jumbo MTU, DMA addressing/IOMMU, RSS/multiqueue, IRQ affinity, NUMA remote queues, link loss and surprise removal. Every hardware offload must produce wire output equivalent to its software path, including retransmission and tunneling; emulated virtio cannot certify this.

## 3. Netlink, configuration, diagnostics, and network namespaces

**Ordered port:** (1) port classic and generic netlink socket semantics, message/TLV encoding and multipart dump state; (2) implement family registration/introspection, multicast membership, policy validation/extack and compat messages; (3) port rtnetlink links/addresses/routes/rules/neighbors/nexthops and socket diagnostics; (4) add ethtool/devlink/netdev/shaper/gen_stats/psample and family-specific control APIs; (5) implement per-net initialization, rollback, exit ordering, per-net sysctls/proc counters and references held by sockets/routes/devices; (6) integrate all create/move/rename/delete/notifier paths and race dump/control operations against teardown.

**Traps:** port ID is not necessarily PID; sequence/ACK handling, successful `NLMSG_ERROR`, `NLMSG_DONE`, dump interruption, extack offsets, nested alignment, strict versus legacy validation, multicast loss/`ENOBUFS`, permissions and reply truncation are observable. N4 says `do` work executes synchronously on send even though its reply needs recv; do not convert all operations into an eventually consistent work queue. Socket netns remains the socket's namespace across task setns. Netns is not IPC/user/mount namespace; use process-owned namespace authority and correct owning-userns capability checks.

**Reuse/bundle/simplify:** one checked netlink codec and dump cursor shared by every family; `rtnetlink` only external client evidence. Generate Rust UAPI codecs from reviewed pinned descriptions where exact legacy semantics permit; retain handwritten quirks explicitly instead of forcing old families into stricter new schemas. Share internal configuration objects with proc/sysfs/ioctl views without replacing those ABIs. RCU snapshots/generation IDs may simplify readers but cannot erase baseline dump interruption or notification ordering.

**Threat/performance:** malformed attribute depth/length, integer overflow, unauthorized cross-netns lookup, notification floods and use-after-free during dumps. Use accounted output buffers, incremental dumps, read-mostly route snapshots and batched notification allocation. Do not hide object creation to make a dump fast.

**Done gate:** binary request/reply/error corpus compared to baseline for every registered command and invalid attribute class; iproute2/ethtool/devlink/socket-diagnostic workloads; concurrent dump/change/delete; netns destruction while fd references remain, namespace moves and veth peer deletion. Physical gates include persistent queue/NAPI configuration after driver reset, device rename/move if supported, per-net statistics under real ingress, SR-IOV/representor isolation and namespace churn during link/PCI reset.

## 4. Ethernet, IPv4, IPv6, routing, neighbors, ICMP, and fragments

**Ordered port:** (1) Ethernet/802 receive demux, loopback, address setup and ARP/neighbor tables; (2) IPv4/IPv6 local delivery and forwarding, FIB tables/rules, nexthops/ECMP, route cache invalidation and source selection; (3) IPv6 ND/RA/SLAAC/DAD/address lifetimes and IPv4 address/ARP policy; (4) ICMPv4/v6, PMTU/error queues, options/extension headers, fragment/reassembly state and expiration; (5) multicast IGMP/MLD/socket memberships and multicast routing, anycast/broadcast/link-local semantics; (6) advanced route actions, IPv6 segment routing/IOAM, VRF/l3mdev, policy routing and all sysctl/ioctl/netlink views.

**Retained distinctions:** IPv4 fragmentation is not TCP segmentation; IPv6 routers do not simply imitate IPv4 fragmentation. Preserve overlapping/duplicate fragment handling, reassembly keys and netns isolation, fragment timeout/resource thresholds, checksum policy and ICMP quote validation, options/routing-header rules, scope IDs, dual-stack mapped addresses/`IPV6_V6ONLY`, transparent/freebind/device-bound sockets, mark/UID/cgroup route selection, reverse-path filtering, unreachable/prohibit/blackhole behavior and error timing. RFC correctness alone does not reproduce Linux route/sockopt policy.

**Reuse/bundle/simplify:** one neighbor lifecycle, checked header cursors, prefix/nexthop objects, timer/accounting code and route-notification engine; preserve protocol-specific state machines and wire behavior. `etherparse` can supply independent packet vectors but not full extension parsing, routing or reassembly. Consolidate duplicate IPv4/v6 plumbing with typed address families, not an untyped byte string that drops scope. A common immutable FIB snapshot is acceptable only with reference-compatible route selection/invalidation/error behavior. No fixed tiny routing/neighbor cache copied from an embedded stack.

**Threat/performance:** spoofed ARP/ND/RA/ICMP, fragment memory/CPU exhaustion, hash collisions, route churn, cross-netns leakage and amplification. Preserve Linux tunable limits/security checks; add checked parsers and amortized reclaim without silently new packet drops. Candidate optimizations are per-CPU lookup caches with safe generations, compact prefix nodes, incremental checksum work, fragment page sharing and batch neighbor resolution, measured under both churn and steady-state traffic.

**Done gate:** reference packet-trace and raw-syscall comparison over local/forwarded/routed/multicast traffic, asymmetric paths, ECMP/policy/VRF changes, options/ext-header chains, malformed/reordered/overlapping fragments, PMTU black holes, DAD collisions and namespace churn. Physical IPv4/IPv6 peers and routers must exercise VLANs, jumbo MTUs, multicast, real checksum-status metadata, NIC RX truncation/errors and cable loss; capture beyond the DUT to distinguish pre-offload host representation from actual wire packets.

## 6. AF_UNIX, AF_PACKET, and AF_VSOCK

**AF_UNIX ordered integration:** complete socket facade → pathname/abstract binding and connection/datagram/seqpacket queues → IPC-owned ancillary and garbage collection → security/poll/splice/diagnostics integration. [IPC](ipc.md) is the single semantic authority, including baseline configurable urgent/OOB behavior. Shared packet ownership is a consolidation opportunity, not permission to impose IP retransmission/MTU semantics on local sockets. No existing userspace socket crate replaces it. Done requires IPC's lifecycle matrix plus network-namespace separation of abstract names; pathname visibility follows the actual VFS/mount semantics, not a blanket netns string map.

**AF_PACKET ordered port:** raw/cooked receive/transmit and protocol/device binding → membership/promiscuity/fanout/cBPF/eBPF → TPACKET versions and RX/TX mmap rings → auxdata/VLAN/checksum/timestamps, loss/statistics and qdisc-bypass semantics → teardown/reconfigure. N4's packet-mmap ownership/status barriers and ring-layout validation are UAPI, not internal implementation details. Reuse packet cursors/page ownership and core memory mappings; no host packet-capture wrapper is a kernel implementation. Typed ring states simplify unsafe boundaries but must allow all valid baseline layouts and version-specific behavior. Validate ring-size arithmetic, stale descriptors, malicious shared indices, capability/netns constraints and device disappearance. Batch ring retirement and retain clones instead of copying where legal; TPACKET mmap does not universally mean NIC-to-user zero-copy. Done requires tcpdump/libpcap interoperability, fanout/filter/rollover/fault cases, all ring versions and send/close races; physical captures verify RX hash, stripped VLAN metadata, hardware timestamps and drops under saturation.

**AF_VSOCK ordered port:** CID/port binding and sockets → transport registry/credit/shutdown/timeout rules → virtio/vhost and remaining baseline transports → seqpacket/datagram/stream support as each transport actually permits → diagnostics, zero-copy and host/guest reset/migration behavior. Reuse VFS and virtqueue/page owners with [virtualization](virtualization.md), not TCP over a host proxy. A common transport state interface may simplify callbacks without inventing capabilities or fallback. No general Rust vsock client crate supplies the kernel backend. Guard guest-controlled lengths/credits and stale connection IDs across reset; optimize SG/batching and maintain MSG_ZEROCOPY release notifications. Done requires actual host/guest and nested/transport-specific tests, asymmetric shutdown/credit starvation, CID conflicts, VM reset and physical-host DMA/IOMMU stress alongside guest traffic; VMCI/Hyper-V or other unavailable transport hardware remains a named blocker, not certified by virtio.

## 7. L2 topology, switching, virtual links, tunnels, and routing extensions

### Driver-hosted protocols and virtual devices are not a coverage loophole

Test software paths and real NIC attach/redirect/monitor/offload/reset interactions. Legacy SLIP/CSLIP, FDDI and HIPPI keep their frame/address/compression/link semantics and physical-driver requirements; shared cursors/buffers are candidates, no evaluated crate covers complete Linux behavior. ## 16. Exhaustive definition of done and executable qualification contract

“Done” is a conjunction, never “ping works” or “the directory was translated.” Every section/subfamily and every supported configuration must satisfy all of the following, with evidence paths linked from its implementation record:

1. **Inventory closure:** every pinned source/UAPI/config/test/doc path routed here has disposition; every registered family/protocol/type/option/ioctl/netlink command/attribute/algorithm/link mode has a behavioral record. Include compat32/endian/architecture layouts, disabled/unsupported combinations and driver-provided handlers. No ignored legacy rows or assumed crate coverage.
2. **Implementation closure:** actual Rust kernel code, all callers migrated, fallible allocations and unsafe contracts reviewed, no C-backed runtime, placeholder success, ENOSYS wall or hidden host service. All source provenance and per-file notices preserved.
3. **ABI/wire closure:** exact return values, errno/short-I/O/copy-fault precedence, metadata and message boundaries, wire encodings, sysctl/proc/sysfs/netlink observations and documented nondeterminism compared to pinned Linux. Every discrepancy has an approved compatibility decision, not a suppressed test.
4. **Lifecycle closure:** creation/partial failure, concurrent operation, blocking cancellation/signal/restart, fork/exec/SCM, setns/cgroup/credential changes, shutdown/last reference, device/netns/program teardown, asynchronous completions, suspend/resume, CPU/queue hotplug, timeout/reset/recovery and allocator failure are exercised. No leaked charges/pages/keys/UMEM/RCU callbacks and no DMA/use-after-free after destruction.
5. **Security closure:** malformed packet/cmsg/netlink/descriptor fuzzing, privilege and LSM denial, cross-netns/cgroup isolation, memory/CPU exhaustion, replay/spoofing/side-channel relevant review, secret zeroization and offload/software policy equivalence. Tests run with baseline-equivalent mitigations and security enabled.
6. **Conformance closure:** upstream selftests plus protocol suites, Linux peer interoperation, regression corpus, adversarial/property/model tests and long-running saturation/recovery. Keep external tests unmodified where possible; Rust-native adapters preserve their assertions. A suite name is not evidence: record actual executed cases, expected/actual output, exit status, seed, test/config revisions and unsupported/skipped reasons.
7. **Emulation and physical closure:** QEMU debug/smoke plus real applicable NICs/media/transports, multiple vendor/platform combinations, NUMA/IOMMU/noncoherent architectures where supported, required offload matrices and failure/recovery paths. Each hardware-specific row needs genuine hardware; unavailable device/peer/licensed RF space is a named blocker and that row stays unqualified.
8. **Performance closure:** at least pinned Linux on **every declared workload/hardware/configuration**, using [performance protocol](../performance.md). Measure goodput/PPS/connection rate, latency and p50/p95/p99/p99.9/max tails as appropriate, CPU cycles/interrupts/softirq, memory/retained pins, startup/connect/failover and idle/load energy. Compare matched firmware, NIC/driver settings, topology, MTU/offloads/RSS/IRQ/NUMA, security, compiler optimization and congestion policy; use repetitions, confidence intervals and noise controls. No aggregate hides a regression, no arbitrary regression allowance, and inconclusive non-inferiority is not a pass.
9. **Operational closure:** reproducible boot/test/recovery instructions, logs reachable after a hang, preserved peer/capture data, no host-production damage, maintenance ownership and upstream regression/CVE intake. Release claim names qualified configurations explicitly; everything else remains not_started/incomplete/unqualified as appropriate, never silently “supported.”

### Actual bounded smoke suite

The project-owned dependency-free Rust [bare-metal smoke suite](../bare-metal-suite.md) is the runnable setup deliverable. Its bounded TCP/UDP/Unix loopback cases exercise basic socket functionality without changing interfaces, mounting, elevating privilege, rebooting or touching raw devices:

```text
cargo run -p baremetal -- run --output <new-directory> --label <label> --expect-release <exact-osrelease> --environment <reference|qemu|bare-metal>
```

Use a new output directory and the exact release of the running kernel. The environment label is the operator's assertion, not proof of physical hardware. On the current workstation/reference kernel, results validate the runner and that environment only; they cannot prove candidate-kernel networking, physical NIC data paths, offloads, legacy families, namespace isolation or performance. The [bootstrap](../implementation.md) does not supply this Linux userspace/network stack. Broader suites below remain required future qualification. The user personally installs/selects/boots a future Linux-replacement package via Limine/systemd-boot while preserving the existing working kernel; this plan authorizes no host boot/install/reboot actions.

### Runnable external-suite entry points

The commands below are **future qualification recipes, not executed evidence**. They invoke external pinned Linux test sources; their non-Rust implementation is allowed by project policy. Run them on a dedicated isolated DUT after the actual Rust kernel boots, and run the identical cases against reference Linux. Build external tests on a separate reference build host using the matching headers/toolchain; do not import C tests into the kernel or introduce project-owned shell/Python test implementations.

Given an external checkout at the pinned commit, the [selftest Makefile](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/tools/testing/selftests/Makefile) and [installed runner](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/tools/testing/selftests/run_kselftest.sh) provide real entry points for broader future qualification. Explicitly clear default `SKIP_TARGETS` and require every requested target to build; otherwise BPF is normally skipped and partial build success can hide missing cases. These privileged external suites are not safe default smoke commands for the current workstation.

```text
make -C tools/testing/selftests TARGETS="net net/netfilter bpf" SKIP_TARGETS= FORCE_TARGETS=1 KSFT_INSTALL_PATH=/srv/linux-rs-kselftests install
/srv/linux-rs-kselftests/run_kselftest.sh -c net -c net/netfilter -c bpf
```

Use the pinned external test tree's own target list and hardware prerequisites to select additional `net/mptcp`, networking driver, wireless, CAN and transport suites; inventory every skipped target and add real Rust-native cases for uncovered protocol ABIs, rather than inventing a nonexistent upstream test filename. Packetdrill, iproute2/bridge/tc/ss, nftables/xtables regression suites, can-utils, BlueZ tools, wpa_supplicant/hostapd, OVS and distributed-filesystem workloads are external qualification inputs, not kernel dependencies. Their exact pinned versions and invocations belong in each implementation evidence record.

For **future full bare-metal qualification**, an additional lab harness must accept explicit artifact digests, disposable interface/device allowlists, isolated peer identity, recovery controls and a result directory. It must verify no tested interface carries host management, save authorized test configuration, enumerate actual offloads/queues/firmware, execute the section-specific semantic cases, capture external wire traffic, run matched performance cases, and perform explicitly authorized fault/recovery tests. This broader, privileged hardware harness is not the non-destructive smoke runner and is not implemented by describing it here. Missing networking implementations, fixtures and full-harness evidence remain blockers for full networking qualification; they do not prevent running the actual bounded smoke suite on compatible reference Linux. No serial identifiers need be collected in ordinary smoke reports.

### Required initial physical path

Only the current workstation is available now. From M1, co-develop QEMU and a user-operated recoverable physical boot on that machine, following [packaging](../packaging.md) and [bare-metal](../bare-metal.md), preserving the working kernel and independent recovery media. Do not run unattended NIC reset, boot/install/reboot, firmware or destructive actions on the workstation. Their absence never changes the standing full-parity/performance requirement.
