### First userspace program

`user/init` (package `linux-rs-init`, binary `init`) is a static, libc-free x86_64 Linux executable meant to be the kernel's first `/init` and, unchanged, a differential oracle on real Linux. Source: `user/init/src/main.rs`; crate and rejection records in [dependencies](dependencies.md#first-userspace-program-userinit-one-admitted-crate-two-rejections).

- **Output:** `init: hello from userspace` (the checked `write(1, ...)` itself), one summary line `init: argc=<n> argv0=<s> pid=<n> rsp_mod16=<n> auxv=<KEY:value,...> execfn=<s> platform=<s> envp=<a,b>` (hex values; `*` for AT_SYSINFO_EHDR, AT_RANDOM, AT_EXECFN, AT_PLATFORM; `envp` lists its entries only when pid is 1 and they are exactly `HOME=/`,`TERM=linux`, otherwise just their count, so host runs and PID-namespace pid-1 runs never print the environment), then `init: ok` and `exit_group(0)`. The NULL-write EFAULT check needs stdout to be a file, pipe or tty: `/dev/null` ignores the buffer, so the check fails there. A failing check prints `init: FAIL <check> got=<value>` and exits 1; a panic prints `init: FAIL panic`. `argv[1] == fault` prints `init: faulting on purpose` and reads address 0 (SIGSEGV); `mmap` prints `init: calling mmap` and calls `mmap` (a syscall the first kernel slice does not implement); `rseq` expects `-ENOSYS` (true only in the candidate's declared `CONFIG_RSEQ=n`; the reference kernel has `RSEQ=y`); `sse` checks the initial FCW 0x37f, MXCSR 0x1f80 and zero XMM5/XMM15, then adds 1+1 on the x87 stack and squares 3.0 with SSE2 (the only FP/SIMD instructions in the binary, written with `asm!` because the target is soft-float) and prints `init: sse ok`. Unknown arguments are ignored.
- **Checks:** initial `rsp % 16 == 0`; `argc >= 1` and `argv[argc]` is the terminator; AT_PAGESZ 4096; AT_PHDR equals `__ehdr_start + e_phoff`; AT_PHENT 56; AT_PHNUM equals `e_phnum`; AT_ENTRY equals `_start`; AT_SECURE 0; AT_RANDOM non-null with 16 readable bytes; AT_EXECFN and AT_PLATFORM readable NUL-terminated; `write(1,buf,0) == 0`; `write(1,NULL,1)` and `write(1,0x8,5)` give EFAULT; `write(0x7fffffff,..)` and `write(-1,..)` give EBADF (never-open descriptors); syscall 100000 gives ENOSYS. Only as pid 1: argv0 is `/init` and envp is exactly `HOME=/`, `TERM=linux` (`init/main.c` `argv_init`/`envp_init`; `rdinit=`/`init=`, unknown `key=value` words and unknown bare or post-`--` words change them). Its limits: a malformed initial stack faults instead of being reported, and kernel-provided pointers are read directly.
- **Build** (no host build: the bin needs `--features freestanding`, as the kernel does):
  `cargo +nightly rustc -Zbuild-std=core,compiler_builtins -Zbuild-std-features=compiler-builtins-mem -p linux-rs-init --bin init --target x86_64-unknown-none --release --locked --features freestanding --target-dir <dir> -- -Crelocation-model=static -Cstrip=debuginfo -Clink-arg=--no-pie -Clink-arg=--no-undefined`.
  Result: ET_EXEC at 0x200000, no PT_INTERP/PT_DYNAMIC, empty `nm -u`, no `rep` string instruction, and no xmm/x87 instruction outside the `sse`-mode `fpu_checks`. `x86_64-unknown-none` is soft-float, so the kernel need not enable user FPU state. `memset`/`memcpy` link from the tiny `linux-rs-runtime` crate (`rt/`, moved out of the kernel binary; both the kernel and the init depend on it, the init does not depend on `kernel`) rather than `compiler_builtins`' REP assembly. A scratch build forcing a 4 KiB copy confirmed the linker picks them, and both kernel profiles' link maps show `memcpy`/`memset` from that crate. The init ELF has no `limine` section or symbol. The crate is empty off `x86_64-unknown-none`, and its self-test is behind feature `self-test`, enabled by the kernel's `qemu-self-test`; the self-test was not run in QEMU for this change.
- **Evidence:** `target/linux-reference/init-reference-003/` (README with all commands, hashes, the exact auxv order and verbatim summary lines): the host run exits 0 with `init: ok`; the pinned 6.18.57 reference `bzImage` in QEMU TCG with a one-file newc initramfs printed `init: ok` then `Kernel panic - not syncing: Attempted to kill init! exitcode=0x00000000`; with `-- fault` it printed `init[1]: segfault at 0 ...` then `exitcode=0x0000000b`; with `vdso=0` the same as normal minus AT_SYSINFO_EHDR. `init-reference-001` (printed the host environment, carried Limine statics) and `-002` (probed fd 5) are superseded. One run per mode, TCG only; the candidate kernel's run of this program is not yet recorded.
- **Assembly proof, `_start`** (`user/init/src/main.rs`, `naked_asm!`): at process entry the kernel provides only `rsp` (-> argc; `rsp % 16 == 0` per the SysV psABI), with no return address or calling-convention registers; ordinary Rust cannot read `rsp` before a prologue and no intrinsic exists, so a naked function is the smallest boundary. It zeroes `rbp` (outermost frame), copies `rsp` to `rdi` (the argument of the `extern "C"` Rust main, so alignment is reported unmodified), aligns `rsp` down by 16 (clobbers flags) so a misaligned stack is reported by a check and not by misaligned Rust code, and `call`s `start_rust` (one return address pushed on the aligned stack, no other memory access). `start_rust` never returns (`exit_group`); `ud2` traps if it did; there is no unwinding (`panic = abort`, `extern "C"`). User mode, no privilege or interrupt requirement. The `syscall` instructions are the `syscalls` crate's (see its record). Disassembly review: `init.disasm` in the evidence directory; no independent assembly review has been done.

## Engineering decisions made for this request

These are implementation sequencing choices under the request, not additional detailed user approvals:

- Use the maintained `x86_64-unknown-none` target, ELF/System V without red zone or FP/SIMD, rather than host Linux `core`. Kernel package `kernel`, binary `linux-rs-kernel`; host workspace default members remain the existing tools.
- Use the genuine Limine base revision 5 protocol first. Installed external `BOOTX64.EFI` plus OVMF permits real loader/firmware handoff without a project C stub or a new crate. Base revision 5 guarantees exited EFI boot services, defined entry state and mapped ACPI data. The kernel verifies the revision and required responses; it never calls boot services.
- A Linux bzImage/EFI-native stub preserves direct systemd-boot and broader Linux loader compatibility, but entails additional image/real-mode/mixed-mode contracts. PVH is a genuine Linux-supported 32-bit protected-mode handoff and useful direct-QEMU alternative, but requires an initial 32-to-64-bit transition and is not a physical UEFI deployment path. Neither is silently considered implemented by using Limine. Both remain required scope, together with BIOS and remaining baseline paths.
- Use explicit BSP-only early ownership, fallible RAM allocation, owned page tables and guard stacks before enabling interrupts. No generic global allocator, sleeping/reclaim/I/O, DMA, AP activation or application-facing artificial resource limit is introduced. Reserved and loader-reclaimable ranges remain reserved until their consumers and firmware lifetimes can be discharged.
- Panic aborts with bounded emergency serial output and stops; it does not reboot. QEMU's explicitly configured debug-exit device supplies a test result, not a physical shutdown implementation.

## Five required design questions

### Loader, firmware and trusted entry

1. **Can I use a preexisting crate?** `limine`, `uefi`, `acpi` and `x86_64` were candidates; this historical cell added no third-party crate. `x86_64` 0.15.5 and `raw-cpuid` 11.6.0 were admitted later for the [CPU layer](#cpu-layer-on-audited-crates). Limine is an external bootloader/firmware dependency, not linked kernel implementation. Its protocol header is 0BSD with notices preserved in the translated layout file. Compiler `core` and actual linked runtime implementations are separately audited, not claimed absent.
2. **Can I bundle functionality together?** One boot-record boundary owns immutable loader responses and checked physical/virtual translation. It is shared by firmware parsing, physical allocation and mapping construction; none builds a second memory map or allocator. Only format-independent checked byte/range operations are shared. EFI service lifetimes and ACPI checks remain distinct.
3. **Can I simplify things?** One real UEFI/Limine x86_64 debug cell and synchronous initialization reduce bring-up variables without claiming Linux boot, physical firmware or architecture parity. Four-level paging is requested and checked rather than guessed. Unknown/invalid records fail explicitly; no table is treated as a successful unsupported service.
4. **Is this secure?** Firmware, loader responses, memory-map lengths and ACPI tables cross trust boundaries. Checked counts/arithmetic/alignment, overlap rejection, range-class checks and checksums precede interpretation. The initial loader itself is trusted to supply live mappings; a malicious privileged loader is outside protection. Runtime/ACPI/reserved/MMIO memory never becomes free RAM. No firmware calls occur after exit. Secure Boot, DMA/IOMMU confinement, CPU mitigations, entropy and physical recovery are not established by this debug cell.
5. **How can I improve this?** Preserve source records in place while reserved, avoid unnecessary copies, compare boot/memory checkpoints and later Linux-matched timing/footprint on actual hardware. A native Rust EFI stub and Linux/PVH paths expand compatibility; they are obligations, not already demonstrated improvements.

### Physical-page ownership and mappings

1. **Can I use a preexisting crate?** Generic buddy/slab/heap crates do not supply Linux zones, reclaim, accounting or early reservation semantics. Use `core` checked arithmetic and a kernel-owned early bitmap with storage sized from actual usable RAM. It is not the completed Linux allocator. No allocator crate or heap is admitted.
2. **Can I bundle functionality together?** A single allocator issues non-copyable frame owners to memory tests and page-table construction. Kernel, stack, metadata, firmware and loader ownership are kept distinct. Page tables use the same physical allocator and retain ownership until retirement; freeing a frame requires its unique token.
3. **Can I simplify things?** Initial non-sleeping BSP-only allocation can fail without retry/reclaim/reserves; actual memory bounds replace fixed-success test arenas. This sequencing does not erase Linux NUMA/zones/SLUB/reclaim/OOM/GFP/accounting requirements. No userspace allocation ABI is advertised.
4. **Is this secure?** Every allocated frame originates wholly inside a validated usable range; metadata reserves itself; page-zero, holes, image, stack, firmware and loader memory are excluded. Overflow/exhaustion/invalid alignment leave accounting unchanged. Owned page references cannot outlive release. Page tables keep writable data non-executable and kernel text non-writable, with no writable direct-map alias of image text. TLB state changes precede mapping retirement. DMA and additional CPUs remain inactive; BSP-only assumptions must be replaced before enabling either.
5. **How can I improve this?** Host property/conservation tests and real frame-content/reuse checks precede batching. Later hand off exactly once to mature Linux-compatible page allocation, retaining allocation/metadata counts. Measure latency, footprint and fragmentation against the pinned reference before optimization claims.

### Exceptions, interrupts, clocks and diagnostics

1. **Can I use a preexisting crate?** Core atomics and the supported CPUID intrinsic suffice for scalar state. Architecture crates would still require entry/interrupt/stack/unsafe review; this historical cell admitted none. The later [CPU layer](#cpu-layer-on-audited-crates) admits `x86_64`/`raw-cpuid` for descriptor formats and register access.
2. **Can I bundle functionality together?** One normalized exception-frame boundary saves/restores complete scalar state. One diagnostic path is allocation-free and bounded. Timer IRQ state uses atomics, never the allocator or serial formatting inside the handler. Distinct CPU error-code conventions and NMI/double-fault stacks remain explicit.
3. **Can I simplify things?** Use one explicitly selected legacy PC clockevent/controller pair for the first q35 cell; APIC/IOAPIC, high-resolution timekeeping, SMP, NMI nesting, suspend and all other clocks/controllers remain open. Actual hardware interrupt counts and exception return assertions, not a printed banner, gate the experiment.
4. **Is this secure?** The IDT is installed before enabling maskable interrupts. Unavoidable entry assembly proves stack alignment, register preservation, DF clearing, no unwinding and `iretq` layout. Emergency stacks isolate double fault/NMI/machine-check from normal stack failure. Expected test faults require exact vector/address/error/RIP; unexpected traps report failure and stop. IRQ handlers do not allocate, sleep or take a lock; timer progress has a host-enforced timeout.
5. **How can I improve this?** Inspect final disassembly for all entry/return sites, helpers and unexpected SIMD/CRT symbols. Add real controller/time-source calibration and physical drift/latency evidence without changing Linux semantics. A VM tick count is not monotonic-clock or performance qualification.

## First-userspace slice (kernel side)

Decision [A18](decisions.md) selects ring-3 execution of a static `/init` from the boot archives ahead of the M2/M3 scheduler and SMP gates. This section records the kernel side. **Phase 1:** every mechanism below as host-tested pure logic in the `kernel` library, the freestanding loader that builds `/init`'s address space before CR3 publication, and the shared user-copy walk exercised against the real owned tables. **Phase 2:** the ring-3 transition and `SYSCALL` entry in `cpu.rs` (Linux GDT selectors, `STAR`/`LSTAR`/`SFMASK`, a `pt_regs` frame, `iretq` return), routing of ring-3 exceptions to `exec::report`, SMEP/SMAP, the state moved into statics, `Run /init as init process`, the `CHECK userspace exec ...`/`RESULT` contract and Linux's `NO_INIT` panic, with **manual** QEMU runs of `user/init`. **Round 3** (review findings): the harness now generates the initramfs and builds `/init`, the catalog has 18 cases (see [kernel tooling](kernel-tooling.md)), a missing `/init` ends in what the pinned kernel prints through `prepare_namespace`, configuration equivalence is a behavioural table, x87/SSE work in ring 3, and the ring-3 hardening gaps the independent reviews named are closed or listed. Still missing: any scheduler, `execve`, signals, other syscalls, SMP, CPU-vulnerability mitigations and physical hardware. This is a running first userspace in one QEMU cell, not Linux compatibility or M1/M2/M3 completion.

**Declared configuration** (one table, [`kernel/src/config.rs`](../kernel/src/config.rs): every entry cites the pinned source that defines the behaviour and lists the syscalls it turns into `-ENOSYS`): boot option `norandmaps` (no stack, brk or `arch_align_stack` randomisation, so `STACK_TOP = 0x7ffffffff000` exactly), `vdso=0` (no `AT_SYSINFO_EHDR`), `noxsave` (FXSAVE-only state, so `AT_MINSIGSTKSZ` is 0x5a0; **x87 and SSE still run**, as on a `noxsave` Linux), `nofsgsbase` (`AT_HWCAP2 = 0`, asserted at start-up because it is only true while CR4.FSGSBASE is clear); `CONFIG_RSEQ=n` (no `AT_RSEQ_*` and `rseq` 334 is `-ENOSYS`, `kernel/sys_ni.c:392`), `CONFIG_X86_USER_SHADOW_STACK=n` (`map_shadow_stack` 453), `CONFIG_UPROBES=n` (`uretprobe`/`uprobe` 335/336), `CONFIG_X86_X32_ABI=n`; `CONFIG_IA32_EMULATION=y` with the boot parameter `ia32_emulation=0` (`ia32_enabled()` false, `arch/x86/include/asm/ia32.h:84`): `AT_MINSIGSTKSZ` keeps the `sigframe_ia32` sizing of the config option (0x5a0, equal to the oracle) while, exactly as Linux does for `ia32_emulation=0`, no `int $0x80` gate is installed (`#GP`, `idt.c:233-239`), `SYSENTER` MSRs are zero and compat `SYSCALL` is the `-ENOSYS` `CSTAR` stub (`common.c:2230-2252`); a Linux booted without that parameter dispatches compat syscalls, which this kernel does not. Root credentials, no secure-exec. The pinned oracle (`target/linux-reference/init-reference-004`, local evidence, the exact harness-built init ELF) ran the reference configuration (RSEQ and UPROBES on) with randomisation and vDSO on; its `vdso=0` auxv line minus the two `AT_RSEQ_*` entries is the comparison. `AT_HWCAP` is the raw `CPUID.1:EDX`: equal to Linux's `x86_capability[CPUID_1_EDX]` on the `qemu64` model, where no capability is cleared or forced; other CPUs can differ, so only `qemu64` is compared exactly. `AT_HWCAP2` is 0 only without FSGSBASE: under `-cpu max` Linux would set `HWCAP2_FSGSBASE` and enable CR4.FSGSBASE, this kernel does neither.

### Mechanisms and their five design questions

**Exec loader** (`exec::find`, `exec::plan`, `exec::args`, `userspace::load`). 1. *Preexisting crate?* `goblin`/`object`/`elf` parse ELF but not Linux's acceptance order, errnos or `elf_load` arithmetic, and none handles a cpio replace chain; the existing borrowed [`image::elf`](../kernel/src/image/elf.rs) and [`image::cpio`](../kernel/src/image/cpio.rs) decoders are reused and `syscalls` supplies `Errno`. 2. *Bundle?* One plan type serves the loader, the page-content filler and the fault printer (`Vmas`); one archive walk serves discovery and the boot inspection. 3. *Simplify?* Static `ET_EXEC` only; static PIE and `PT_INTERP`, overlapping segments, mappings that end beyond EOF (Linux `SIGBUS`) and more than 16 `PT_LOAD` are explicit unsupported errors, never reinterpreted. 4. *Secure?* The ELF and archive are untrusted: all arithmetic wraps exactly where the C does or is checked, every `TASK_SIZE_MAX` bound of `__get_unmapped_area` and `load_elf_binary` is applied before any frame is allocated, `p_vaddr`/`p_offset` mismatches fail as `vm_mmap` does, and a 20,000-case corruption loop covers header and program-table bytes. `padzero` is applied only to writable segments, as in Linux (`clear_user` on a read-only private mapping fails and is ignored), so no kernel byte is invented or hidden. 5. *Improve?* Replace the fixed 16-segment table by a VMA tree with the first `mmap`/`brk`; add static PIE with ASLR base selection; map file pages lazily from the page cache instead of copying.

**Initial stack** (`exec::stack`). 1. *Crate?* None builds a Linux auxv. 2. *Bundle?* One builder writes the whole block into a caller-owned window (the top four stack pages, one order-2 frame), so the loader needs no second copy. 3. *Simplify?* Fixed 36-page stack (4 argument pages plus Linux's 32-page `stack_expand`); no growth on fault. 4. *Secure?* Every offset is checked against the window and fails as `-E2BIG`; the pointer arrays and strings are laid out as `create_elf_tables` does, so a hostile command line cannot move `rsp` outside the mapped pages. `AT_RANDOM` is RDRAND when CPUID reports it, otherwise a `SplitMix64` expansion of the TSC, which is predictable. 5. *Improve?* A kernel entropy pool, then growth up to `RLIMIT_STACK`.

**User address space** (`paging::Tables::map_user`, `paging::UserSpace`). 1. *Crate?* The `x86_64` crate migration is a separate branch; this reuses the existing owned table writer. 2. *Bundle?* The same `map` that built the kernel tree installs user leaves, with `USER` carried on every level of a user path and refused under a supervisor-only table; frames come from the one buddy allocator. 3. *Simplify?* No huge user pages, no PCID/global entries, frames are never freed (init's death panics the kernel). 4. *Secure?* All user table writes precede `Tables::activate`, so the existing "no software write after CR3 publication" invariant stands. Leaves are NX unless the segment is executable, writable only when requested, never at or above `TASK_SIZE_MAX`; module payload pages are copied into fresh zeroed frames while the loader mapping epoch is active and no payload borrow survives `userspace::load`. 5. *Improve?* Share the module payload copy-on-write instead of copying, once a page cache exists.

**User copy** (`usercopy`, `paging::UserSpace`). 1. *Crate?* None applicable in `no_std` kernel space. 2. *Bundle?* One pair `copy_to_user`/`copy_from_user` over one `UserPages` trait; syscalls, the stack check and a future `strncpy_from_user` use it, nothing else touches a user address. 3. *Simplify?* A software page-table walk plus the direct-map alias of the frame replaces exception-table fixups. 4. *Secure?* `access_ok` is Linux's `__access_ok` runtime branch (`ptr + len` without wrap and `<= TASK_SIZE_MAX`); each page must be present and user (and writable for writes) at every level before a byte moves; short copies return the uncopied count and `copy_from_user` zero-fills the tail. The kernel never dereferences a user virtual address, so SMAP cannot trap and no `STAC`/`CLAC` window exists; the module documents where one would go if a direct-access path is ever added. TOCTOU: one task on one CPU, user code does not run during a syscall, so nothing can unmap between walk and copy; this argument MUST be replaced (atomic walk-and-copy under an address-space lock, or fault fixups) before a second task, a second CPU or `munmap`/`mprotect`. 5. *Improve?* Fault-and-fixup copies avoid the software walk on the fast path.

**Ring-3 entry, SYSCALL, exceptions and FPU** (`cpu.rs`, `userspace.rs`). 1. *Crate?* The vendored `x86_64` 0.15.5 supplies the MSR/CR/DR/segment types (`Efer::update`, `Star::write`, `LStar`, `SFMask`, `Cr0/Cr4::update`, `Dr0..Dr7`, `DS/ES/FS/GS::set_reg`), wrapped in `unsafe fn`s with contracts because the crate marks `LStar::write`/`SFMask::write` safe although they can break the CPU; `raw-cpuid` reports SYSCALL/SEP/SMEP/SMAP/UMIP/FXSR/SSE; `core::arch`'s `_fxrstor64` is the only FP instruction. No crate provides the entry or `iretq` frame. 2. *Bundle?* One kernel stack (the `BOOT_STACK` top = `TSS.RSP0`) serves SYSCALL, exceptions and IRQs from ring 3; `kernel_main`'s frame is abandoned by `enter_user` (it never returns) and all later state is in `STATE` behind a `RawSpinLock`; any ring-3 CS (`cs & 3 == 3`, so compatibility mode too) takes the user path of the existing IDT entries. 3. *Simplify?* `syscall_entry` builds a Linux `pt_regs` and always returns by `iretq` (the SYSRET fast path needs canonical-RIP and RCX/R11 checks); the user RSP scratch is one global word (no `swapgs`, no per-CPU); every ring-3 exception is fatal (no handlers exist) so exceptions do not save a full `pt_regs`; the kernel is soft-float and there is one task, so user FP state is never touched by ring 0 and needs no context switch. 4. *Secure?* `SFMASK` is Linux's `MSR_SYSCALL_MASK`; `STAR`/`LSTAR` as Linux; `CSTAR` points at a `-ENOSYS` `sysret` stub except on Intel CPUs (Linux `wrmsrq_cstar`: ignored there, a `#VE` in a TDX guest); the three `SYSENTER` MSRs are zeroed (`idt_syscall_init`), so `SYSENTER` from ring 3 cannot enter ring 0 at a stale target; INT3 and INTO gates are DPL 3 (Linux `SYSG`), every other gate DPL 0; `#DB` has its own IST stack (Linux `IST_INDEX_DB`) and DR0-3/DR7 are scrubbed at boot (`initialize_debug_regs`); the window between `SYSCALL` and the stack switch can be entered only by IST vectors (NMI, `#MC`, `#DF`, `#DB`), which never touch the user RSP (the earlier "no interrupt can intervene" comment was wrong and is fixed); NMI, `#MC`, `#DF` and any unclassified vector taken from ring 3 are kernel failures, never init deaths; CR4.SMEP/SMAP/UMIP are enabled when CPUID reports them and `CHECK userspace exec` reports SMEP/SMAP as read back (`qemu64` has none, `-cpu max` both: the `cpu-max` case requires `true true`); FS/GS selectors and bases are zeroed like `start_thread`; x87/SSE are enabled as Linux does with `noxsave` (CR4.OSFXSR|OSXMMEXCPT, CR0.EM=TS=0, MP|NE set) and init starts from Linux's initial image (FCW 0x37f, MXCSR 0x1f80, registers zero, loaded by `FXRSTOR` so no firmware residue leaks); `#MF`/`#XM` reach init as SIGFPE. An executed audit (`CHECK userspace-audit`) walks the published tree and proves no entry of the kernel half carries the user bit and no user mapping reaches `TASK_SIZE_MAX`. 5. *Improve?* Per-CPU stack and `swapgs`, the SYSRET fast path, `CLAC` at exception entry once a direct user-access path exists, compat syscalls (`IA32_EMULATION=y`), UMIP emulation, XSAVE and lazy FP context switching with the scheduler.

**Syscall slice** (`syscall`). 1. *Crate?* `syscalls = "=0.8.1"` (no default features, `x86_64`) supplies `Sysno` and `Errno`; its x86_64 table was compared with the pinned `syscall_64.tbl` and differs only by 17 numbers Linux answers with `-ENOSYS` (kept in a sorted list with a drift test). Its raw `asm!` wrappers are not referenced: the linked `qemu-self-test` ELF contains no `syscall` instruction (`objdump -d` count 0), though `Errno`'s name table is linked in through `Debug` formatting. 2. *Bundle?* One `dispatch` and one `write` path for fds 0-2 (init's `/dev/console`). 3. *Simplify?* `write`, `getpid` (always 1), `exit`, `exit_group`; a number Linux implements but this slice does not returns `Outcome::Unimplemented` and the caller prints `FAIL syscall unimplemented nr=<n>` and stops - neither fake success nor a broad `ENOSYS`. 4. *Secure?* Number and `unsigned int` arguments are truncated as in Linux; `write` follows `vfs_write` (fd `-EBADF`, `access_ok` on the unclamped count `-EFAULT`, clamp to `MAX_RW_COUNT`) and `iterate_tty_write` (2048-byte chunks; a chunk that cannot be fully copied is dropped, returning earlier chunks or `-EFAULT`). Output processing is the default termios (`OPOST|ONLCR`: `\n` becomes `\r\n`); the oracle's serial log shows exactly that. 5. *Improve?* Table-driven argument decoding once more than a handful of syscalls exist.

**Fault and death reporting** (`exec::report`). 1. *Crate?* No. 2. *Bundle?* One `Display` per Linux line; the VMA bracket is shared by the segfault and trap lines. 3. *Simplify?* The panic backtrace and the following `Code:` line are not printed; CPU/core/socket are fixed to the BSP. 4. *Secure?* The exit code is the signal number with no core flag; kernel addresses in a user fault always show the `PROT` bit (`sanitize_error_code`); a vector that is not a plain user signal (NMI, `#DF`, `#MC`, `#NM`) returns `None` so it can never be misreported as init's death. 5. *Improve?* Real signal delivery, `Code:` bytes and `wait` status.

### Shortcuts (each is also a `shortcut:` comment at its site)

Loader and ABI: only `--` words reach `argv` (no `init=`/`rdinit=`/command-line environment, and "Too many boot init vars" is a plain `FAIL`); `/init` entries with `..` components are ignored and a hard-linked `/init` is rejected; **a damaged archive is skipped whole, whereas Linux keeps the entries it unpacked before the error (so Linux may find an `/init` this kernel never sees)**; the file's owner and setuid bits are ignored; static `ET_EXEC` only, at most 16 `PT_LOAD`, no overlap, no mapping past EOF; a `#!` `/init` gives `-ENOEXEC`/`-ENOENT` as `load_script` and an explicit unsupported failure when its interpreter exists; a `PT_INTERP` is looked up in the archives: absent is `-ENOENT` as `open_exec`, present is the explicit "unsupported dynamic executable" stop; if `/init` fails to execute while one of Linux's four fallback inits (`/sbin/init`, `/etc/init`, `/bin/init`, `/bin/sh`) exists in the archives, the kernel stops with `FAIL fallback init present` instead of running it (with none present it prints Linux's lines and `NO_INIT`); with no `/init` the kernel prints what the pinned reference kernel prints through `prepare_namespace` minus the configuration-dependent filesystem list, not `NO_INIT`; fixed 36-page stack and no growth; no randomisation; `PF_X`/`PF_W` without `PF_R` read too; `AT_RANDOM` falls back to a predictable seed without RDRAND (note before any stack protector or static PIE); frames of a failed load are not returned.

Process model: **a syscall Linux implements but this slice does not stops the whole kernel (`FAIL syscall unimplemented nr=N`) - acceptable only for a single trusted init, since a user must never be able to stop the kernel; it must become the real syscall or an error returned to that task with a second process**; syscalls turned off by the declared configuration return `-ENOSYS`; no signals, so every exception is init's death; compat syscalls, `int $0x80` and `vsyscall` are absent; UMIP is enabled but, unlike Linux, `SGDT`/`SIDT`/`SMSW` are not emulated and kill init; the user RSP scratch word and the kernel stack are single-CPU (no `swapgs`/per-CPU); `AC` set by ring 3 is not cleared at exception entry (harmless while no kernel path touches user virtual addresses; add `CLAC` with the first direct access); no FP context switch (one task, soft-float kernel).

### Blind spots that block physical use

None of Linux's CPU-vulnerability mitigations exist: no KPTI/PTI (ring 3 runs with the whole kernel mapped in the same CR3, so Meltdown-class CPUs leak), no IBRS/eIBRS/STIBP/IBPB or retpolines, no RSB filling or call-depth tracking, no `VERW`/MDS/TAA/MMIO buffer clearing on return to user, no SRSO/BHI handling, no SSBD, no `swapgs` fences. Together with SMP, per-CPU data, KASLR, stack protection, NMI/`#MC` recovery, and independent architecture/security review, these gate any physical run of ring 3; the physical diagnostic authority in [diagnostic handoff](diagnostic-handoff.md) covers none of it.

## Raw IRQ-save exclusion revision

After immutable integrated-005, [sync.rs](../kernel/src/sync.rs) adds an allocation-free native atomic ownership bit and non-transferable guard. The actual [PIC/PIT consumer](../kernel/src/cpu.rs) disables local maskable interrupts before acquiring it, serializes each latch/low/high transaction, and releases raw ownership before restoring local exclusion. It is not an unused synchronization demonstration or a substitute for Linux qspinlock, RT/preemption/lockdep, CPU hotplug or weak-memory qualification. No AP is released by this revision.

| Actor / resource | Ownership, visibility and legal operations |
| --- | --- |
| BSP controller initialization | Before AP release, serialize the complete PIC/PIT programming transaction; saved-IF guard keeps the local IRQ from interrupting it. The existing one-BSP/APIC-disabled legacy policy is not SMP interrupt routing. |
| Ordinary PIT reader / masking | Same raw lock protects each shared port transaction. No allocation, scheduling, user access, fallible destruction or arbitrary callback occurs in normal critical sections. |
| Timer IRQ | Acknowledge PIC EOI without a blocking controller lock. During the bounded bootstrap probe only, attempt `try_lock` once and atomically report its actual result. Interrupt-gate IF remains clear. |
| NMI, fault, panic, emergency output | Never enter this nesting domain or take the blocking controller lock. Console remains an atomic-layout/atomic-cursor, raw-MMIO character sink; it permits interleaving rather than claiming atomic whole records or Linux printk. Its sole initialization is now an unsafe at-most-once, complete-resource-lifetime boundary. |
| Raw lock / compiler | Successful native CAS is Acquire, release-store unlock is Release, failed CAS and polling are Relaxed with no payload access. Field destruction orders raw unlock before IRQ exclusion release. Final restoration has a compiler-only `SeqCst` fence plus non-`nomem` STI; that compiler contract and x86 ordering are distinct from DMA/weak-CPU barriers. |
| IRQ nesting | One BSP-local packed word holds depth and the first owner's IF. Checked entry and atomic final removal preserve that original state under arbitrary guard destruction order. `!Send`/`!Sync` prevents transfer but is not the nesting proof. This word and all other BSP-only state must become genuinely per-CPU before AP release. |

### Shared ownership and context proof

**Historical initial/cell9 ownership record:** the empty-lock-DAG statement below predates the consumed raw PIC/PIT controller lock and saved-IF guard. Current [IRQ ownership](#raw-irq-save-exclusion-revision) and [publication consumers](#publication-checkpoint) supersede it; BSP-only restrictions still apply and no private SMP candidate is landed.

Only BSP executes. No AP is started, no scheduler/preemption/reclaim/heap/I/O work exists, and device DMA is not handed kernel-owned buffers. The loader/firmware remain privileged trust dependencies; this is not protection from malicious firmware/DMA. Initial usable RAM is transferred once; metadata and every issued page are initialized with raw `ptr::write_bytes` **before** the first typed slice/frame borrow, without a duplicate zeroing pass. The allocator bitmap occupies actual usable pages and reserves itself before frame issuance. A non-Copy frame token gives the only live mutable byte borrow. Release consumes it; leaks can consume pages but cannot produce a second safe owner. Tables consume tokens into an encoded root/child ownership tree. Unpublished failure cleanup frees children before the parent and never frees mapped leaf RAM; active roots are not reclaimed.

Timer IRQs touch only a relaxed atomic counter and owned PIC EOI, not allocator/formatter state. Counter operations need no payload publication. Fault/BP permits use release/acquire for their expected tuple/one-shot state. Framebuffer geometry/color fields publish before the address release store; emergency readers acquire that address. Pixel writes use outside-Rust-allocation volatile MMIO, never references to device storage. Reserved framebuffer bytes are tail padding, not assumed initialized fields. Whole physical/virtual extents are checked for overflow, canonicality, class and pixel bounds. No locks are present, so this cell's lock-order DAG is empty; enabling APs, DMA, RT or task allocation requires new shared context/ownership mechanisms, not reuse of BSP assumptions.

Firmware access is not a generic safe RAM-slice facility. `BootInfo::acpi_table_bytes` is unsafe, returns a borrow bounded by `&BootInfo`, and requires actual initialized immutable RSDP/SDT storage with no firmware/SMM/AP/DMA/software writers or reclamation for that borrow. FACS/arbitrary NVS/runtime data is forbidden by the caller contract; reserved class alone proves neither initialization nor immutability. `firmware::discover` and its root/SDT traversal explicitly carry and discharge this external trusted-firmware contract, return only scalar summaries, and let no table references escape. Main names the trusted EFI/Limine/firmware phase and starts no runtime service/AP/DMA while discovering tables. Malicious or concurrently mutating firmware is not claimed safe. The GPR runtime probes use distinct Rust-static full64-bit patterns, with nonzero varied high and low halves and full64-bit comparisons; they no longer test only zero-extended32-bit values.

`cpu.rs` was touched in exactly four places and only by visibility: `IrqSpinLock` (struct, `new`, `lock`) and `IrqSpinGuard` became `pub(crate)`, plus the doc comment above them. No APIC/timer/IDT/entry code changed.

### Lock order and contexts

One DAG, documented in `services.rs`: `PROCESS` -> `TABLES` -> heap -> `FRAMES`; `FRAMES` is a leaf (it calls nothing that locks); nothing is held across a user copy that could fault (the kernel never touches user addresses), a callback or a blocking operation. All are `IrqMutex`: local interrupts are masked while held and restored after unlocking (`cpu.rs` guard order), so an interrupt handler can never deadlock against an interrupted holder on one CPU. NMI, `#DF` and `#MC` are not excluded and must never take these locks. **Allocation context: task context only.** The heap is deadlock-free if called with interrupts enabled, but there is no atomic reserve or GFP-style flag yet, so interrupt handlers MUST NOT allocate; the panic and fault paths only `log!`. The allocator never sleeps, reclaims, does I/O or uses reserves (`memory.rs`). Proof of the `Sync` arguments: `IrqMutex<T: Send>` (payload only reachable through a guard that holds the spinlock with IF masked); `Once<T: Send + Sync>` (single writer by CAS, Release store / Acquire load); `BootInfo: Send + Sync` (immutable data over reserved loader memory, no interior mutability); `Allocator: Send` (exclusive owner of its metadata, pointers are identities never dereferenced); `KernelHeap<S: Send>` is automatically `Send` because the vendored free list carries its own `unsafe impl Send` (the review found a redundant impl of ours, removed). Each has a `SAFETY` comment at the impl.

### Post-activation page-table rule

Kernel half: written only before `activate`, immutable after. User half: a not-present -> present change needs no invalidation (hardware caches no absent entry; SDM Vol. 3 4.10.4.3) and a new intermediate table is zeroed before it is linked; clearing or tightening a present PTE is an atomic RMW (hardware sets A/D bits concurrently) followed by `invlpg`, and only then may the frame be reused or freed. Empty intermediate user tables are not freed (no teardown exists; `shortcut:` in `paging.rs`). **SMP needs a TLB shootdown in place of the local `invlpg`, acknowledged before the frame is freed** (documented at the call sites; not built: one CPU). The `usercopy` TOCTOU contract is now true by construction: resolution and copy happen under one `&mut Tables` borrow, so unmap/protect cannot run between them.

### Fallible heap

Candidates read, the decision and the admitted configuration are in [dependencies](dependencies.md#kernel-heap-buddy_system_allocator): `talc` is rejected because its mandatory `allocator-api2` does not compile under `no_global_oom_handling`; `linked_list_allocator` cannot grow by discontiguous chunks; `slabmalloc` needs a pager plus a second allocator for large objects; `buddy_system_allocator` is admitted (MIT, no dependencies with default features off). Policy in `kernel/src/heap.rs`: growth by whole frame chunks (>= 64 KiB, up to the 4 MiB frame cap, Linux `KMALLOC_MAX_SIZE` analogue; `ORDERS` is 23 so the heap's largest block equals the frame cap), `None` for every failure (oversized, source refusal), no panic on any layout, power-of-two rounding (<= 50% internal fragmentation), chunks never returned (`shortcut:`). Probe evidence (rustc 1.101.0-nightly 5c543b0b8, scratch crate outside the repository, flags as the maintained build): `Vec::try_reserve`, `Vec::push_within_capacity`, `Box::try_new` compile, `Box::new` and `Vec::push` fail with `E0599`. Wired through `xtask` (`Target::build_std`, `remap_flags` appends `--cfg=no_global_oom_handling` for the kernel only, runtime archives require `alloc` for the kernel and none for the init), the package reproduction text, [kernel tooling](kernel-tooling.md#fallible-only-kernel-allocation) and `target/gates.sh` (outside git: the target Clippy line gained `env CARGO_ENCODED_RUSTFLAGS=--cfg=no_global_oom_handling` and `-Zbuild-std=core,alloc,compiler_builtins`; the previous script is `target/gates.sh.before-foundation`).

### Executable records

Two new `qemu-self-test` records, required by `SUCCESS_MARKERS` and `validate_success_serial` (exact, unique) with rejecting unit tests: `CHECK user-mm ok pages=3 rollback_points=3 tlb=invlpg protect=ro unmap=3 conflict=rolled-back accounting=restored` (rollback at each of three allocation points, copies through a fresh mapping, a write fault after `protect_user` and a read fault after unmap that a stale TLB entry would hide, conflict rollback; runs inside init's existing stack page table, so `CHECK userspace-audit` counts are unchanged) and `CHECK heap ok vec=1000 box=4096 align=4096 growth=buddy-frames oom=failed-cleanly recovered=true over_cap=rejected accounting=restored` (injected frame exhaustion through the allocator budget: the 4 MiB request fails, heap and frame accounting are unchanged, the same request then succeeds).

### The five design questions

1. *Crate?* Heap engine: yes, `buddy_system_allocator` (above, with three rejections); `lock_api`/`spin` rejected (they neither mask IRQs nor fit the lock order); `x86_64::instructions::tlb::flush` is the existing `invlpg` wrapper, so no new `asm!`.
2. *Bundle?* One allocator (`Allocator`), one lock type (`IrqMutex`), one user-copy path (`usercopy`), one page-table owner (`Tables`); the heap sits on the frame allocator instead of a second pool, and `UserSpace` is a borrow of `Tables` instead of a copied root.
3. *Simplify?* Removed the private `Shared`/`RawSpinLock` state cell and the unsafe `user_space`; the syscall context replaces the `UserPages` + `Console` pair. Not simplified: SMP shootdown, page-table freeing, chunk return, slab layer are named shortcuts, not hidden.
4. *Secure?* Assets: frames, page tables, the kernel heap. Attacker input reaches `unmap/protect` only through future syscalls; those paths validate alignment and `TASK_SIZE_MAX`, never touch the kernel half, check the user bit before reclaiming, and cannot free a frame twice (the allocator rejects non-live heads). Exhaustion paths are tested (budget injection) and leave no state change. Stale-TLB use-after-free is closed locally by `invlpg` before reuse (tested) and is an explicit SMP blocker. Heap contents of freed blocks are not zeroed (free-list pointers live in them); acceptable for kernel-internal data, revisit before heap-allocated user-visible buffers. Independent unsafe/architecture/security review has **not** occurred.
5. *Improve?* Measure and, if hot, add a slab front end for small fixed sizes and return idle chunks; replace the O(n) buddy scan; per-CPU caches with SMP. No measurement exists yet; none is claimed.

### Review follow-up (PR #13)

* **Heap growth under `FRAMES` is loud.** The grow path takes `FRAMES` with `try_lock`; if it is held it panics (`FAIL panic ... lock-order violation`, then the boot stops). Chosen over spinning (silent hang, the reviewed defect) and over returning an allocation failure (it would hide a kernel bug as `ENOMEM` to the user). It is correct for this cell because there is one CPU and every critical section masks interrupts, so a held `FRAMES` at that point can only be the allocating caller itself. With SMP the owner may be another CPU and the check must become "owner is this CPU" (`shortcut:` in `services.rs`). The rule is stated in `services.rs`, `kalloc.rs`, `Tables::map_user_anon` and `Process::vmas`: reserve heap memory first, then take `FRAMES`. Not covered by a QEMU case (a positive control would deliberately stop the boot).
* **Negative control for `invlpg`, observed under QEMU TCG** (the `qemu-self-test` build, otherwise this branch's source): replacing the `tlb::flush` in both `unmap_user` and `protect_user` by a no-op made `kernel-test` match 7/18 cases with the success case ending `FAIL user-mm error=Conflict` (run `mut-noflush`); removing only the `unmap_user` flush (`mut-line414`) and only the `protect_user` flush (`mut-line461`) each failed the same way (7/18). So TCG does model the stale translation here and `CHECK user-mm` detects either omission. This is evidence about TCG's TLB model, not about hardware (the same code is expected to need the flush on real CPUs, which have larger TLBs and paging-structure caches); the run directories are untracked under `target/kernel-tooling/`, and the mutated source was restored (`git status` clean).
* **Heap block cap** is now 4 MiB (`ORDERS` 23) equal to the frame cap; the self-test rejects 8 MiB and 16 MiB requests before the source is asked. `KernelHeap`'s redundant `unsafe impl Send` was removed. `unmap_user` checks the user bit before clearing the PTE. The heap lock is held with interrupts masked during chunk zeroing (up to 4 MiB) and free-list scans: IRQ latency consequence documented in `kalloc.rs`.
* **Tests of `IrqMutex`/`Once`/`Service`** remain QEMU-covered only (they live in the binary); moving them into the library over a lock trait for host tests is a recorded improvement, not done.

## Framebuffer console on real hardware

Scope: the target workstation has two GPUs (monitors on the discrete card, iGPU outputs disconnected), no serial port, and a long test log must be photographed from the screen. Four defects of the earlier console are repaired; nothing here is physical evidence (QEMU only, below).

| Defect | Change |
| --- | --- |
| Only Limine framebuffer 0 used (may be the disconnected iGPU) | `BootInfo::take_framebuffers` (`kernel/src/boot.rs`) reads every entry Limine reports, at most `MAX_FRAMEBUFFERS` = 8, each through the previous per-entry checks (pointer slot and struct inside bootloader-reclaimable memory, `pitch*height` extent inside a kind-7 region); a bad entry is `None` and the others are kept. `console::init` validates each survivor again with `fbtext::validate` and draws every character on all accepted ones. |
| Only 32 bpp 8/8/8 accepted (a 10-bit GOP mode left a blank screen) | `fbtext::validate` accepts RGB model, 16/24/32 bpp, any non-empty, non-overlapping channel sizes/shifts inside the pixel (A2R10G10B10, RGB565, XRGB1555, 24-bit packed, ...). Foreground is every colour bit set; pixels are written as an aligned `u16`/`u32` store or three byte stores. Rejects (model, depth, size, pitch, alignment, channels, overlap) are counted per framebuffer and printed on the screens that work. |
| Output wrapped to the top and overwrote itself | The cursor passes the last row lazily: a character or newline at the pending position scrolls once. The last line is therefore not wasted and a trailing newline does not scroll. |
| 8x16 is tiny on a 2560x1440 panel | Glyph scale follows Linux's `get_default_font` (below). |

**Provenance.** Font choice: Linux 6.18.57 `lib/fonts/fonts.c:111-151` (`get_default_font`, scoring loop reproduced in `fbtext::choose_scale`), candidate `pref` values from `font_8x16.c:4632` (VGA8x16, 0), `font_8x8.c:2583` (VGA8x8, 0) and `font_ter16x32.c:2068` (TER16x32, -1 off SPARC), call site `drivers/video/fbdev/core/fbcon.c:995-998`. We keep only `font8x8` 0.3.1 (already admitted, glyph data only); 8x8 is scale 1x1, VGA8x16 is the existing 1x2 line doubling, TER16x32 is 2x4. Scales 3x6 and 4x8 reuse TER16x32's `pref` and win only where Linux's formula already prefers more than 16x32 and Linux has no font (an extension, never selected below 4K-class panels). Results: 640x350 -> 8x8, 1024x768 and 1920x1080 -> 8x16, 2560x1440 and 3840x2160 -> 16x32 (as the pinned scoring picks TER16x32 there), 7680x4320 -> 32x64. No new crate and no new font data. Not reproduced: Linux's actual TER16x32 and VGA8x16 glyph shapes (the scaled 8x8 glyphs look coarser), fbcon's other fonts and the `fbcon=font:` selector.

**Scrolling: shadow redraw, not framebuffer copy.** A static `SHADOW` (`MAX_COLS` 256 x `MAX_ROWS` 128 glyph indices, 32 KiB BSS; atomics, so no reference is ever formed to it) holds the text. A scroll shifts the shadow up one row, zeroes the last row and redraws every cell from it, scanline-major so each framebuffer row is written in one ascending run. Reason: framebuffers are normally write-combined (`paging.rs` maps kind 7 as PAT[5] WC) and reads from WC/UC are far slower than writes; a copy within the framebuffer would read ~15 MB per scrolled line at 1440p. Redrawing replaces every cell including blanks, so a scrolled-in line cannot show stale glyph pixels, which also removes the "newline must clear" concern. Cost: one full-screen write of `width*height*bytes` per scrolled line (about 15 MB at 2560x1440x4, 33 MB at 4K) - unmeasured on hardware; a 300-line log at 1440p is ~255 scrolls. `shortcut:` redraw is not diffed against what is displayed; add a displayed-cell shadow and skip equal cells if a physical photo run shows it is too slow, or scroll in batches. The initial clear writes the whole framebuffer black (removing the firmware logo).

**Multiple framebuffers.** One logical grid shared by all: columns/rows are the minimum over accepted screens, each at its own scale, so a larger screen has an unused right/bottom margin. Slots are published with a single `COUNT` release store; the cursor is the only mutable coordination.

**Emergency/no-lock contract (restated, console.rs header).** No lock and no allocation; framebuffer bytes are only volatile exposed-provenance stores (readback only in the QEMU self-test); `fbtext::step` is the pure cursor transition and a compare-exchange hands each character a cell and decides who scrolls. Reentrant or interleaved writers (an exception during output) can garble text but cannot index outside the grid or the framebuffer (`put` re-checks x/y against width/height; `step` clamps out-of-range cursor state). Interleaving remains permitted, whole-line atomicity is not promised.

**Tests.** Host (`kernel` lib, `fbtext`): 8 tests - standard, 10-bit, 565, 555 and 24-bit formats, every reject reason, the Linux font scores, grid clamping, lazy-scroll cursor steps, and a simulated log through a 4x3 grid. QEMU (`qemu-self-test` only): `console::self_test` writes `rows+2` marker lines and logs `CHECK console ok framebuffers=N scrolled=true tail=true stale=false readback=true`, i.e. the shadow tail is the last `rows` lines, no cell outside column 0 is stale, and the pixels of five cells per framebuffer (read back through MMIO) equal what the glyph must render. `xtask kernel-test` requires that record, with `framebuffers=2` in the `success` case (its QEMU also attaches `-device ramfb`, giving OVMF a second GOP handle) and `framebuffers=1` in the other seventeen; a unit test rejects a wrong count or a failed field. The case catalog size is unchanged (18).

**QEMU evidence** (not physical; ad hoc runs of the same default `freestanding` kernel image from `target/kernel-tooling/console-002/default-boot`, screendumps through QMP, under `target/worktrees/console/target/console-evidence/`): `run1/` std VGA + ramfb, `console: framebuffers used=2 reported=2` and both screens drawn; `r480/vga.png` Limine `resolution: 640x480x32` - the 33-line log scrolls, the head is gone and the tail ("init: ok", the panic line) is intact, nothing overwritten; `qhd/vga.png` `2560x1440x32` on a 64 MiB VGA - 16x32 glyphs, grid 160x45. The maintained `kernel-test` run is `target/kernel-tooling/console-003` (18/18, default screenshot 1024x768). QEMU/OVMF always delivers BGRX8888, so 10-bit, 565 and 24-bit are covered only by the host unit tests, not by an executed framebuffer; nor is a multi-resolution mix.

**Touched outside `console.rs`:** `kernel/src/boot.rs` (`take_framebuffer` replaced by `take_framebuffers`, `MAX_FRAMEBUFFERS`, `Framebuffers`), `kernel/src/main.rs` (the `console::init` call, one `console::self_test` call under `qemu-self-test`, a comment), `kernel/src/lib.rs` (`pub mod fbtext`), new `kernel/src/fbtext.rs`, `xtask/src/kernel.rs` (`DebugCase.framebuffers`, ramfb argument, console record check, tests).

**Five questions.** *Preexisting crate?* `font8x8` is kept; no crate offers Linux's font-selection rule or this cursor/scroll model, and a console crate would add its own allocation. *Bundle?* Format validation, font choice and cursor stepping share one pure module (`fbtext`) used by the console and tests, one drawing path (`put`) serves clear, cell and redraw. *Simplify?* A shadow plus whole redraw instead of copy/diff/damage tracking; one shared grid instead of per-screen cursors. *Secure?* All loader fields are untrusted: independent per-entry validation, checked arithmetic, aligned access widths, volatile MMIO only, bounded loops (8 framebuffers, 256x128 cells, <= 16384 pixels per side), no references into MMIO, no panics reachable from loader values (`validate` shifts only after bounding `shift+size <= bpp <= 32`); `step` clamps. A hostile extent is limited by the kind-7 check; the mapping itself is unchanged. *Improve?* Measure the scroll cost on the workstation; diff-redraw or batch scrolling; Linux's real TER16x32/VGA8x16 glyphs through a vetted font crate or a provenance-preserving port; hardware-accurate EDID/preferred-screen selection; an on-screen banner with the source/ELF hash.
