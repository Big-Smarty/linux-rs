## Unreleased

- Memory-mapping model ([record](docs/implementation.md#memory-mapping-model)): `kernel/src/mm/`, pure `forbid(unsafe_code)` library code with 35 host tests (expected values from the `init-reference-005` oracle `mm` group where it covers them, derived from the pinned source otherwise) for the VMA set and its merge/split/`anon_vma` rules, `norandmaps` x86-64 `mmap` placement, `mmap`/`munmap`/`mprotect`/`brk` decisions in Linux's check order, the user page-fault decision with stack expansion, and a `UserPages` trait for the paging owner. Not wired into the kernel; shared-anonymous, hugetlb and file-backed mappings stop at typed outcomes. `kernel` enables `extern crate alloc` and `vec_push_within_capacity`.

- Identity and process-attribute syscalls ([record](docs/implementation.md#identity-and-process-attribute-syscalls)): `getuid`/`geteuid`/`getgid`/`getegid`, `getresuid`/`getresgid`, `getgroups`, `getppid`, `gettid`, `getpgrp`/`getpgid`/`getsid`, `getpriority`, `sched_getscheduler`, `sched_get_priority_{min,max}`, `sched_{get,set}affinity`, `getrlimit`/`setrlimit`/`prlimit64` (Linux's `INIT_RLIMITS`), `umask`, `getcwd`, `uname`, `sysinfo`, `personality`, `set_tid_address`, `set_robust_list`, `arch_prctl` (FS/GS bases through the vendored `x86_64` crate) and the `prctl` options init uses (any other implemented option stops the kernel). State is `task::Attributes` in `Process`; `usercopy` gains `put_user` and `strncpy_from_user`. `kernel-test` gains the generic `oracle_case!` kind and `oracle-ids`, which requires the 158 `init: test|tests ids` lines to equal the pinned Linux's.
- Kernel services foundation ([record](docs/implementation.md#kernel-services-foundation)): `BootInfo`, the frame allocator and the page tables live in synchronised statics (`services.rs`, lock order `PROCESS` -> `TABLES` -> heap -> `FRAMES`); user mappings can be mapped, unmapped, protected and freed after CR3 activation (`invlpg`, atomic PTE updates, rollback; `UserSpace` borrows `&mut Tables`); a fallible kernel heap (vendored `buddy_system_allocator` 0.13.0 over buddy frames) with `alloc` built `--cfg no_global_oom_handling` so infallible `Box::new`/`Vec::push` do not exist in the kernel; `Process` context and `syscall::dispatch(&mut impl Context, ..)` with `syscall/` split into `mod.rs`, `io.rs`, `process.rs`. New QEMU records `CHECK user-mm` and `CHECK heap`; no syscall added, no behavior visible to `/init` changed.
- Framebuffer console on real hardware: draws on every Limine framebuffer (up to 8, each validated independently), accepts any 16/24/32 bpp RGB channel layout including 10-bit, scrolls instead of overwriting (shadow-cell redraw, no framebuffer reads), and picks the glyph scale by Linux's `get_default_font` rule (16x32 at 2560x1440). Pure parts in `kernel::fbtext` with host tests; the QEMU suite checks a scroll/readback record on one and two framebuffers. See [implementation](docs/implementation.md#framebuffer-console-on-real-hardware).
- Oracle syscall test suite: `user/init` modes `mm`, `ids`, `time`, `signal`, `fs` and `proc` (1,005 checks, one `init: test <group>.<name> ok|FAIL` line each) written and proven first on the pinned Linux 6.18.57 (TCG `qemu64` and KVM `host`, all pass; `target/linux-reference/init-reference-006`), expected lines in `xtask/oracle/expected.tsv`; the generated initramfs gains the `fixture/` tree (`records=11 files=10 regular=5 symlinks=2`). No `kernel-test` case runs the modes on this kernel yet. See [implementation](docs/implementation.md#oracle-syscall-test-suite).
- Interrupt controllers and timekeeping (WP-M1.2 slice, WP-M2.6 core): the ACPI walk now decodes the MADT (LAPIC address and override, IOAPICs, interrupt source overrides, NMI sources, x2APIC entries, `PCAT_COMPAT`), HPET and FADT timer fields and, like Linux, only warns on a bad checksum or unreadable child table; local APIC in xAPIC (uncached MMIO via a new `Tables::map_mmio`) or x2APIC (MSR) mode chosen by Linux's rules, IOAPIC with every pin masked and PIT IRQ0 proven through the MADT-described pin, 8259 masked in APIC mode, spurious/error vectors; TSC calibration in Linux's order (CPUID 0x15/0x16, quick PIT, HPET/PM-timer, 1% refinement), LAPIC TSC-deadline or calibrated one-shot clockevent at HZ=1000 (PIT only with `nolapic`), CMOS RTC wall time and `ktime_get_ns`/`ktime_get_boottime_ns`/`ktime_get_real`/`wait_until_ns`; pure arithmetic in `kernel::{time,intc}` with host tests; `kernel-test` grows to 25 cases (HPET off, PIT off, `nolapic`, `noapic`, forced and firmware x2APIC, KVM) and its timer records count tick periods on the TSC instead of PIT wraps.
