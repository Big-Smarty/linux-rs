# Kernel verification

## Scope and non-negotiable rules

Read [verification](../../../docs/verification.md), [compatibility](../../../docs/compatibility.md), [performance](../../../docs/performance.md), [bare-metal qualification](../../../docs/bare-metal.md), and the applicable subsystem plan first. This is an original project-local skill; do not install external skills or execute their embedded commands without source review and explicit authorization.

The behavioral oracle is Linux **6.18.57**, resolved through [reference metadata](../../../planning/reference.tsv), not the developer's host kernel. Kernel implementation and project-owned executable harnesses are Rust only. Existing external userspace tests and reference Linux may be non-Rust. Tests requiring C kernel helper modules are not permission to load legacy modules or introduce a C-backed runtime; port the required helper to reviewed Rust or record that case as blocked. The real x86_64 bootstrap has revision-specific evidence in the canonical [implementation record](../../../docs/implementation.md); its currently routed workstreams are `in_progress`, not completed. Keep unexecuted gates distinct from retained results rather than treating the earlier planning-only boundary as current.

Correctness, security, and at-least-baseline performance are separate mandatory obligations. Passing a VM boot, a model, or a source inventory proves none of the others. QEMU is the first debugger, not a substitute for physical-machine co-development starting in M1.

Use the standing [definition of done](../../../docs/definition-of-done.md) and [packaging design](../../../docs/packaging.md). First userspace is Arch/CachyOS userspace, not downstream CachyOS kernel patches; use the approved balanced-server performance profile. Only the current workstation is available for physical execution now: keep multi-vendor/NUMA/device coverage as explicit blockers, not implied available equipment. A storage-free diagnostic trial on separate user-owned recoverable media with independent known-good recovery may precede rootfs/initramfs/userspace; the existing Limine ELF is not a Linux-replacement package or a directly bootable systemd-boot EFI/PE/Linux image. Linux-replacement packaging still requires real storage/durable filesystem/root/initramfs/init/userspace and broader gates. The user personally installs/selects/boots candidates, preserving the working kernel and recovery path. Do not install, reboot, mount devices, update firmware or perform destructive host tests.

## Existing bootstrap evidence

Read [implementation and exact workstream routing](../../../docs/implementation.md), including immutable `target/kernel-first-boot/cell9/` ELF hashes, `manual-results.json`, per-case logs, both-profile disassembly/layout/maps and retained earlier failures. Eight actual QEMU q35/OVMF/Limine runs each had a 30-second bound: positive exit 33; panic, unexpected fault (vector 6), bad map (production overflow validator), unarmed breakpoint (vector 3), unassigned INT40 (`unknown-external`), no-PAT rejection and genuinely unmasked timer all exit 35 without a success marker. The positive case exercises actual frame exhaustion/restoration, all 20 table-allocation failure points, W^X/guards, exact page-fault errors 0/3/17, full-width preservation of 15 GPRs and two real PIT wraps with masked IRQ delta 0. The unmasked mutation observes delta 1 and fails the same assertion.

Five host tests of the production range/firmware parsers passed. Owned host-library/test Clippy and both freestanding release profiles also passed with `-D warnings`; the inherited `core` soft-float future-incompatibility warning remains unsuppressed. This is integration verification, not a newly specified user approval. The runtime identity is exact `rustc 1.101.0-nightly` commit `5c543b0b8c73c7b72bc8284ced4fb22ead15734d`, LLVM 23.1.1 and matching installed `rust-src`/build-std, not the separate host MSRV 1.88 metadata baseline. These kernel observations do not establish host-tool qualification on 1.88. Exact commands are in [implementation](../../../docs/implementation.md); maintained harness interfaces are in [kernel tooling](../../../docs/kernel-tooling.md). Manual cell9 runs are not evidence that the harness ran.

No physical candidate boot/recovery, performance qualification, complete M1, Linux userspace or full-baseline compatibility follows. The `freestanding` diagnostic ELF excludes QEMU-only COM1/debug-exit paths and uses a validated 32bpp framebuffer; its physical console/controller/recovery requirements still need evidence.

## Existing bounded smoke suite

The separate [bare-metal suite](../../../docs/bare-metal-suite.md) is an existing Linux userspace functional runner, not the bootstrap's freestanding QEMU test or a full qualification suite. Its exact interface is:

```text
cargo run -p baremetal -- run --output <new-directory> --label <label> --expect-release <exact-osrelease> --environment <reference|qemu|bare-metal>
```

Substitute an exact observed release and a fresh output directory; select one environment label. That label is an operator assertion, not attestation of physical execution. Run only when the assignment authorizes execution; no-gates and delegated edit tasks hand checks to the integration owner. Review actual runner/report behavior through its owning documentation rather than inventing output fields or a successful result.

Require bounded memory/thread, sandbox filesystem sync/rename/link, TCP/UDP/Unix loopback with timeouts, process exec/wait/exit, and permission-aware proc/sysfs cases. The suite must refuse release mismatch and output overwrite, return nonzero failures, distinguish skipped/unavailable cases, preserve per-case outcomes/environment metadata without hardware serial IDs, and never mount, raw-write devices, change settings, elevate, reboot or update firmware. A host reference run validates the runner and host smoke behavior only; it is not a Linux 6.18.57 oracle run unless that exact reference kernel is actually running. The bootstrap has no userspace to run this suite. Broader negative/differential/fuzz/durable-crash/hardware/performance requirements below remain open beyond the exact observed bootstrap cases.

## Required inputs

- Change/workstream ID, upstream commit and paths, observable contract, affected ABI/architecture/configuration variants, and dependency gates from the [roadmap](../../../docs/roadmap.md).
- Reference and candidate source identities, executable hashes, complete build configuration, compiler/linker versions and flags, firmware/microcode, rootfs/userspace/test-suite revisions, command lines, environment and fixture identities.
- Hardware/VM identity: CPU/vendor/stepping/features, SMT, sockets/NUMA, memory, IOMMU, interrupt routing, storage/controller/cache policy, NIC, firmware, boot mode, QEMU version/machine/accelerator. Record unavailable items explicitly.
- Threat/invariant list, expected successful and failing outcomes, safe lab ownership, timeouts, crash collection and recovery plan. No destructive execution against the development host.

## Procedure and step-by-step outputs

1. **Turn behavior into an oracle contract.** Read pinned Linux UAPI, implementation, and relevant upstream tests. For each operation write preconditions, inputs, effects, output bytes/layout, return/errno, side effects, ownership, ordering, signal/restart rules and allowed nondeterminism. Compare sets of permitted outcomes for races rather than requiring one arbitrary scheduling order. Do not normalize away meaningful errno, partial I/O, permissions, timestamps, persistence or readiness differences. Output: a case-to-contract-to-upstream-source map and reviewed normalization rules.
2. **Make two reproducible environments.** Build reference Linux and the candidate separately from recorded configurations; map equivalent features rather than assuming identical build systems. Preserve security mitigations and runtime policies. Use the same userspace, workload data, topology and devices where comparison permits; disclose any compiler/backend difference that cannot be made identical. Separate instrumented correctness builds from production-equivalent performance builds. Output: immutable run manifests and artifacts, including unsupported configurations rather than silently omitting them.
3. **Construct the build/configuration matrix.** Cover minimum and broad feature sets; debug and optimized settings; UP/SMP; preemption modes; compat ABIs; 32/64-bit, endianness and page-size variants; allocator pressure; architecture atomic widths; NUMA; IOMMU and device configurations as relevant. Track each baseline architecture even when compiler/backend or hardware support is a named blocker. Pairwise selection can prioritize exploration but cannot certify all combinations. Output: matrix with executed/pass/fail/blocked/not-run cells and reasons; compiler target availability is not kernel support.
4. **Layer semantic testing.** Use host Rust unit/property tests for separable parsers, arithmetic and state machines; execute kernel-local Rust invariant tests; then run syscall/ABI differential cases and pinned applicable kselftests, LTP, filesystem/network suites and real userspace smoke workloads. Trace actual preconditions so an upstream skip is not counted as a pass. Exercise startup, service operation and orderly shutdown, not just successful process launch. Output: per-case logs, assertions, skip classifications and contract coverage, not a single suite exit code.
5. **Attack every failure transition.** Inject allocation failures at each allocation point, usercopy faults across page boundaries, invalid pointers/alignment/lengths, integer boundaries, bad flags and handles, privilege denials, interrupted/restarted operations, cancellation, disk full/read-only/corruption/timeouts, link loss, duplicate completions and hot removal. Verify Linux-compatible error precedence, partial progress, rollback, resource/accounting restoration, no privilege change and no leaked bytes. Repeat failure then successful retry to reveal poisoned state. Output: injection index, observed failure site, expected post-state and regression seed.
6. **Check concurrency independently.** Specify lock ordering, IRQ/preemption context, linearization points, reference lifetimes and memory-order invariants. Model bounded shared algorithms with a reviewed host tool such as Loom after the [dependency audit](../kernel-dependencies/SKILL.md); enumerate thread/step/preemption limits and unmodeled operations. Apply Linux memory-model litmus reasoning where appropriate, then stress real SMP/NUMA with migration, interrupts, reclaim, teardown and hotplug. A Rust model cannot represent DMA, MMIO or all weak-memory behavior by default. Output: model assumptions/bounds, traces/counterexamples, mapping to real primitives and hardware stress evidence.
7. **Fuzz with reproducible artifacts.** Start parser/state-machine fuzzing before boot; progress to coverage-guided syscall sequences and device/protocol inputs when the required ABI and coverage hooks exist. Evaluate syzkaller as an external suite, not an assumed drop-in: record executor, syscall descriptions, coverage transport, reset and crash-detection requirements and missing interfaces. Use bounded isolated workers, seed corpora and deterministic replay; retain input, seed, config, symbols, crash signature and minimized reproducer. Add every fixed issue to regression coverage and replay on Linux to distinguish mismatches from shared upstream defects. Output: reached surfaces, coverage limitations, campaign duration and unique findings; no-crash duration is not a correctness proof.
8. **Prove durable state separately.** On sacrificial images/devices, issue a recorded sequence of writes, rename/link/unlink, metadata updates, fsync/fdatasync and directory synchronization according to the filesystem contract. Cut execution at enumerated journal/COW/flush/barrier boundaries, lose volatile caches, simulate torn/reordered/failed writes permitted by the device model, and recover under the candidate and compatible Linux tools. Compare allowed acknowledged data and namespace states, replay idempotence, metadata integrity and information isolation. VM reset does not prove power-loss durability if host caches survived. Add actual controlled power-cut campaigns with documented controller/cache/power-loss-protection properties. Output: durable-prefix oracle, crash point, I/O trace, recovered image and consistency verdict.
9. **Co-develop on physical hardware.** From M1 maintain a lab run alongside emulation: serial/remote console independent of the tested NIC, known-good boot entry, watchdog/remote power recovery, firmware inventory, dedicated disks and isolated network. Extend to multiple CPU/platform vendors, real NVMe/SATA/NIC devices, NUMA, DMA/IOMMU faults, interrupt storms, suspend/resume, power states, hotplug and supported error injection. Preserve console logs across reset. Never infer physical timing or mitigation behavior from QEMU. Output: device/firmware-specific qualification records; missing machines are named blockers, not VM passes.
10. **Measure performance only after semantic proof.** Follow [kernel-performance](../kernel-performance/SKILL.md). Compare each required workload and physical configuration against pinned Linux with equivalent security, compiler settings, topology, storage state, firmware, thermal and frequency conditions. Record throughput, latency distributions/tails, CPU, memory, startup and power; predeclare repetitions, warm-up, order randomization, noise controls, confidence intervals and the directional comparison per metric. No geometric-mean-only report, arbitrary regression budget or mitigation-off victory. An unresolved interval or unproved non-regression is inconclusive, not a pass; retain raw observations and optimize avoidable allocation/copy/locking only without changing semantics. Output: per-workload/hardware non-inferiority evidence and regression investigations.
11. **Close the evidence loop.** Attach regression cases, manifests, logs, raw results, model bounds and reviewer decisions to the change; synchronize [coverage](../../../docs/coverage.md), [maintenance](../../../docs/maintenance.md) and subsystem qualification through [kernel-documentation](../kernel-documentation/SKILL.md). Preserve prior failures and distinguish fixed, waived-by-explicit-decision, blocked and still failing. Output: a concise verdict whose scope is exactly the tested configurations.

## Five mandatory design checks

- **Crates:** Is the test dependency host-only or linked into the kernel? Review feature graph, unsafe/native code and licenses; Criterion or Loom are candidates for appropriate host contexts, not kernel runtimes. Existing Linux C-only sanitizers are oracle aids, not automatically available Rust-kernel instrumentation.
- **Bundle:** Reuse one run-manifest, fixture, oracle comparison, crash-signature and result vocabulary across subsystems; retain domain-specific assertions and independent oracles. Shared code must not make identical candidate/oracle mistakes invisible.
- **Simplify:** Minimize reproductions and model state while retaining the failure. Snapshot fixtures and deterministic seeds simplify diagnosis; deleting difficult configurations or treating skips as success does not.
- **Security:** Treat fuzz inputs, test images and devices as hostile. Restrict debug interfaces, resource usage, credentials and network reachability; do not upload secrets or embargoed reproducers to public CI.
- **Improve:** Prioritize uncovered transitions and real regressions, improve observability without changing measured production behavior, and compare before/after profiles rather than assuming Rust is faster.

## Errors and traps

An oracle crash may be an upstream security bug, not behavior to reproduce; quarantine and use [kernel-security](../kernel-security/SKILL.md). A flaky test stays failing/inconclusive until cause is understood; retrying until green is not evidence. A timeout needs logs and a distinction between harness loss, deadlock and slow progress. Model exhaustion, unsupported instrumentation, missing coverage hooks, unavailable lab machines and insufficient statistical separation are explicit blockers. Do not claim absence of UB from compilation, absence of races from stress, durability from clean shutdown, or hardware support from one emulated driver.

## Gates and final output

A change report must contain contract/source map, matrix, reproducible manifests, positive and negative outcomes, regression artifacts, concurrency and crash evidence where applicable, hardware scope, performance verdict, unresolved failures, and reviewers. Integration requires applicable semantic/security regressions to pass and required evidence to exist; release requires at-least-Linux performance per required workload/hardware and the full agreed compatibility/architecture/device scope. M0 documentation/audit results do not satisfy M1–M8 execution gates. Execute commands only when the assignment permits; never report an unrun gate as passed.
