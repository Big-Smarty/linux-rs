# Unsafe kernel boundaries

## Scope and non-negotiable rules

Read [project rules](../../../AGENTS.md), [architecture](../../../docs/architecture.md), [memory plan](../../../docs/subsystems/memory.md), [drivers](../../../docs/subsystems/drivers.md), and [toolchain policy](../../../docs/toolchain.md). Apply this skill to every unsafe block/function/trait implementation and every proposed safe wrapper around kernel or hardware state. Kernel implementation is Rust `no_std`; host tools may use `std`. The real [bootstrap proof register and evidence](../../../docs/implementation.md) cover a narrow BSP cell with raw-before-reference RAM initialization, unique frame ownership, owned mappings and bounded immutable firmware borrows. These are reviewable engineering contracts and actual tests, not independent soundness certification or completed workstreams.

`unsafe` does not relax Rust validity, aliasing, race, or lifetime rules. “The C version does it,” “the address is mapped,” “it is volatile,” “it is behind a lock,” and “Miri passed” are not complete safety arguments. No C shim, standalone assembly, or generic embedded recommendation may override the kernel contract. Inline assembly is allowed only for an operation irreducible to Rust or supported intrinsics with the required semantics.

Apply the [standing definition of done](../../../docs/definition-of-done.md): a soundness claim, a limited host check and a smoke pass are different evidence classes. The actual [bounded smoke suite](../../../docs/bare-metal-suite.md) is runnable now on a reference environment, with expected-release checking and fresh output reports; it does not exercise privileged/MMIO/DMA invariants or qualify the bootstrap. Preserve its failures/skips/unavailable results and never report an unrun invocation.

Only the current workstation is physically available. New architecture/vendor/noncoherent-DMA cells remain qualification blockers until equipment and evidence exist. The user installs/selects/boots a real candidate under [packaging and recovery rules](../../../docs/packaging.md); do not install bootloaders, reboot, change firmware, raw-write storage or test unsafe device teardown on the development host. The generic non-destructive smoke runner is not permission for privileged hardware fault injection.

## Evidence packet before writing unsafe

For the exact operation provide:

- Source provenance and pinned Linux behavior, CPU/device/firmware specification revision, compiler/target/features, execution context, and owning [workstream](../../../planning/workstreams.tsv).
- A memory map naming address spaces: CPU virtual, CPU physical, device bus/IOVA, user virtual, MMIO, ordinary Rust allocations, and any allocator/page-table boundary whose Rust semantics need explicit justification.
- Object owner, lifetime and pinning guarantees, allocation and mapping extent, alignment, initialization/valid-bit constraints, access permissions, synchronization, cache/coherency attributes, and reclamation/quiescence events.
- All safe clients, concurrent actors including IRQ/NMI/firmware/device DMA, error/early-return paths, and untrusted input constraints. List what callers establish versus what the implementation establishes.
- Evidence strategy: executable host-testable core, target/disassembly checks, QEMU cases, initial physical-machine cases, and recovery safeguards. Missing hardware/specification is a named blocker, not permission to guess.

## Ordered proof-and-implementation procedure

1. **Try a safe expression first.** Use typed indexing, checked arithmetic, validated bytes and existing audited abstractions when they express the operation without avoidable allocation/copying. Identify exactly which unavailable language operation requires unsafe. Do not remove a bounds check on speculative performance grounds.
2. **Draw ownership and state transitions.** For each pointer record origin, permitted extent, active aliases, initialization state, address-space/mapping identity, and last use. Separate ownership from merely storing an address. Include transfer to another CPU/device, cancellation, hot removal, IRQ completion, reset, and failure rollback.
3. **Establish provenance explicitly.** Preserve the allocation-derived pointer through pointer arithmetic/tagging using applicable provenance APIs; integer equality of addresses is not permission to access. Do not combine adjacent allocations into a slice, recover a containing allocation from an insufficiently scoped field reference, use `offset` outside its allocation, or forge a larger reference. Page allocator/direct-map/virtual-alias abstractions require an explicit compiler-memory-model argument; hardware page tables alone do not establish it. Escalate unresolved assumptions instead of hiding them behind casts.
4. **Prove reference formation separately from raw access.** Before creating `&T`, `&mut T`, slices, or boxes prove alignment, non-nullness, initialization/validity, live extent, and the aliasing contract for the full reference lifetime. Device-owned buffers, user pointers, uninitialized objects, packed fields and concurrently changing memory are not ordinary reference targets. `NonNull` proves non-nullness only; `UnsafeCell` permits interior mutation but does not prevent races or establish exclusive access. Avoid forming a temporary invalid reference even if immediately cast away.
5. **Handle initialization and byte representation.** Use `MaybeUninit` with a field/range initialization ledger and explicit success/failure cleanup. Zero bytes do not represent every Rust type. Validate raw discriminants and booleans before constructing them. Do not transmute arbitrary bytes to references, enums, or owning types. Typed moves can leave padding uninitialized; use proven byte conversion or explicit serialization before exposing bytes to userspace/devices.
6. **Separate access classes.** Distinguish ordinary RAM, atomic shared RAM, faultable userspace, MMIO registers, and DMA buffers. Each needs a different API; volatile is not a universal pointer-access primitive. A CPU fence, compiler fence, MMIO ordering operation, cache-maintenance instruction and IOMMU invalidation are not interchangeable.
7. **Encapsulate MMIO by register contract.** Validate mapped resource ownership, page attributes, bounds, width, alignment, byte order, privilege, and lifetime. Use raw pointers plus the exact volatile operation where required; no ordinary Rust reference to side-effectful register memory. Under the documented outside-allocation volatile exception, provenance can be absent, but access must not trap, must yield a valid value, and the access must not modify Rust allocation memory as an immediate side effect. Do not generalize this exception to RAM. A doorbell/device-DMA protocol still needs a separate device-ownership/order proof. Verify access widths in target disassembly; aggregate volatile reads may split. Document write-one-to-clear, read-to-clear, reserved bits, posted writes and required readbacks. Never perform an automatic read-modify-write on registers where it changes hardware semantics.
8. **Encapsulate DMA as ownership transfer.** Obtain valid mappings, address masks and segment constraints through the shared DMA/IOMMU mechanism, not `virtual as physical as device_address`. Handle mapping failure. Define CPU-owned, device-owned, completion, synchronized and reclaimable states; prevent Rust references/access from violating the device's concurrent mutation contract. Coherent allocation does not eliminate ordering barriers. For noncoherent DMA specify cache maintenance and ownership sync; prohibit cacheline sharing that could corrupt adjacent data. Keep allocation/pinning, IOVA mapping and device permissions alive until hardware is stopped, completions drained and translations invalidated as required. Reset or timeout is not proof DMA has stopped.
9. **Audit special control transfer and assembly.** Prefer Rust/intrinsics only when they specify the required privileged/register semantics. For each unavoidable inline-assembly site record operation, rejected alternatives, feature/privilege preconditions, register operands, outputs and early-clobber behavior, flags, stack alignment/red-zone assumptions, memory reads/writes, compiler ordering, fault recovery and control-flow contract. Do not claim `nomem`, `readonly`, `preserves_flags`, `nostack`, or `noreturn` without proof. Preserve all ABI-required state across entry/return/context switches and account for compiler-generated prologue/epilogue. No standalone `.S`/`.s` files or C trampoline.
10. **Seal the abstraction.** Define private representation and constructors so every safe client, including malicious or unusual safe clients, preserves the invariant. Review `Send`/`Sync`, pinning, variance, cancellation and drop legality. Do not assume a guard destructor always runs: safe code may forget values. Leaks may consume resources, but must not enable memory unsafety; context restoration requiring stronger guarantees needs constrained interfaces and explicit review. Document public unsafe caller obligations and local `SAFETY` reasoning that discharges them.
11. **Integrate all consumers and evidence.** Move existing callers onto the reviewed boundary; remove duplicate unsound raw helpers. Re-run the proof when allocator, target, compiler, memory attributes, ownership, ordering or hardware assumptions change. Update [decisions](../../../docs/decisions.md), affected plans and review records with exact assumptions and artifact links.

## Five design checks

| Check | Domain-specific requirement |
| --- | --- |
| Reuse | Start with documented `core::ptr`, `MaybeUninit`, `UnsafeCell`, atomics and supported intrinsics. [Zerocopy](https://docs.rs/zerocopy/latest/zerocopy/) may reduce byte-conversion unsafe only when its traits prove the actual layout/validity requirements. Review precise versions/features, transitive licenses, unsafe, advisories, no_std/allocator and target assumptions under [dependency policy](../../../docs/dependencies.md). A volatile/register crate cannot prove PCI resource ownership, MMIO bus ordering, or DMA lifetime by itself. |
| Bundle | Centralize mapping ownership, usercopy recovery, typed address spaces, MMIO access rules, DMA ownership, and architecture barriers with their domain owners. Keep device-specific register side effects and architecture-specific contracts explicit. One giant unsafe module is not encapsulation. |
| Simplify | Prefer explicit initialized byte codecs to transmute and a small ownership state machine to hidden aliasing. Simplify private representation, not the Linux ABI, required cache maintenance, IOMMU isolation or hardware teardown. Do not replace allocation with an arbitrary fixed-size limit that changes behavior. |
| Security | Prove bounds/overflow, address-space permissions, usercopy isolation, output initialization, code/data protections, privileged state sanitization and device isolation. Check stale translations, firmware/device-controlled lengths, speculative access and use-after-free under reset/hotplug. Safety comments need evidence, not merely assertions. |
| Improve | Measure copies, cache maintenance, mapping/unmapping, barriers and batching only after correctness. Remove avoidable work without dropping ordering, widening device privileges, leaving pages pinned indefinitely, or weakening mitigations. Preserve fault and lifetime semantics when introducing zero-copy. |

## Validation and definition of done

Follow [verification](../../../docs/verification.md), [performance](../../../docs/performance.md), and [bare-metal lab policy](../../../docs/bare-metal.md). Use the exact retained [cell9 execution and compiler/unsafe register](../../../docs/implementation.md) for what ran; the broader requirements below remain open. Never report planning or a narrow QEMU/host observation as complete safety proof.

- **Before merge:** reviewers can reconstruct every unsafe invariant from sources and the exact compiler/API contracts; all safe entry points and failure/drop paths are covered. Host-testable allocation/codec/ownership components have runnable regression/adversarial cases and applicable Miri checks, with model/version limits recorded. Miri cannot validate real MMIO, DMA, privileged code or all Rust semantics.
- **M1 physical bring-up:** run the actual entry/exception, mapping, supported console/MMIO and primitive tests in QEMU and on recovery-backed hardware. Preserve binary/compiler identity, target disassembly and captured console logs; exercise invalid mapping and fault containment without touching the development host. The existing diagnostic's validated framebuffer is distinct from QEMU-only COM1/debug-exit paths; physical console/controller compatibility and recovery remain unproved.
- **M2–M7 affected-device gates:** provide runnable Rust harness/test entries for ownership rejection, alignment/range boundaries, partial initialization cleanup, SMP access, DMA mapping failure, IOMMU fault, transfer completion, reset with in-flight DMA, hotplug and teardown. Bind each entry to safe fixture setup, expected oracle, timeout, serial capture and physical recovery/cleanup. Run on relevant coherent/noncoherent and IOMMU configurations; an unavailable architecture/device cell is blocked, not covered by QEMU.
- **Performance/M8:** compare affected paths and real workloads against pinned Linux on matched hardware/configuration/firmware/mitigations. Include throughput, latency/tails, CPU, memory/pinned pages, startup and relevant power, repetitions, uncertainty and noise controls. No arbitrary regression budget, security disablement, or average-only masking; unproven at-least-baseline behavior remains unqualified.

A complete boundary has source-backed proof, migrated consumers, independently reviewable disassembly where relevant, runnable reproducible test entries, actual passing observations for required hardware/configuration cells, and no unresolved soundness blocker. A test not run is reported unrun. Existing host/parser, QEMU fault/ownership/GPR and both-profile artifact evidence does not establish Miri, physical DMA, SMP, complete M1 or performance qualification; exact-nightly interrupt lowering must be requalified on compiler changes.

## Stop and escalation

Stop on unresolved provenance/aliasing assumptions, undocumented device side effects, unsupported compiler operation, invalid references, data races, unbounded post-free device access, assembly with unproved clobbers/control flow, or a safe API that can violate its own invariant. Escalate to architecture/memory/driver/security owners with the smallest counterexample and missing source or proof. Do not suppress a diagnostic, rely on observed compiler output as a language guarantee, or weaken a mitigation to obtain a test/benchmark result. Unsafe hardware tests require isolated equipment and verified recovery before execution.

## Deliverable checklist

- [ ] Per-operation source, address-space, ownership, provenance, validity, aliasing and context evidence.
- [ ] Narrow safe/unsafe APIs, `Send`/`Sync` and leak/drop review, every success/failure/teardown consumer migrated.
- [ ] MMIO/DMA/cache/IOMMU contracts and irreducible assembly exception records where applicable.
- [ ] Five design decisions; independent reviewers; reproducible runnable cases and disassembly artifacts.
- [ ] Real QEMU/bare-metal/performance evidence or explicitly blocked/unrun cells; no proof inferred from tool silence.

## Primary references

- [Rust undefined behavior](https://doc.rust-lang.org/reference/behavior-considered-undefined.html) and [pointer validity/provenance](https://doc.rust-lang.org/core/ptr/index.html): evolving rules, not a formal complete memory model.
- [Volatile read contract](https://doc.rust-lang.org/core/ptr/fn.read_volatile.html): ordinary-allocation versus outside-allocation cases, alignment, valid values, access splitting and no synchronization guarantee.
- [Pinned DMA mapping guide](https://raw.githubusercontent.com/gregkh/linux/v6.18.57/Documentation/core-api/dma-api-howto.rst): virtual/physical/bus distinction, mapping capabilities, ownership and ordering obligations.
- [Rust inline assembly](https://doc.rust-lang.org/reference/inline-assembly.html): operand/options and control-flow rules; hardware specification evidence is additionally required.
